# 机密 R 包访问边界、安装卸载与本地测试规范设计

## 已确认目标

用户要求将 gotoTools、gotoBase、gotoPlot、gotoStat 四个目录作为公司机密源码，Agent 只允许执行安装和卸载工作，不得读取内部代码；同时指出外部工具缺少 gotoPlot 安装和卸载入口。本次立即遵守该边界，仅检查部署仓 `.bash` 下的外部包装脚本和测试，不读取四个目录内部文件。

同一会话中用户进一步确认补齐本地测试服务、编译依赖、路径映射和并行隔离，并明确“生产允许所有测试写入”。该授权登记为 goto-software 专属、持续有效的测试写入规则，覆盖全局数据库客户端只读限制；不改变四个机密 R 包的访问边界。本轮只修改规范，不执行生产写入。

## 设计

- 在规范仓 `goto_software_spec.md` 添加常驻边界，覆盖源码目录、同源副本、容器映射以及索引、子代理、日志等间接读取渠道。通用索引补充项目规则路由，不把机密目录路径复制到其他项目。
- 允许已授权安装器在本机内部读取安装所需元数据和源码，但禁止把内容交给 Agent 或上传；允许输出包名、阶段、版本、退出码和不含源码的错误摘要。部署工具本身位于四个目录外，可以维护。
- 依照现有单包模式增加 `install_gotoPlot.sh`、`remove_gotoPlot.sh`。固定安装路径 `/root/software/gotoPlot`，关闭依赖安装和升级，卸载缺失包为成功空操作。
- 批量入口保留原三包安装顺序，再安装 gotoPlot；卸载顺序相反。所有四包和八个脚本均在卸载开始前预检。未读机密包 DESCRIPTION，不声明已经验证真实包依赖；实际安装器负责拒绝缺失依赖。
- WSL 启动配置补上 gotoPlot 挂载；目录不存在时在停止或删除旧容器之前退出，不创建机密源码目录。本次不启动脚本、不重建容器。

## 取舍与非目标

只增加两个单包脚本会使现有批量入口和容器挂载仍不支持 gotoPlot，因此同步补齐它们；不新增通用安装框架，不修改其他 R 包源码、不安装或卸载真实包、不改生产连接或执行部署。

## 本地测试与生产写入规范

- 新建项目细则 `goto-software/local-testing.md`，承载服务矩阵、编译依赖、Java/R 文件映射、生产资源复用和并行测试要求。项目入口提供摘要、必读路由和 `global.database-readonly` 的显式覆盖登记。
- 生产测试写入包含本项目测试目标范围内的 API、应用、测试脚本和数据库客户端写操作，不因使用生产连接重复索取逐次授权；测试数据准备、变更和清理均允许。其他项目和非测试运维不继承该许可。
- 默认本地前端与 system/task 连接远程 home 数据库、Redis DB 1 和本机 WSL Rserve。生产资源是否复用与被测程序是否本地启动分开表达，不把生产写入许可解释成复用旧服务或忽略并行任务归属。
- 使用同一 Redis DB/Stream 消费组或共享输出文件的真实任务验收依次执行；只有已确认消息、数据与文件互不干扰才并行。不引入自动选 Redis DB、动态 Stream 协议或新锁服务。
- Maven 编译依赖为 rsession、freedom-public、goto reactor；JDK 17，使用当前平台安全包装器。公共 Maven 正文的项目范围改为服从已存在的平台映射，消除旧的 hsmap-only 描述。

## 补充验收

- 测试先验证项目入口与新细则的 override 和路由合同，确保覆盖只限 goto-software，其他项目不变。
- 规范校验、完整规则测试和 diff 检查通过；人工核对服务/构建/路径/资源/并行五项齐备，机密边界仍先于探索与调试。
- 同一变更集更新原有唯一总结，追加真实提交与验证结果，不创建第二份总结。

## 验收

- 外部脚本测试采用模拟 Docker，确认四包预检、顺序、参数检查与任一步骤失败后停止。
- 通过容器中的 R 解析器仅解析外部八个包装脚本，不执行；测试不读取真实机密目录、不调用包内函数。
- 规范元数据与既有规则测试通过，检查保密边界优先于探索、索引和调试指令。
- 跨仓提交均包含本 ID；在 goto-docs 的完成总结根目录保留唯一总结，不推送远端的已有未推送提交。

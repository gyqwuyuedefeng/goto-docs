# goto-web 参数联动自动化回归测试设计

## 1. 背景

`goto-web/src/constant/associationParamModify.js` 是绘图参数联动的统一入口。它负责执行公共参数联动，并根据图组 ID 分发到 `src/constant/modify/*Modify.js` 中的图组逻辑。`src/constant/modify/publicFunction.js` 提供分类参数、分面参数、文件标记、刻度范围等跨图组公共能力，同时维护上传、删除、保存和首次加载等生命周期处理器映射。

当前联动行为正常，但测试主要集中在若干局部函数和近期修改场景。统一入口自身只有少量刷新与首次加载分发测试，尚未形成“完整参数树 + 一次用户动作或文件事件 + 最终联动状态”的统一回归能力。因此，后续修改即使破坏跨模块联动，也可能无法在提交前及时暴露。

## 2. 目标

本期建设一套基于 Jest 的参数联动状态迁移契约测试能力，并实现以下闭环：

1. 从真实统一入口执行公共逻辑和图组逻辑，不绕过生产调用链。
2. 覆盖当前注册的全部 11 个图组。
3. 覆盖参数修改、文件上传、文件删除、文件标记保存、文件保存和首次加载等联动入口。
4. 使用稳定、可读、可复用的测试参数树与文件数据。
5. 对联动后的关键字段执行显式断言，同时断言关键无关字段没有被意外修改。
6. 新增图组却未增加契约场景时自动失败，防止覆盖范围悄然退化。
7. 提供可单独运行的快速命令，并继续纳入现有完整单元测试。

## 3. 非目标

- 不重构现有生产联动实现。
- 不引入新的测试框架、浏览器服务或端到端运行环境。
- 不把 Excel 上传、前端页面渲染、后端接口和 R 绘图执行纳入本期联动主测试。
- 不追求以行覆盖率代替业务场景覆盖率。
- 不为当前为空实现的处理器虚构业务行为。

## 4. 方案选择

采用数据驱动的状态迁移契约测试，不采用整棵对象的 Jest 快照，也不以真实 Excel 浏览器端到端测试作为主方案。

每个测试场景显式描述：

- 图组和入口类型；
- 初始参数树与文件数据；
- 一次用户动作或文件生命周期事件；
- 预期发生变化的字段；
- 预期保持不变的关键字段；
- 必要的 API 调用及提交参数。

选择该方案的原因是：字段级断言的失败信息更接近业务含义，合法修改只需更新受影响场景，不会产生完整参数树快照的大面积噪声，也不会依赖浏览器、接口或外部文件路径。

## 5. 测试架构

### 5.1 目录结构

```text
goto-web/tests/unit/constant/association/
├── associationTestBuilders.js
├── associationModify.contract.spec.js
├── associationLifecycle.contract.spec.js
└── fixtures/
    ├── common.js
    └── 各图组场景文件
```

只有在单个文件明显影响理解时才按图组继续拆分 fixture；不预建通用插件体系或独立场景执行框架。

### 5.2 测试构造器

`associationTestBuilders.js` 只提供现有运行时对象的最小构造能力：

- Vue 2 上下文：实现 `$set`、`$delete` 和 `$forceUpdate`，并保留调用记录；
- 参数项与 `moduleType === -1` 参数分组；
- `topParamSettingsList`；
- `fileSettings`、`uploadFileInfo.handsontable`、`headerInfoList` 和 `fileMarkContainerList`；
- `commonParams` 事件上下文；
- 每个测试使用的深拷贝和状态投影工具。

构造器不复制生产联动逻辑。它只负责生成符合生产函数输入结构的数据，避免测试自己实现一套联动规则后产生同源错误。

### 5.3 场景执行

参数修改场景按以下顺序执行：

```text
读取并深拷贝场景 fixture
→ 定位待修改 setting
→ 写入场景指定的新值或事件参数
→ 调用 associationParamModify
→ 提取关键状态
→ 执行变化断言与不变项断言
```

文件生命周期场景直接调用真实导出入口：

- `uploadFileModify`
- `deleteFileModify`
- `saveFileMarkSuccess`
- `saveFileSuccess`
- `firstLoadModify`

这些入口内部的参数重置、公共文件逻辑和图组处理器均使用真实实现。只有 API 持久化等外部副作用允许 mock；存在持久化预期时，需要同时断言调用次数和提交内容。

### 5.4 场景隔离

- 每个测试从不可变 fixture 深拷贝出独立参数树。
- 每条测试前后清理 Jest mock。
- 对 `publicFunction.js` 中按对象身份管理的运行时缓存，使用全新参数对象隔离。
- 不使用随机数、当前时间或依赖对象枚举偶然顺序的预期值。
- 若生产逻辑需要模板颜色，fixture 明确提供固定模板色。

## 6. 测试数据策略

主回归测试在 `goto-web` 仓库内直接构造轻量 JS fixture。`R/Software/goto/TestData` 用于选择具有代表性的真实列名、离散值和数值分布，例如：

- 分组、时间、性别等离散列；
- 丰度、坐标、置信区间等数值列；
- `GT_Selected` 与不同文件标记组合；
- 多文件同名列和空表头等边界数据。

测试运行不得依赖 `R/Software/goto/TestData` 的绝对路径，也不在单元测试中重复验证 Excel 解析。这样可以保证 CI、Windows 和 WSL 环境中的结果一致，同时保留数据的真实业务特征。若某个场景实际使用数据库业务字典，字典值例外地在测试运行时通过既有配置只读查询生产库，以实时结果为准，不缓存为固定预期、不静默回退到硬编码值；前端代码枚举不按数据库字典处理。

## 7. 覆盖范围

### 7.1 统一入口与公共能力

| 范围 | 必测契约 |
|---|---|
| `associationParamModify` | 公共逻辑与图组逻辑均被执行；`by`、刷新标记和 `dragSort` 触发正确刷新或排序；视图刷新次数符合入口约定 |
| 生命周期分发 | 上传、删除、保存文件标记、保存文件和首次加载进入正确的图组处理器 |
| 图例设置 | 图例位置与依赖参数显隐联动 |
| 分类参数 | 同组分类项的 `by` 和 `value` 同步，离散值列表正确重建或保留 |
| 分面参数 | `none`、`grid`、`wrap`、`radial` 的显隐、活动值和颜色状态迁移 |
| 文件标记参数 | 列内容参数和分组内容参数在上传、删除和保存标记后同步 |
| 刻度范围 | 标记列范围变化后的硬校验与输入修改后的轻校验 |

### 7.2 图组场景

| 图组 ID | 图组 | 必测关键联动 |
|---:|---|---|
| 4 | 饼图 | 值与标签位置、避让方式、环形厚度、文件标记后的列及选项同步 |
| 6 | 韦恩图 | 集合数量驱动的图类型禁用与回退、权重显隐、保存标记后的重建 |
| 7 | 箱线/小提琴图 | 图形类型、点类型、中位数类型、箱体模式和分类颜色联动 |
| 8 | 柱状图 | 误差线显隐、Y 轴与误差线列互斥、分类属性和分面联动 |
| 12 | 曲线图 | 曲线类型、平滑与拟合方式、置信区间、拟合统计和堆叠模式 |
| 13 | 热图 | 宽表与长表切换、行列注释参数、不同文件索引的生命周期联动 |
| 14 | 网络图 | 当前空处理器无副作用，且统一入口和各生命周期映射未丢失 |
| 15 | 桑基图 | 节点与边分类同步，节点分组数量驱动对齐和间距列表 |
| 17 | 散点图 | 图形类型、边际图、中心线、地毯线、标签、HDR、分箱和文件标记 |
| 19 | 旭日图 | 分组列变化后颜色列表按唯一值重建，数据类型入口保持兼容 |
| 22 | 堆叠柱图 | 样式、分面、极坐标限制、标签显隐、元数据文件和首次加载迁移 |

每个存在真实行为的图组至少具备：

1. 一条参数修改状态迁移；
2. 一条适用的文件生命周期状态迁移；
3. 一条反向迁移或边界场景；
4. 一组关键不变项断言。

对于网络图等当前为空实现的图组，仅验证分发完整性和无副作用，不增加没有当前业务消费者的测试抽象或虚假预期。

## 8. 注册完整性约束

契约测试维护明确的当前图组场景注册表，并与 `GLOBAL_PLOT_GROUP_PARAMS` 中的处理器映射键集合比较。至少校验 `DO_MODIFY_MAP` 的图组集合为：

```text
4, 6, 7, 8, 12, 13, 14, 15, 17, 19, 22
```

同时检查各生命周期映射的已注册集合。新增图组或移除映射时，如果场景注册表未同步调整，测试必须失败并显示缺失或多余的图组 ID。

该约束只校验注册与场景覆盖的对应关系，不把生产映射结构复制到新的运行时配置中。

## 9. 失败诊断与错误处理

- 测试名称包含图组、触发参数、入口类型和预期业务结果。
- fixture 缺少场景必需的参数时，由构造器抛出包含参数名和场景名的错误。
- 断言直接比较业务字段，避免只断言“没有抛异常”。
- 对有意保持无行为的处理器，比较调用前后的状态投影，证明没有意外修改。
- 不提供自动更新预期结果的脚本。合法联动变更必须由开发者审阅并显式修改对应场景。
- 对无法稳定断言的非业务字段不纳入预期投影，但不得因此忽略显隐、值、选项列表、禁用列表、文件索引和持久化参数等业务字段。

## 10. 运行方式

在 `goto-web/package.json` 中增加快速入口：

```text
npm run test:association
```

该命令只运行 `tests/unit/constant/association/` 下的契约测试。现有 `npm run test:unit` 的 Jest 匹配规则继续自动包含这些文件，不建立第二套测试配置。

## 11. 验收标准

1. 当前 11 个注册图组全部存在对应契约场景。
2. 参数修改场景通过真实 `associationParamModify` 入口执行。
3. 通用联动和五类文件生命周期入口均有完整链路测试。
4. 人为破坏任一已覆盖的显隐、值同步、列表重建、图组分发或注册关系时，对应测试失败，并能从测试名称和断言差异定位场景。
5. `npm run test:association` 执行通过。
6. `npm run test:unit` 执行通过，既有单元测试无回归。
7. 测试运行不依赖 `R/Software/goto/TestData` 的绝对路径、浏览器或后端服务；若场景确实涉及数据库业务字典，只允许复用既有客户端和连接配置对生产库执行实时只读字典查询，任何写入均禁止。

## 12. 后续事项

真实 Excel 上传到页面后的浏览器端到端冒烟测试可在后续独立建设。本期先完成参数联动逻辑层的确定性回归闭环，不预先引入浏览器自动化基础设施。

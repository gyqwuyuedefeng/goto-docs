# 桑基图 PDF 文字比例修复设计

## 目标与现状

用户要求导出的桑基图 PDF 与页面显示一致，尤其是文字和连线的相对比例；本轮只修桑基图 PDF，网络图和其他格式保持现状。现有流程由前端上传当前 SVG，`DrawPlotDownload` 调用 `fileConvert.sh` 转 PDF。该脚本默认以 300 DPI 调用 `rsvg-convert`。

已用同一份现有桑基图 SVG 复现：浏览器在 402×241 像素下显示正常，300 DPI 转换后的 PDF 按同样像素尺寸栅格化时文字严重重叠；改为 96 DPI 后，文字与图形比例基本恢复。SVG 的坐标由约 401×241 的 `viewBox` 描述，文字使用 `font-size="8pt"`。300 DPI 将 PDF 页面缩至约 96×58 pt，但文字仍保持原物理字号，产生相对放大。

## 设计

在 `goto/system` 的 `DrawPlotDownload` 中，仅当图组为桑基图（现有分支值 15）且下载格式为 PDF 时，向已有转换脚本传入 `-d 96`。其他调用仍不传 DPI，沿用脚本默认 300。前端的当前 SVG 上传、SVG 直接打包、脚本默认值及网络图路径均不改变。转换命令的失败处理与现状一致，不另建转换服务或配置项。

选择该方案是因为它直接修正已定位的 SVG→PDF 单位不匹配，变更范围可由下载器现有图组和格式判断限定。备选方案有两种：在前端把 SVG 的 `pt` 字体转换为 `px`，但会改变上传源文件及其他导出；修改 `fileConvert.sh` 的全局默认 DPI，则会影响全部图形。两者均超出本轮范围。

## 验证与边界

先新增失败测试，证明桑基图 PDF 转换命令缺少 `-d 96`，并覆盖网络图 PDF 与桑基图非 PDF 仍使用原命令；随后做最小实现，使测试由红转绿。再使用现有桑基图 SVG 执行真实转换，按同一输出尺寸对照浏览器与 PDF，并完成受影响模块测试、构建、后端启动及关闭验证。不能用仅生成了 PDF 文件代替内容核对。

桑基图页面内滚动条另有来源：生成 HTML 的固定尺寸容器设置了 `overflow:auto`。简单隐藏会裁掉越界标签或拖动后的节点；用户允许暂缓，因此本轮不改滚动条，也不改变生成 HTML 或图形布局。

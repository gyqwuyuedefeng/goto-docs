# 图形通用功能与图片多格式转换完成总结

## 结果摘要

五项功能的本地实现及先前真实浏览器通过记录见下文。图例「重新标记并保存」的补充端到端验收当前受环境依赖阻塞，测试变更保留在前端工作区。

## 原因与目标

绘图共用文件合并需要支持两份文件的异名列按顺序配对，允许等量的多个匹配列。列名标记应明确显示必选状态，绘图同级参数名统一为常规字重。同名列暂时失去标记后，应保留用户设置的图例方向、列数和刻度数。图片工具应按上传文件后缀识别输入格式，并支持一次选择多个输出。

## 设计决策

- 合并预览分别返回已上传文件与追加文件的完整表头。两边按控件选择顺序配对，服务端校验列存在性和两侧数量。异名键使用追加表临时副本对齐表头。追加表同名的非键列保留为独立列。现有 R 合并入口实际只接受单键，任务层把多列编码成单个临时键并复用原合并入口，结果移除临时键后再替换已上传工作簿。旧接口同名列仍可调用。
- 标记提示读取模板的 `required` 状态。字重统一在绘图工作区共享表单样式中，折叠面板分组标题沿用标题样式。
- 图例按列名在同一绘图会话内恢复排列参数。新增列使用模板默认值。
- 图片输入沿用工具已有的 PDF 和 SVG 能力，后缀忽略大小写。多格式依次复用转换任务，每个格式独立展示下载或错误。

## 实际变更

- goto-web 的共用表格增加双列选择和配对预览。绘图页列标记增加必选及可选提示，共用参数样式统一。图例刷新保留短暂消失列的排列设置。图片工具使用多选输出和分项结果。
- goto 的 system 接受并校验两组列，处理 Excel 或 CSV 追加表的异名键。task 在需要时构造临时复合键，并在结果完整时发布工作簿。
- home 只读核对模板及字典。热图模板 286 的行、列和主值为必选，次值、标签、属性为可选。桑基图 291 的边设置包含 `colorFollowNode`、`edgeThicknessPower`、`edgeMaxWidth`、`edgeBorderWidth` 和 `edgeFillColor`，这些参数字段作为同名 R 参数输出。边颜色的选列来源包括边文件的标记列，控件显隐受 `colorFollowNode` 联动。三组模板中的 `legendList` 由分类联动生成。绘图模板的 103 个存储文件设置使用 XLSX。

## 偏差、风险与遗留

- Windows Git 最初在 SSH 握手阶段断开。通过命令级 Windows SSH 配置使用已验证地址及主机密钥后获取成功。仓库远端配置保持原值。
- 首轮生产构建发现 Webpack 无法解析新增的可选链。改用项目兼容语法并重跑。首次浏览器字重检查发现全局绘图规则覆盖局部样式，统一修改共享规则，并在禁用旧缓存的新编译中验收。
- 真实复合键首次执行发现原合并入口无法接收多个键。采用临时单键适配，补充回归测试并通过真实合并。
- 首轮启动缺少 HMAC、后续发现缺少精确站点 Origin。通过本次进程作用域的测试配置及成对分配的端口解决，所有失败启动和最终验收实例均已关闭。
- 先行 Maven 执行会话曾在日志显示 BUILD SUCCESS 后返回 143，另一次复核曾因 VPN 检查的 Windows 监听层失败在启动前停止。网络恢复后重新运行，最终结果见上节。浏览器脚本初次定位必选标签时使用不匹配的相对选择器，修正后以真实页面复核。首轮 Jest 匹配了历史 worktree 下的同名测试，最终通过限制测试根目录重新计数。

- 追加复验首轮已通过真实合并，但分类弹窗未出现 `level`，用例超时。原脚本只等待合并后的表格结果，列标记依赖的表头通过独立请求刷新。测试补充等待和校验表头响应，并确认属性标记显示后再打开分类弹窗。随后两条真实链路一次运行通过。业务源码无此次追加改动。

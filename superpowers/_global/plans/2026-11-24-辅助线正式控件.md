# 辅助线正式控件实施计划

> 并行任务按独立的 Java、前端和浏览器用例边界推进，主任务负责集成与验证。

**目标**在两处管理页及用户绘图使用正式辅助线控件，完成规范合入和真实 Playwright 验收。

**契约**使用 moduleType 31 和 paramName auxLine。value 是有序的行数组。行保留 type、value、label、position、color、linetype、linewidth。横竖线的 value 是数值列表，斜线的 value 由 {mode, values} 组成。旧 referenceLines 和旧六项仅作快照兼容。Java 在公共绘图调用生成 auxLine，实际绘制由 R 绘图函数负责。

- [x] 完成规范主分支集成并核验目标节及双方成果。
- [x] Java 注册、往返转换、同步隔离、兼容数据读入、原生 R 实参生成及测试。
- [x] 共享管理新增配置、用户图正式组件、逐项改表保留及定向前端测试。
- [ ] Playwright 验证三个保存位置、同步和回显、实际折线与散点图及下载。
- [ ] 根据本地实际验收结果合入应用工作树并保存验证记录。

应用侧通过独立应用和已授权的公开绘图接口验收。R 包维护者负责修改和构建机密 R 包。

## 辅助线标签修复计划

**目标**让散点图原生绘出 `auxLine` 的标签，并用同一套用例复核折线图。预览与下载用同一次绘图产生的图形验证。

### 1. 锁定故障发生位置

- [ ] 固定模板、轴范围、字体、尺寸和 Excel 输入，用同一 R 构建分别执行三组调用。第一组 `label = ""`，第二组指定 `label = "SD"`、`position = 0.1`，第三组保留 `SD` 并设 `position = 0.8`。先只传一条横线，再用现有包含两行横线、一行竖线和三种斜线的 7 条线用例复验。
- [ ] 分别验证 `GT_Scatter` 和 `GT_Curve`。核对浏览器请求、保存后的快照和任务生成的 R 实参，确认标签与位置按同一配置行传到 R。Java 定位入口为 `goto/common/src/main/java/com/freedom/util/ReferenceLineSettings.java` 的 `asRList`。已有 `PlotAuxLineTest` 覆盖标签、位置和 Unicode 字符。
- [ ] 如果直接调用 R 也无法读出 `SD`，由 R 包维护者定位标签生成环节。如果直接调用正确而应用失败，沿 Java 参数组装或预览与下载取图入口定位差异。前置证据是两张生产 SVG 均有新增辅助线，但散点图的指定标签尚未通过验收，折线图也需复核。

### 2. 在原生绘图中生成标签

- [ ] 保持输入契约 `auxLine = list(...)`。R 包维护者在原绘图函数构建图对象时，把当前行的 `label` 和 `position` 应用到该行辅助线。预览与导出使用这个图对象。
- [ ] 有公开且可复验的定位口径时沿用。其余情况建议把 `position` 定义为当前面板内可见线段上的比例。横线从左到右，竖线从下到上，两点斜线沿 P0 到 P1，其余斜线按 X 坐标递增方向。同一行有多根线时，建议每根线各显示一次该行标签。空标签只画线。用 `0` 和 `1` 验证边缘标签可读。
- [ ] 交付可识别的 R 构建及版本或提交 SHA，并给出两张图有标签、换位置和清空标签的对照片。在隔离的 Rserve 环境核对实际加载的构建，再运行应用验收。

### 3. 恢复 Playwright 验收并发布

- [ ] 更新 `goto-web/tests/e2e/plotReferenceLines.playwright.cjs` 的 `assertSvg`。颜色按等价的十六进制与 RGB 值匹配。SVG 有 `<text>` 时直接核对文案。文字转为轮廓时，在固定轴范围、字体和尺寸下，对照标签区域的浏览器渲染，确认指定文字可见，换位置后跟随移动，清空后消失。保留线条数量、样式和有效几何断言。
- [ ] 用真实数据跑通两种图的 Excel 上传、参数提交、异步出图、历史回显、SVG 预览和实际下载。既有管理页用例继续覆盖 `PlotGroup`、`PlotType` 与 `UserDraw` 的保存和同步。用一份旧位置参数记录复跑一次重绘。如果已确认支持 `auxLine` 的函数仍收到其拒绝的旧实参，只在这些函数的 Java 调用边界补兼容转换。
- [ ] 上述回归通过后按生产发布规范备份和校验产物，再发布。线上使用真实登录复查两种图的标签、预览和下载，按验收结果决定保留发布或回退。

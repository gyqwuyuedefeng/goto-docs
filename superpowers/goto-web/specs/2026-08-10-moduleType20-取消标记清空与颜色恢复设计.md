# moduleType=20 取消标记清空与颜色恢复设计

## 背景

`goto-web` 的分面参数组件使用 `moduleType = 20`。保存文件标记成功后，
`associationParamModify.saveFileMarkSuccess()` 会调用 `reSetParamSettings()`，再由
`processFacetParamSetting()` 根据 `facetFileMarkColumnList` 和文件表头的标记状态重建分面参数。

提交 `82c6736` 为了在上传文件和重新标记时保留分面勾选状态及颜色，将“所有关联标记列均解析不到有效表头”定义为
`BINDING_MISSING`，并直接保留旧配置。这个状态同时覆盖了两种含义不同的情况：

1. 文件、标记容器或关联索引不存在，无法判断用户意图；
2. 关联源完整存在，但用户明确取消了该标记位的全部列。

因此，用户取消文件标记并保存后，`rows`、`cols`、`facets` 以及活动颜色列表仍保留旧值。

此外，分面颜色由 `publicFunction.js` 中的 `WeakMap` 运行时缓存支持。该缓存不是旧活动值未清空的直接原因，
但如果修复时只清空界面数据而没有先保存当前颜色，首次未曾触发缓存写入的颜色可能无法在重新标记后恢复。

## 目标

- 关联标记位明确没有选中任何列时，立即清空 moduleType=20 的活动分面值。
- 将来重新标记同一列并由用户重新勾选后，恢复此前的背景色和边框色。
- 不自动恢复旧分面勾选状态。
- 保持跨文件同名列的颜色隔离。
- 保持关联源缺失时的兼容行为，避免把无法判断的临时状态当成用户明确取消。

## 非目标

- 不改变 `facetFileMarkColumnList` 本身的组件关联配置。
- 不持久化运行时颜色缓存。
- 不恢复旧版“每次都先全量清空再重建”的实现。
- 不修改 moduleType=7、22、27 或刻度范围等其他参数类型的重置语义。
- 不重构现有分面组件或建立新的通用状态管理层。

## 状态模型

处理 `facetFileMarkColumnList` 时区分以下三种结果：

### 1. 关联缺失

满足以下任一情况：

- `facetFileMarkColumnList` 为空；
- 所有关联项对应的文件不存在；
- 所有关联项对应的 `SELECT_COLUMN` 标记容器不存在；
- 所有关联源均因结构异常而无法可靠解析。

该状态无法确认用户是否主动取消标记，继续保持当前活动值和缓存不变。

### 2. 明确为空

至少有一个关联项能够解析到文件、表头列表和对应的 `SELECT_COLUMN` 标记容器，但所有可解析关联项均没有选中任何表头。

该状态代表用户明确取消标记。处理前先缓存当前活动颜色，再清空活动分面值。

### 3. 存在有效标记

至少解析出一个被标记的表头。处理前先缓存当前活动颜色，再按现有复合身份合并有效候选列、勾选状态和活动颜色。

当多个关联中只有部分仍有有效标记时，只保留当前有效列；已取消列的颜色仍留在运行时缓存中，以便将来恢复。

## 活动状态与可恢复状态

### 活动状态

“明确为空”时通过 Vue 2 响应式写入清空：

- `rows.value.list`
- `cols.value.list`
- `facets.value.list`
- `fillColorList.value`
- `borderColorList.value`

清空后，界面和后续参数保存均不再包含已取消标记产生的分面列。

### 可恢复颜色状态

继续复用 `publicFunction.js` 中现有的 `facetColorStateCache`：

- 缓存仍以 moduleType=20 设置对象作为 `WeakMap` 键；
- 颜色组仍以 `columnName + fileSettingIndex` 作为身份；
- 清空或重建活动状态前，显式把当前背景色和边框色写入缓存；
- 不删除因取消文件标记而暂时不可用的颜色组；
- 缓存不写入设置对象，也不参与后端序列化。

重新标记同一列后，该列先以未勾选状态进入候选列表。用户重新勾选时，现有颜色同步流程从缓存恢复颜色。

## 代码边界

### `src/constant/paramSettingsReset.js`

- 增加最小的关联源解析结果，区分“关联缺失”“明确为空”“存在有效标记”。
- `processFacetParamSetting()` 根据解析结果决定保持、清空或重建。
- 清空时直接操作传入的 `facetParamSetting`，避免通过参数名查找而误处理其他 moduleType=20 实例。
- 保留现有的有效列去重、三组候选列表独立 checked 恢复以及活动颜色合并逻辑。

### `src/constant/modify/publicFunction.js`

- 在现有颜色缓存边界内增加一个封装方法，用当前分面类型快照活动颜色。
- 复用 `cacheFacetActiveColorGroups()`，不向调用方暴露 `WeakMap` 或内部缓存结构。
- 保持类型切换、取消并重新勾选以及跨文件同名列恢复逻辑不变。

### `src/constant/associationParamModify.js`

无需修改。保存标记成功后已经正确调用 `reSetParamSettings()`；问题发生在 moduleType=20 对空解析结果的解释阶段。

## 数据流

```text
保存文件标记成功
  -> associationParamModify.saveFileMarkSuccess
  -> reSetParamSettings
  -> processFacetParamSetting
       -> 解析关联源和当前标记表头
       -> 关联缺失：保持活动值和缓存
       -> 明确为空：缓存当前颜色 -> 清空活动值
       -> 存在有效标记：缓存当前颜色 -> 重建活动候选和颜色

将来重新标记同一列
  -> processFacetParamSetting 重建未勾选候选列
  -> 用户主动勾选
  -> facetParamsModify
  -> 从 facetColorStateCache 恢复该文件该列的背景色和边框色
```

## 异常与兼容处理

- 非法文件索引、缺失文件、缺失表头列表或缺失标记容器均视为不可解析关联，不抛出异常。
- 只有能够证明关联源存在且当前选择为空时才清空，避免失败开放式误删配置。
- 部分关联不可解析、部分关联可解析时，以可解析关联的当前选择为准重建活动列表。
- 旧颜色组缺少 `fileSettingIndex` 时继续遵循现有唯一名称兼容规则；跨文件同名时不得猜测归属。
- 使用现有 `$set`/响应式赋值方式，确保 Vue 2 界面同步更新。

## 测试设计

在 `tests/unit/constant/paramSettingsReset.spec.js` 和分面颜色缓存相关单测中覆盖：

1. 标记容器存在且所有表头对应状态位均为 `0` 时，五组活动值全部清空。
2. `facetFileMarkColumnList` 为空时保持当前兼容行为。
3. 文件或标记容器不存在时保持旧值。
4. 多个关联中只取消一个时，仅移除该关联产生的候选列和活动颜色。
5. 清空前尚未触发过类型切换或勾选变化时，当前颜色仍会被写入缓存。
6. 取消标记并保存后重新标记同一列时，候选列恢复但默认未勾选。
7. 用户重新勾选后，背景色和边框色恢复为取消前配置。
8. 跨文件同名列分别恢复各自颜色，不发生串色。
9. 正常重新保存标记时，现有候选列、勾选状态和颜色合并行为保持不变。

## 验收标准

- 取消组件所关联标记位的全部列并保存后，界面中不再显示旧分面候选或活动颜色。
- 后续参数数据中不再携带由已取消标记产生的活动分面列。
- 重新标记同一文件的同一列后，该列默认未勾选。
- 用户主动勾选该列后，恢复取消前的背景色和边框色。
- 两个文件的同名列始终按 `fileSettingIndex` 隔离。
- 关联配置缺失或关联源不可解析时不误清旧配置。

## 方案取舍

未采用仅在保存回调中强制清空的方案，因为这会把 moduleType=20 的业务语义分散到事件层，并难以正确处理多文件和部分取消。

未恢复旧版“先全清空再重建”方案，因为该方案会丢失正常重新标记时的勾选状态，并与已确认的颜色恢复需求冲突。

本设计只补充现有解析模型缺失的“明确为空”语义，并复用现有颜色缓存，是形成完整闭环的最小改动。

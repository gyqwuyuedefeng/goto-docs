# 绘图多行辅助线完成总结

## 结果摘要

折线图和散点图的多行辅助线已发布至 [GOTO Studio 绘图站](https://plot.goto-studio.cn/)。本地 Playwright 验证三组绘图用例，生产 Playwright 使用管理员账号登录并通过两组业务回归。验收创建的生产绘图记录已清理。

## 原因与目标

补齐上一变更集暂缓的辅助线配置。支持同一类型的多行，每行可含多根线并单独设置标签、位置、颜色、线型和线宽。保持 Excel 多工作表的默认首表和选择上传行为。替换数据时逐项判断输入值，保留仍然有效的内容。

## 设计决策

- 折线图组 12 和散点图组 17 使用同一编辑器。斜线逐根选择两点、斜率加截距、点加角度三种输入，位置使用 0 至 1 的线段比例。
- 使用现有绘图快照保存配置。历史记录可读原有辅助线值。Java 在任务提交前校验新结构，对基础绘图显式传空以关闭旧线。基础图成功后更新最终 SVG 和下载使用的 RData。

- 生产管理员密码登录和图形验证码在真实浏览器完成。折线图与散点图分别核对 7 根线、4 个标签、各组颜色和样式、SVG 下载及历史回显。Excel 换表验证单表、默认首表、选择第二表、取消无提交、保留轴与标题，以及 `1、3、5` 只清除 `5` 并成功绘图。

## 偏差、风险与遗留

- 隔离 Maven 缓存缺少私有依赖，准备过程耗时。合入基线后使用安全包装器继续，Windows 挂载盘上的管理包重打包仍在文件替换阶段失败，具体文件系统原因待确认。改用完全相同提交的 Linux 临时构建目录后恢复。
- 前端生产打包器无法解析新组件的一处空值运算符，已改用项目兼容语法。首轮 Playwright 按普通 JSON 读到了 gzip 请求体，散点测试工作簿也缺默认点大小映射列。已分别按真实协议解压，以及补足模板所需测试列。
- 真实绘图暴露出旧 R 函数省略辅助线参数时会使用默认值而报错。经同一工作簿对照确认，显式传空后完整绘图和渲染成功，并补齐了参数回归断言。
- 首轮生产重建同时启动两个 Java 服务，90 秒未等到就绪，已自动回退。原版本回启管理服务耗时约 115 秒。随后复用校验后的产物逐个启动并等待实际就绪。恢复过程中发现代理缓存了原容器地址，已通过语法检查和平滑重载恢复转发。
- 干净前端基线复现 3 项热图单元契约测试失败。抽测的两份旧散点 RData 在原绘图构建或绘制阶段失败。本次相关的本地及生产 Playwright 用例均已通过。

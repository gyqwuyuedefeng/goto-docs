# 系统管理编辑详情样式隔离设计

## 目标与范围

继续精修 `plotGroup` 与 `plotType` 的全屏编辑详情，使基础信息、文件设置、参数卡片、字段控件、嵌套配置和底部操作区形成统一的管理工作台视觉。

本次只改变两个系统管理页面编辑弹窗中的展示结构和样式。`views/goto/components/paramSettings.vue`、`fileSettings.vue`、`views/goto/components/form/plotSetting` 以及 `views/goto/plot` 继续作为用户端共用实现，不修改其模板、脚本和默认样式。

## 方案比较

1. **系统页上下文 class + 管理端 scoped 深层样式（采用）**：两个管理弹窗增加唯一的详情外壳，并给现有 `FileSettings`、`ParamSettings` 实例增加管理端 class；所有覆盖都从 `.goto-settings-page .management-detail-shell` 开始。改动最少，且不会改变共享组件在其他页面的表现。
2. 给共享组件递归增加 `adminMode` prop：边界显式，但 `ParamSettings` 的递归结构和大量 `plotSetting` 子组件都需要透传，改动面大且容易影响功能。
3. 复制一套管理端组件：物理隔离最强，但会让参数组件形成两套长期分叉，后续业务修复容易遗漏，不符合当前最小闭环。

## 结构设计

- 两个全屏 `management-edit-dialog` 的表单内容外包一层 `.management-detail-shell`。
- `FileSettings` 实例增加 `.management-file-settings`，`ParamSettings` 实例增加 `.management-param-settings`；这些 class 只存在于两个系统管理页面。
- 详情正文保持原有组件层次、数据绑定、事件和 ref，不新增 prop，不改变共享组件源码。
- 全屏弹窗使用纵向 flex：标题固定、正文独立滚动、底部操作区保持可见。

## 视觉设计

- 详情正文限制最大阅读宽度并居中，浅灰蓝画布承载白色内容分区。
- 文件设置的每个文件成为独立卡片；字段从旧式“灰色标签拼输入框”调整为上标签、下控件的响应式网格。
- 参数设置的 `g-card` 使用一致的圆角、边框、标题栏和正文留白；普通字段以最小 240px 的网格排列，复杂列表组件可独占整行。
- 输入框、选择器、数字框、单选按钮统一高度、圆角、边框和焦点环；移动、添加、删除等按钮保留原语义但降低视觉噪声。
- 右侧参数模块添加入口保持原交互，只调整尺寸、阴影和展开面板质感。
- 低于 900px 时字段网格收敛为单列，弹窗正文减少留白，不产生视口级横向滚动。

### 复杂列表参数修正

第二轮浏览器验收使用 `moduleType = 13`、`paramName = ManageParamTemplateColor`、6 个颜色列表项的真实同结构数据，确认普通参数 mock 未覆盖以下问题：

- `plotSetting/list.vue` 的根容器和配置卡片固定使用白色，深色主题下形成大块浅色断层。
- 参数外层已经提供数据结构、数据类型、权限和同步入口，列表子组件内部又显示一套相同配置，造成信息重复。
- 列表子组件使用 `450px + 1fr` 双栏、`height: 100%` 与 500px 内滚动；它和全屏弹窗正文滚动叠加，产生双滚动及大面积空白。
- 未选中的单选按钮固定为白色，与深色输入框和卡片不一致。

修正继续只写在 `.management-param-settings` 上下文中：

- 保留参数外层的字段、同步图标和所有交互；仅隐藏列表子组件内部重复的 `.config-panel`。
- 列表编辑器改为单一列表面板；列表项在宽屏使用双列网格，在较窄视口回落为单列。
- 移除列表项容器的固定最大高度和内层纵向滚动，由全屏弹窗正文统一负责滚动。
- 列表根容器、标题、卡片、列表项和未选单选按钮全部使用全局主题变量，不再写死白色。
- 参数卡片末尾的数据关联与排序入口保留原有层级和事件，仅收敛为主题化工具区，避免按钮直接散落在卡片底部。
- 保留新增、删除、上移、下移、勾选和颜色编辑的原事件与 DOM，不改变 `list.vue`、`paramSettings.vue` 或其他共享组件源码。

## 隔离与功能保护

- 管理端新增规则必须同时位于 `.goto-settings-page` 与 `.management-detail-shell` 上下文内。
- 不修改共享用户组件；契约测试扫描这些文件，确保没有反向引用 `management-detail` 或管理端 SCSS。
- 两个目标页面的 `<script>` 哈希继续保持不变。
- 不调整 CRUD、接口、表单字段、事件、递归参数结构、上传或同步逻辑。

## 验收标准

1. 两个编辑弹窗的基础信息、上传文件设置和参数设置均呈现一致的卡片与字段网格。
2. 管理端详情在桌面与窄屏均无页面级横向溢出，正文和底部操作可用。
3. `paramSettings.vue`、`fileSettings.vue`、`form/plotSetting` 和用户画图页没有源码改动，也不引用管理端样式。
4. 页面脚本哈希、隔离契约测试、相关单元测试、生产构建和 Playwright MCP 交互验证全部通过。
5. 深色主题复杂列表参数不出现固定白底；外层配置和列表项职责分离，不再显示子组件内部的重复配置区。
6. 复杂列表只有弹窗正文一个纵向滚动层；6 个列表项在宽屏双列展示，新增、移动、删除、勾选和颜色编辑入口保持可用。

## 规格自审

- 无待定项或占位符。
- 样式隔离范围、允许修改的文件和禁止修改的共享组件没有冲突。
- 当前方案只解决两个系统管理编辑详情，不建立新的组件体系或管理模式协议。
- 复杂列表修正仍由现有管理端父级上下文完成，没有放宽共享组件零改动边界。
- 每项验收标准均可由源码契约、构建或 Playwright MCP 复验；复杂列表必须使用深色主题和真实同结构数据，不得再用普通输入框、单选框替代。

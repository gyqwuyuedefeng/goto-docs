# 图形／统计上传限额与解析提速 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 图形／统计上传前后端统一限制为 20,000,000 字节，消除大表插列的平方级搜索与文本单元格的异常解析开销，保持整表编辑。

**Architecture:** 前端直接使用的 `Uploader` 默认限制设为 20 MB；后端在六个业务上传处理类进入保存与解析前调用同一个大小校验器。`HandsontableUtils.addColumn` 按行下标遍历；共用 Excel 监听器先识别数字再构造 `BigDecimal`。

**Tech Stack:** Vue 2、Jest、Java 17、Spring Boot 3、JUnit 5、Maven 安全包装器。

## Global Constraints

- `Change-Set-Id: CS-20260925-6ccfe78f-d470-4f95-a4b5-8c73c0c23231`；所有提交用中文消息及该 trailer。
- 机密 R 包目录和同源副本禁止读取、索引、构建、测试内部实现。
- Maven 仅用 WSL 安全包装器；Java 新增和修改代码及测试需详细中文注释。
- 前后端边界为 `size <= 20_000_000` 允许，`size > 20_000_000` 拒绝。
- 保留上传后整表立即可编辑、现有接口格式及非图形／统计上传限制。

- `goto/system/src/main/java/com/freedom/model/file/upload/impl/PlotTypeUploadSizeLimit.java`：六类图形／统计上传共用的大小判断及错误消息。

### Task 5: 同会话返修 Excel 文本解析开销

**Files:** 修改 `freedom-public/common-utils/src/main/java/com/freedom/model/NoModelSheetDataListener.java`；新建 `freedom-public/common-utils/src/test/java/com/freedom/model/NoModelSheetDataListenerTest.java`；更新本设计、计划和唯一收尾总结。

**Interfaces:** `invoke(Map<Integer, Object>, AnalysisContext)` 继续把可被 `BigDecimal` 接受的单元格值转为 `BigDecimal`，普通文本、非法数字与 `null` 维持原对象；表头、行数、文件格式和可编辑表响应不变。新增包内可见的 `convertCellValue(Object)` 仅供监听器内部复用与单元测试。

- [x] **Step 1: RED。** 新测试用真实的包内转换方法验证 `"text-001"`、`"1x"`、`"NA"` 不产生 `NumberFormatException` 且保持原值；`"12"`、`"-0.5"`、`".5"`、`"1e3"` 仍得到对应 `BigDecimal`；`null` 不变。对 1000 个普通文本值开启 JFR `jdk.JavaExceptionThrow` 事件，断言该段没有 `NumberFormatException`。先用 Maven 安全包装器运行此测试并确认因方法尚未存在而失败，不以测试配置错误当作 RED。
- [x] **Step 2: GREEN。** 将 `invoke` 中逐单元格的 `try { new BigDecimal(...) } catch (Exception)` 改为调用 `convertCellValue`。该方法先处理 `null`，再以无异常的字符扫描检查可选正负号、整数或小数位、可选指数位；不符合十进制形态时直接返回原值。符合形态时用 `new BigDecimal(text)` 作最终判定，极少数不被构造器接受的边界仍回退原值。为方法和关键分支写中文注释；重跑定向测试和现有 `HandsontableUtilsTest`。
- [x] **Step 3: 性能。** 以相同的 `01_172800rows_real.xlsx` 与原版、修复版分别在同一操作系统、相同 JDK、相同临时存储位置测三次读取链路，记录每段耗时和生成表格行数；必要时只在项目外临时目录保存 JFR 数据。不得把独立方法耗时冒充完整 HTTP 耗时。

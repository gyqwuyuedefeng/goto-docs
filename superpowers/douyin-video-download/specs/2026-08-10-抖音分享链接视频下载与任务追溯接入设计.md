# 抖音分享链接视频下载与任务追溯接入设计

- 目标代码目录：`/mnt/f/IdeaProjects/goto-software/douyin-video-download`
- 状态：已完成分段设计确认，待用户审阅本文档
- 主流程：Superpowers

## 1. 目标

建立一个只在本机使用的最小网页工具：用户粘贴一段抖音分享文字或单个抖音链接，服务从中提取唯一链接，使用仓库外的匿名 `cookies.txt` 调用 `yt-dlp` 获取公开视频，再以 MP4 附件返回浏览器。

本项目同时作为 Codex Task Orchestrator 的第一个真实端到端任务，验证项目登记、Brainstorm/Spec/Plan 记录、执行日志、测试证据、Git 提交、最终摘要和人工审核的追溯闭环。

## 2. 范围拆分与实施顺序

这是两个独立但有先后依赖的功能：

1. 先为 Codex Task Orchestrator 补齐最小的项目登记与任务历史闭环。该平台只使用其项目规则指定的 Spec Kit 主流程，不用本文档替代平台功能规格。
2. 再在平台中登记 `goto-software` 项目组和 `douyin-video-download` 仓库，把本设计作为阶段输入，由 Worker 执行下载器的实施计划。

两者不共享代码、数据库或运行进程。平台只负责任务编排与追溯，下载器保持为可独立运行的小项目。

## 3. 平台前置能力与集成契约

### 3.1 项目登记

平台页面提供一个最小登记入口，允许：

- 新建项目组；
- 登记已存在的本地 Git 仓库、具体分支和本地 Remote；
- 查看登记结果和可用执行分支。

平台不代替用户任意创建或删除本地目录。`douyin-video-download` 在目标目录中初始化为独立 Git 仓库，避免继承当前脏的 `goto-software` 父仓库状态。

### 3.2 WorkItem 详情与历史

WorkItem 详情页至少展示：

- 概要：标题、目标、状态、项目组和关联仓库；
- 阶段记录：Brainstorm 对话与人工回答、Spec、Plan 的版本、内容和摘要；
- 执行记录：ExecutionTask、Attempt、Codex Session、完整脱敏事件日志；
- 结果：改动文件、测试、Git 提交、风险、阻断、最终摘要和审核结果；
- 历史：返修、重试和关联 WorkItem。

当前 Brainstorm 对话以 Markdown 阶段输出导入，不新增一套“自动驱动 Brainstorm 会话”的调度系统。

### 3.3 搜索与上下文复用

第一版使用 PostgreSQL 普通文本查询，覆盖：

- 任务标题和目标；
- Brainstorm、Spec、Plan 阶段输出；
- 最终摘要、改动文件、关联目标、Git 提交和审核理由。

创建新任务时可搜索并选择关联历史 WorkItem。任务认领时冻结精确的 Brainstorm、Spec 和 Plan 版本，Worker 提示词必须包含这些阶段内容和已选关联任务的摘要，不能再只传标题与目标。

第一版不引入向量库、Embedding、日志平台或 LLM Judge。

### 3.4 初始数据整理

实施前先对当前运行库与执行日志生成可校验归档，再重建干净运行库。恢复项仅限：

- 管理员；
- 当前本地 Worker 与其凭据；
- 全局阶段策略；
- 已经完成的永久 Bootstrap Seal。

演示和验收期间产生的项目组、任务、Attempt、Epic、Artifact、Review、配置版本和事件不恢复到新运行库。破坏性切换前必须先生成归档清单、摘要和校验值，并在切换后验证保留项与应清空计数。

## 4. 下载器架构

### 4.1 组件

- **FastAPI 应用**：提供本地页面、健康检查和下载入口。
- **原生 HTML/CSS/JavaScript**：只实现文本输入、提交、等待状态和错误提示，不引入前端框架。
- **输入解析器**：从完整分享文字或原始 URL 中提取恰好一个 HTTP(S) 链接，并校验抖音域名白名单。
- **Douyin 下载适配器**：通过 `yt-dlp` Python API 请求可获取的最佳 MP4 格式。
- **临时文件管理器**：每个请求使用独立临时目录，响应完成、客户端断开或下载失败后清理。

### 4.2 部署边界

- 只监听 `127.0.0.1`，对外预览地址不使用 `localhost`；
- 单用户、单进程、同时只执行一个下载；
- 不实现登录、数据库、任务队列、下载历史或文件持久化；
- 限制同源 POST，校验浏览器 `Origin`，防止其他网页静默触发本地下载；
- `cookies.txt` 路径通过环境变量提供，文件必须位于仓库和 worktree 之外；
- Cookie 内容不得进入聊天、提示词、数据库、Git、应用日志或测试证据。

## 5. 数据流

1. 用户打开 `http://127.0.0.1:<port>`，粘贴分享文字或 URL。
2. 服务解析输入，要求恰好一个 URL，并验证协议与域名。
3. 服务检查当前无其他下载、Cookie 文件可读且处于允许路径。
4. 在每请求临时目录中运行 `yt-dlp`，仅接受 MP4 输出。
5. 将文件名整理为“脱敏标题 + 视频 ID + `.mp4`”，以附件响应传输。
6. 响应结束或失败时释放并发槽位，删除临时目录。

## 6. 错误处理

用户可见错误必须是简短中文说明，日志只记录脱敏的错误类型和请求关联 ID。

| 场景 | 处理 |
|---|---|
| 未找到链接或找到多个链接 | 拒绝请求，提示仅粘贴一条分享内容 |
| 非 HTTP(S) 或非抖音域名 | 拒绝请求，不调用下载器 |
| Cookie 未配置、不可读或已失效 | 返回可操作提示，不输出 Cookie 内容 |
| 视频私密、已删除或受地区限制 | 返回统一的不可用错误，不尝试绕过 |
| 网络超时或提取器失败 | 结束本请求、清理临时目录，允许用户重试 |
| 已有下载在运行 | 返回 `409 Busy`，不建立队列 |

## 7. 测试策略

### 7.1 平台增强

- API 契约和真实 PostgreSQL 集成测试覆盖项目登记、WorkItem 详情、阶段输出、搜索、关联历史和认领快照。
- 安全测试验证日志路径不能越界，界面不能返回未脱敏秘密。
- Vitest 覆盖项目登记、WorkItem 详情、阶段输出、日志和搜索状态。
- Playwright 覆盖“登记项目→创建任务→查看阶段记录→查看日志→搜索历史”主路径。
- 数据整理脚本必须支持预演报告，并验证归档校验值、新库应保留记录和应为零的业务记录。
- Worker 提示词测试逐项验证冻结的 Brainstorm/Spec/Plan 内容和关联任务摘要已注入。

### 7.2 下载器

- 单元测试覆盖 URL 提取、单链接限制、域名白名单、文件名整理、Cookie 路径校验、并发槽位和临时目录清理。
- 集成测试使用可注入的假 `yt-dlp` 适配器，默认测试不访问抖音网络。
- Playwright 覆盖本地页面成功提交、无效输入、不支持域名、缺少 Cookie 和服务忙状态。
- 真实冒烟测试使用仓库外 `cookies.txt` 与公开抖音测试链接，但不进入默认 CI，以免 Cookie 失效或站点风控导致正常构建失败。

## 8. 验收标准

### 8.1 平台闭环

- 页面可登记 `goto-software` 项目组和本地 `douyin-video-download` Git 仓库。
- WorkItem 详情可查看本次 Brainstorm 对话、Spec、Plan、完整脱敏日志、结果摘要、测试、提交和审核。
- 可通过标题、阶段内容、摘要、改动文件或提交搜索到本任务。
- 创建后续 Bug 或迭代任务时可关联本 WorkItem，Worker 实际提示词包含本任务摘要和冻结阶段内容。

### 8.2 下载器闭环

- 访问 `http://127.0.0.1:<port>` 可看到简洁可用的下载页面。
- 粘贴完整分享文字或单个抖音链接后，可获得 MP4 附件。
- 同一输入中零个或多个 URL、非抖音域名、无效 Cookie 和并发请求都得到明确错误。
- 下载成功、失败与客户端断开后均无遗留视频临时文件。
- 应用日志、Codex 日志、测试证据和 Git 均不包含 Cookie 内容。
- 真实公开链接冒烟测试成功，并明确记录执行时间和脱敏结果。

## 9. 明确不做

第一版不实现：

- 抖音登录或官方 Access Token 接入；
- 私密、登录后或地区受限内容的绕过；
- 去水印、转码、剪辑或修改视频内容；
- 批量下载、播放列表、下载队列或多并发；
- 下载历史、视频库、用户系统、权限系统或外网部署；
- 向量检索、Embedding、日志平台、LLM Judge 或新的通用工作流引擎；
- 为其他站点提供通用视频下载接口。

## 10. 设计决策摘要

- 选择 FastAPI + 原生页面 + `yt-dlp`，因为这是目前最少组件且能形成真实端到端价值的方案。
- 选择外部匿名 Cookie 文件，因为当前 `yt-dlp` 对抖音提取需要新鲜 Cookie，而官方 Access Token 不是任意公开视频文件下载凭据。
- 选择单并发且不排队，因为当前只有本机单用户。
- 选择普通文本搜索和显式关联历史，因为当前任务规模不支持向量库或语义搜索的成本。
- 平台增强不新增 Brainstorm 调度器、日志系统或新工作流框架，只补齐已有数据模型和执行链中的可见性与上下文缺口。

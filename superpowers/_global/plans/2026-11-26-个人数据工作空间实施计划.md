# 个人数据工作空间实施计划

目标是让用户上传一次 Excel，确认变量类型及类别顺序后，在所有统计方法中选择同一个数据集。
数据集保存在任务共享根独立目录下，以账号为边界。管理器校验文件、保存草稿和策略，并通过现有 Rserve 调用作者的两个固定入口。统计运行仍复制独立工作簿快照。

## 实施步骤

- [x] 在 `goto/system` 增加数据集接口、存储、Excel 校验和管理策略。默认保留 7 天、总容量 100 MB、单文件 20 MB、最多 10 个数据集。以账号锁串行结算字节和数量，用暂存目录发布成品。拒绝非 OOXML、活动内容和超规格文件。Java 用例覆盖跨账号、并发配额和到期。
- [x] 在 `goto/system` 的数据集服务接入 R 准备和确认。只传递固定函数名和参数值，工作目录由后端分配。将就绪工作簿接入 `StatisticsWorkbookService`，依靠原有运行快照的读取逻辑提交所有统计方法。
- [x] 在 `goto-web/src/views/goto/datasets` 实现数据集列表、导入确认和管理配置。统计主页增加入口，统计工作台增加已就绪数据集选择。按保存的变量类别推荐角色并允许用户调整。保留原上传及逐变量假设表路径。
- [x] 运行 Maven 和前端构建，执行真实数据集导入和结果下载的 Playwright 场景。用同一工作簿先做描述性统计，再做两样本检验，核对下载内容。
- [x] 扩展真实浏览器用例覆盖其余 9 个统计方法，复用统计回归脚本检查直接上传 Excel。

## 真实浏览器用例

从本次前端 worktree 运行 `node tests/e2e/datasets.playwright.cjs`。与既有统计回归使用相同的 `STATISTICS_BASE_URL`、`STATISTICS_SYSTEM_URL`、`STATISTICS_LOGIN_CODE`、`STATISTICS_PLAYWRIGHT_MODULE` 和 `STATISTICS_CHROMIUM_EXECUTABLE`。用例生成工作簿并保留结果到本次临时目录，验证选表、缺失值、重复行、手动类别排序、两次任务提交和实际工作簿下载。

运行 `node tests/e2e/datasetsMethods.playwright.cjs` 验证其余方法。为独立 MySQL 准备本次用到的已发布模板和测试账号，使用独立 Redis 与 Java、Rserve 共同可见的任务目录。通过 `STATISTICS_SUPERVISED_REFERENCE_DIR` 指定现有监督模型固定工作簿目录。用例校验自动识别的有序类别，并从浏览器下载统计及模型验证工作簿。

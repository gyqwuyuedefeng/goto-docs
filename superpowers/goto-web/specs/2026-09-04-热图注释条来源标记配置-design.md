# 热图注释条来源标记配置设计

## 背景与目标

热图当前使用三个文件配置：

- `dataset`（索引 0，数据集）包含 `x_column`、`y_column` 等标记；
- `col_anno`（索引 1，列属性）包含 `x_column2` 等标记；
- `row_anno`（索引 2，行属性）包含 `y_column2` 等标记。

现有 `heatmapModify.js` 仍按旧结构将行、列注释条分别写死到文件索引 0、1，并使用旧标记名 `anno`、`anno1`。数据库中现有热图模板因此把 `rowAnnoParams` 的分类项记录为 `byFileSettingIndex=0`，而 `colAnnoParams` 记录为 `byFileSettingIndex=1`。这与当前三文件结构不一致：行注释条应来自 `row_anno/y_column2`，列注释条应来自 `col_anno/x_column2`。

本次目标是把注释条来源改为与 `moduleType=7` 的 BY 标记列相同的可配置机制，并保证：

1. PlotGroup 和 PlotType 都能保存该配置；
2. 从 PlotGroup 同步到全部历史 PlotType 时，该配置能够同步生效；
3. 历史数据尚未显式配置时，自动按当前三文件语义选择正确来源；
4. 行、列注释条的内容刷新与 tab 显隐相互独立。

## 已确认的参数与字典

行注释条涉及：

- `rowAnnoParams`：颜色映射，`moduleType=22`；
- `rowAnnoPos`：位置，字典 12；
- `rowAnnoWidth`：注释条宽度占比；
- `rowAnnoTitle`：标题字体。

列注释条涉及：

- `colAnnoParams`：颜色映射，`moduleType=22`；
- `colAnnoPos`：位置，字典 13；
- `colAnnoHeight`：列注释条高度占比；
- `colAnnoTitle`：标题字体。

嵌套分类与字体还使用图例位置、图例方向、字体粗细、水平对齐和垂直对齐字典。现有字典数据完整，本次不新增或修改数据字典。

## 方案选择

采用集合级配置方案：在 `ClassifyParamList`（`moduleType=22`）上增加 `byFileMarkColumnList`，用于声明动态分类集合的来源标记列。

没有采用“读取第一个嵌套 `moduleType=7` 子项配置”的方案，因为注释分类子项会在文件上传或标记变化时整体重建，子项数量也会变化，把来源配置放在动态子项中会导致配置丢失或语义不稳定。

没有新增热图专属参数实体，因为现有 `FileMarkColumn` 和 `MarkColumnSelector` 已能完整表达文件索引与标记字段，复用现有模型即可形成闭环。

## 数据模型与管理端

在后端 `ClassifyParamList` 增加：

```text
byFileMarkColumnList: List<FileMarkColumn>
```

该字段使用现有 `FileMarkColumn` 结构：

```json
{
  "fileSettingIndex": 2,
  "filedName": "y_column2"
}
```

字段名沿用现有拼写 `filedName`，避免引入不兼容的数据格式。

在管理端 `paramSettings.vue` 的 `moduleType=22` 配置区复用现有 `MarkColumnSelector`，显示“分类集合来源标记列选择”。管理员可在 PlotGroup 或 PlotType 上选择任意文件标记列。热图的目标配置为：

- `rowAnnoParams.byFileMarkColumnList = [{ fileSettingIndex: 2, filedName: "y_column2" }]`；
- `colAnnoParams.byFileMarkColumnList = [{ fileSettingIndex: 1, filedName: "x_column2" }]`。

动态生成的内部 `moduleType=7` 分类参数继承集合级来源配置，使现有分类重置、BY 定位和颜色保留逻辑继续使用统一的数据来源。

## PlotGroup 到 PlotType 的同步

现有 `ParamSyncUtil` 只对 `ClassifyParam` 强制同步 `byFileMarkColumnList`，没有处理 `ClassifyParamList`。本次增加 `ClassifyParamList` 的同步分支，将集合级 `byFileMarkColumnList` 从 PlotGroup 配置复制到目标 PlotType。

同步行为如下：

1. 管理员在 PlotGroup 设置行、列注释来源；
2. 执行现有“同步到全部 PlotType”操作；
3. 所有 UUID 匹配的历史 PlotType 获得相同集合级来源配置；
4. PlotType 后续运行以显式配置为准。

本次不新增同步入口，也不改变现有同步范围与权限模型。

## 运行时来源解析

为行、列注释集合提供统一来源解析函数，优先级为：

1. `moduleType=22` 上存在非空 `byFileMarkColumnList` 时，严格使用显式配置；
2. 字段缺失或为 `null` 时，按当前三文件语义使用默认值：
   - `rowAnnoParams` → `row_anno/y_column2`；
   - `colAnnoParams` → `col_anno/x_column2`；
3. 当前三文件标记不存在时，为更早的两文件历史结构回退到：
   - `rowAnnoParams` → `anno`；
   - `colAnnoParams` → `anno1`。

显式空数组表示管理员有意不配置来源，不触发语义默认值。这样既能兼容未迁移历史数据，也允许管理端明确关闭自动来源。

默认解析同时校验文件名称和标记字段，避免仅凭数组位置绑定错误文件。显式配置仍以配置中的文件索引和字段名共同定位；无效配置返回空结果，不偷偷切换到其他数据源。

## 生命周期与显示行为

文件上传、删除、内容保存和标记保存不再通过固定索引判断行侧或列侧，而是判断本次文件是否被对应注释集合的来源配置引用。

- 行来源变化时，只重建 `rowAnnoParams`；
- 列来源变化时，只重建 `colAnnoParams`；
- 数据集行列标记变化仍刷新矩阵对称性相关设置；
- 同一个文件被两侧显式引用时，两侧都刷新。

显示规则：

- 来源能解析到有效标记列时，显示对应注释条分组及其四个参数；
- 来源不存在、文件被删除或标记被取消时，隐藏对应分组及其四个参数；
- 行、列分组分别判断，任何一侧变化不得影响另一侧；
- 首次加载也执行相同判断，避免历史保存状态短暂展示错误 tab。

需要持久化的可见性与动态分类集合继续通过现有参数更新接口保存，不增加新的接口。

## 异常与兼容处理

- 显式配置引用不存在的文件索引或标记字段时，该侧按无有效来源处理，并允许管理端现有清理入口移除无效标记；
- 缺少某个历史参数或分组时跳过该项，不阻断热图加载；
- 获取 `moduleType=7` 表单模板失败时保持当前参数，不写入半成品列表；
- 默认语义只用于配置缺失或为 `null` 的历史数据，不覆盖管理员保存的显式配置；
- 不通过数据库客户端修改任何 PlotGroup 或 PlotType 数据。

## 测试与验收

前端单元测试覆盖：

1. 三文件历史配置缺失时，行侧默认解析到索引 2 的 `y_column2`，列侧解析到索引 1 的 `x_column2`；
2. 显式配置优先于默认语义；
3. 显式空数组不会回退默认来源；
4. 索引 2 的上传、标记保存、内容保存和删除只刷新行注释；
5. 行、列分组及四个子参数独立显隐；
6. 动态 `moduleType=7` 子项继承集合级来源配置；
7. `paramSettings.vue` 为 `moduleType=22` 提供 `MarkColumnSelector` 配置入口。

后端单元测试覆盖：

1. `ClassifyParamList.byFileMarkColumnList` JSON 往返不丢失；
2. PlotGroup 参数同步到 PlotType 时，集合级配置被强制同步；
3. 未配置字段的历史 JSON 可以正常反序列化。

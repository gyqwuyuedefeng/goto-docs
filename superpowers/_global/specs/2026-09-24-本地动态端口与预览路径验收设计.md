# 本地动态端口与预览路径验收设计

## 目标与边界

修正本次本地验收环境，使前端热更新连接使用实际前端端口、图形卡片能读取已有 SVG 预览、绘图详情能读取同一业务文件；随后在 goto-software 项目规范中补充可重复检查的动态端口和资源验收要求。不读取或修改四个机密 R 包源码，不改业务接口、数据库、共享容器或默认端口上的其他服务。

## 已核实的现象

- 前端运行于 `127.0.0.1:58929`，但开发客户端连接 `localhost:8818/sockjs-node`；`vue.config.js` 将 devServer 端口固定为 8818。该连接是热更新通道，不是后端业务 WebSocket。
- WSL Java 使用 `home` 配置。`application-common-home.yml` 的 `chartRoot`、`chartExample` 和 `chartUser` 以 Windows 反斜杠拼接；预览接口按路径查找 SVG，找不到时返回 `EMPTY`，前端显示“暂无预览”。正确的本地预览目录已有 SVG 文件。
- `plot_data` 的服务端日志另有上传文件找不到和结果 HTML 找不到记录；浏览器 HTTP 400 与固定热更新端口不可直接等同。日志还记录短暂时钟回拨异常，需要在复测时按实际请求和响应分别归因。

## 方案

采用本次进程级覆盖，不改持久业务配置。重新选择并确认三个本地空闲端口，前端 devServer 的实际 HTTP、热更新 SockJS 地址和浏览器页面 origin 使用同一前端端口；`VUE_APP_BASE_API` 与 `VUE_APP_WS_API` 同时指向本次 system 端口。WSL Java 的业务路径、样例图路径和上传/结果路径使用正斜杠及已确认的同一 public-root；R 侧路径继续对应现有容器挂载。重启只针对本次可控前台会话，先 Ctrl-C，再核验端口释放后启动，不接管其他服务。

在 `goto_software_spec.md` 的本地验收摘要补充硬约束，并在 `goto-software/local-testing.md` 写明操作性判据：动态端口验收必须核查前端 HTTP、SockJS 热更新、业务 WebSocket、后端 API 的实际目的端口；页面可打开不等于图片正常；卡片须区分 `READY`、`EMPTY`、`FAILED` 与未完成加载，核对批量接口结果、SVG 文件存在性及 Java/R 映射；对 400 与连接拒绝按对应接口和服务端日志分别判断。

## 验收与失败处理

验证本次前端地址可访问且开发客户端不再访问 8818；选取至少一张现有样例 SVG，确认批量预览接口返回 `READY` 且浏览器显示图片；检查绘图详情的相关请求和文件路径，不将未找到的历史用户文件伪造为成功。真实绘图仅在完整依赖和数据已核对时执行。若本次仅能修复环境而既有记录缺文件，明确报告剩余阻断。规范文件通过差异、链接和约束一致性检查；结束验收后按全局规则关闭本次启动的三个服务并确认端口释放。

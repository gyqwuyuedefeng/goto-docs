# 用户画图页刻度间隔失焦校验设计

## 背景

`2026-06-14-scale-interval-mark-column.md` 实施计划已为刻度间隔参数增加 `scaleFileMarkColumnList`，并在公共函数中实现了基于标记列数值范围修正 `start/end/interval` 的能力。测试用户画图页面时发现，`goto-web/src/views/goto/components/form/draw/scaleIntervalParam.vue` 中的起点、终点、间隔输入没有触发预期校验，超出范围也不会被限制。

当前主要问题不是范围计算缺失，而是用户画图页的输入组件链路没有把“输入中”和“失焦校验”区分开，也没有把当前失焦字段传给公共校验逻辑。管理员模板页 `paramSettings.vue` 已有部分管理端配置逻辑，但不是本次修复重点。

## 目标

1. 在用户画图页修复刻度间隔的范围约束。
2. 输入过程中不计算、不修正，避免用户快速输入时被打断。
3. 单个输入框失焦后只校验和修正当前字段。
4. 标记列、上传文件、保存标记列等范围基础变化时继续执行整体硬校验。
5. 复用公共范围计算逻辑，避免在组件内复制业务规则。

## 非目标

1. 不重构管理员模板页 `paramSettings.vue` 的现有刻度间隔配置。
2. 不新增复杂错误提示 UI；本次以自动修正为主。
3. 不改变 `scaleFileMarkColumnList` 字段结构。
4. 不调整后端模型字段或同步注解。

## 范围规则

设关联标记列的有效数值最小值为 `min`，最大值为 `max`，跨度为 `span = max - min`。

字段约束如下：

- `start` 不能小于 `min - span`。
- `end` 不能大于 `max + span`。
- `interval` 必须大于 `0`，且不能大于 `span`。
- `start < end` 需要成立，但只有 `start` 和 `end` 都已填写时才校验。
- 如果只有 `start` 或只有 `end`，先不校验 `start < end`。

如果关联标记列无法计算有效范围，轻校验不清空用户当前输入；硬校验仍可按既有规则清空三项。

## 交互设计

### 输入中

用户在 `start/end/interval` 输入框中输入时，只更新字段值并触发现有修改保存链路，不执行范围计算和修正。

这样可以避免用户快速输入负号、小数点、多位数字时，字段值被提前修正。

### 失焦时

当前输入框失焦时触发轻校验，并传入当前字段名：

- `start` 失焦：只允许修正 `start`。
- `end` 失焦：只允许修正 `end`。
- `interval` 失焦：只允许修正 `interval`。

如果校验 `start < end` 时发现不成立，也只修正当前失焦字段：

- 当前字段是 `start`，且 `start >= end`，只修正 `start`。
- 当前字段是 `end`，且 `end <= start`，只修正 `end`。

### 范围基础变化时

以下场景继续执行硬校验：

- 用户选择或取消刻度范围标记列。
- 上传文件后重新读取列数据。
- 保存标记列后列内容或标记关系发生变化。

硬校验可以整体处理 `start/end/interval`，包括三项任一为空时清空三项、无有效范围时清空三项、三项都有值时整体修正。

## 架构设计

### `draw/scaleIntervalParam.vue`

该组件是用户画图页刻度间隔参数的实际输入界面。它应继续负责展示 `start/end/interval` 与 `keyValues`，并增加失焦事件出口。

设计要求：

- 输入事件继续调用现有 `modify`，保持保存链路不变。
- 对三个 `GInput` 增加字段级失焦事件处理。
- 失焦时向上抛出当前字段名，例如 `scale-field-blur`。

组件不直接计算标记列范围，避免把业务规则放进展示组件。

### `draw/input.vue`

画图页通用输入组件当前只暴露 `modify`。为支持失焦校验，需要为输入框补充 `blur` 事件透传。

设计要求：

- `el-input` 失焦时 `$emit('blur')`。
- 若使用 `el-input-number`，同时考虑其 `change` 或可用失焦事件，确保用户完成编辑后能触发上层字段校验。
- 不改变现有 `modify` 事件语义。

### 上层参数容器

用户画图页的参数渲染容器需要接收 `scaleIntervalParam.vue` 的字段失焦事件，并构造公共参数调用范围同步函数。

设计要求：

- 构造的 `commonParams` 必须能定位当前 `moduleType === 24` 设置对象。
- 轻校验调用：

```js
syncScaleIntervalRangeByMarkColumns(commonParams, {
  hard: false,
  targetField: 'start'
})
```

- 调用后继续触发现有修改链路，确保自动修正后的值会参与后续保存或绘图。

### `publicFunction.js`

公共函数 `syncScaleIntervalRangeByMarkColumns` 需要支持 `targetField`。

设计要求：

- `hard: true` 时保持整体校验三项的语义。
- `hard: false` 且提供 `targetField` 时，只处理目标字段。
- 轻校验不因其他字段为空而清空或修正当前字段以外的值。
- `targetField` 只允许 `start`、`end`、`interval`。
- 修正时优先使用 `vueContext.$set`，保持响应式。

公共函数还需要能处理嵌套参数结构。若当前 `moduleType === 24` 在分组的 `paramSettingsList` 中，校验逻辑也必须能找到它。可通过以下任一方式实现：

- 在 `commonParams` 中显式传入当前 `setting`，优先校验该对象。
- 或递归扫描 `topParamSettingsList` 及其嵌套 `paramSettingsList`。

推荐使用显式传入当前 `setting`，因为失焦事件天然知道当前对象，作用范围更清晰，也避免误改其他刻度间隔参数。

## 数据流

1. 用户输入 `start/end/interval`。
2. `draw/input.vue` 更新 `parent[fieldName]`，触发原有 `modify`。
3. 用户离开当前输入框。
4. `draw/input.vue` 抛出 `blur`。
5. `draw/scaleIntervalParam.vue` 抛出当前字段名。
6. 上层容器调用 `syncScaleIntervalRangeByMarkColumns`，传入 `hard: false` 和 `targetField`。
7. 公共函数计算关联标记列数值范围，只修正当前字段。
8. 上层容器触发现有修改链路，保持后续绘图和保存一致。

## 错误处理和边界情况

- 没有关联标记列：轻校验跳过。
- 关联标记列没有有效数值范围：轻校验跳过。
- 当前字段为空：轻校验跳过。
- 当前字段不是合法数字：轻校验跳过或按现有输入组件转换结果处理，不新增报错弹窗。
- `start/end` 只有一项存在：不校验 `start < end`。
- `interval <= 0`：失焦时修正为 `span`。
- `interval > span`：失焦时修正为 `span`。
- `hard: true` 不受 `targetField` 限制，继续整体修正或清空。

## 测试设计

### 单元测试：公共范围函数

补充 `tests/unit/constant/modify/scaleIntervalRange.spec.js`：

- `targetField=start` 时只修正 `start`，不动 `end/interval`。
- `targetField=end` 时只修正 `end`，不动 `start/interval`。
- `targetField=interval` 时只修正 `interval`，不动 `start/end`。
- `start/end` 都存在且关系不成立时，只修正当前目标字段。
- `start/end` 有一项为空时，不校验二者关系。
- 嵌套分组或显式 current setting 能被正确处理。

### 组件静态或浅层测试

补充或调整画图页相关测试：

- `draw/input.vue` 对 `el-input` 和数字输入暴露 `blur` 或等价完成编辑事件。
- `draw/scaleIntervalParam.vue` 的三个输入框能把字段名向上抛出。
- 上层容器监听刻度间隔字段失焦事件，并调用公共函数时传入 `hard: false` 与 `targetField`。

### 回归验证

手工验证用户画图页：

1. 选择有效数值标记列。
2. 在 `start` 快速输入超小值，输入过程中不被修正。
3. `start` 失焦后被修正到 `min - span` 或满足 `start < end` 的合法值。
4. 在 `end` 快速输入超大值，输入过程中不被修正。
5. `end` 失焦后被修正到 `max + span` 或满足 `start < end` 的合法值。
6. 在 `interval` 输入 `0`、负数或大于 `span` 的值，失焦后修正为 `span`。

## 风险和注意事项

- `el-input-number` 的 `input/change/blur` 事件行为与 `el-input` 不完全一致，需要在测试中覆盖。
- 如果上层容器当前没有暴露 `moduleType === 24` 专用事件，需要沿既有组件注册模式增加最小事件通道。
- 不应把管理员模板页的 `paramSettings.vue` 当作主要验证入口，否则会遗漏用户画图页实际路径。
- 已有 `paramSettings.vue` 中的管理端逻辑可保持现状；若后续要统一管理端体验，应单独设计。

## 验收标准

- 用户画图页输入过程中不会自动修正 `start/end/interval`。
- 当前输入框失焦后只修正当前字段。
- `start/end/interval` 分别满足计划中的范围规则。
- `start < end` 只在两项都填写后校验。
- 快速输入不会被中途修正打断。
- 上传文件、保存标记列、标记列选择变化仍执行整体硬校验。
- 新增或调整的单元测试通过。

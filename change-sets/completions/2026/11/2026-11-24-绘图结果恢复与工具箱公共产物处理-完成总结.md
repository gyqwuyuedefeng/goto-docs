# 绘图结果恢复与工具箱公共产物处理完成总结

## 结果摘要

公开模板全部纳入实测。61 个默认模板中有 60 个生成图形并下载默认 PDF，折线图 276 仍阻断上线验收。三个工具的 19 项正常链路全部通过。最终构建拦截 19 条工具成功通知后，19 项均用当前任务自己的回查响应完成真实下载。桑基图 291 在拦截成功通知后也能恢复 HTML 图形并下载 PDF。相关代码已提交到各任务分支，待验收门禁通过后集成。

## 原因与目标

上一轮真实回归发现 SVG 拼图缺少 TeX 依赖，PDF 与 SVG 转 TIFF、JPEG 出现格式或文件错误，绘图落盘完成后页面可能因漏通知无法获取结果。当前目标是复用成功登记、结果回查、连接生命周期和格式编码的共用逻辑。默认样例仍须使用发布数据完成计算、展示和下载。

## 设计决策

- 工具任务统一在产物存在、可读且非空时登记 Redis 元数据。回查复用登记结果、用户归属和已持久化的执行终态，确保释放当前线程池任务后才推进下一格式。页面等待超时后提示并降低查询频率，保留任务订阅。
- 图片转码的 TIFF 与 JPEG 共用 PNG 渲染及 Java 编码流程。JPEG 合成白底，TIFF 保持透明通道，编码保留 DPI。拼图 Java 与 R 挂载路径共用解析和文件验证，缺少的 lmodern 加到共享镜像构建配置。
- 绘图继续接收 WebSocket，并按当前记录回查严格只读的状态和结果。回查和通知复用图形渲染，处理离页、换记录和迟到进度。雪花编号在浏览器比对时使用精确字符串。
- 折线图 276 的默认参数公开调用包含线性模型、公式和 R²。使用同一发布样表和同一功能入口，只将独立测试记录的 showFitStats 从字符串 TRUE 切换为字符串 FALSE 后成功生成并下载。故障范围缩小到拟合统计标注路径，默认组合仍需有权限的 R 包维护者修复。

- 工具箱正常模式 19/19。最终构建的丢通知模式也为 19/19，每个下载的同一任务均有真实的 owner-scoped 回查成功响应。覆盖双 SVG 拼图、宽转长、长转宽和 16 个转码组合。四个 TIFF、JPEG 实际下载文件完整解码、包含非均匀像素，均为 300 DPI。

## 偏差、风险与遗留

- 阻断条件是公开模板 276 的默认拟合统计标注仍失败。恢复条件为获授权维护者修复共用标注计算，并以原样表、公式和 R² 原配置复验。关闭统计标注只用于独立对照。
- 重绘沿用记录 ID。若同一记录的极快重绘完全漏掉排队和运行状态，现有状态接口无法证明终态来自哪次执行。代码保留旧结果并等待确认。可用现有 Redis Stream 的每轮执行标识补足提交、通知和回查的匹配。
- 工具端若后台失败且同时丢失最终通知，现有就绪查询只提供成功证据，页面会保留等待并提示。重复提交同一旧 API 任务编号仍沿用原接口协议，现行工具页面为每次提交分配独立编号。
- 隔离 Maven 私服缺少部分内部 Java 依赖，首轮未获得可编译输入。核验上次发布归档和版本后，将其中同坐标 Java 依赖放入本任务临时文件仓，通过包装器继续构建。未复制共享 Maven 仓。受影响模块通过后又执行了最终全量构建。
- 一轮绘图探查中，状态接口已返回状态 4 和字符串编号，浏览器仍未请求结果内容。冷启动后的同一 Playwright 场景通过，首次未加载生效的具体原因待确认。折线对照的首个布尔类型试验未产生可用于归因的结果，按原字符串协议重试才获得有效对照。
- 前端旧基线另有四套样式或关联参数测试复现失败，当前定向套件均通过。绘图全量验证之后的增量提交只涉及工具回查的超时和执行终态判断，最终应用已重启并复验三个工具和桑基图 291。
- 因默认模板门禁未通过，未执行合并及合并结果验证。测试报告和各任务分支提交已保存，四个代码任务 worktree 保留供后续复验。

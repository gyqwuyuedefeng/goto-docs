## 字体来源、许可和差异

三个原始字体文件保持原字节，SHA-256 与控制器交接值一致，详见 `embedding-report.json`。Source Han Sans SC Regular/Bold 为 Adobe 官方 release 分支 `OTF/SimplifiedChinese/` 下载的 Version 2.005；Liberation Sans 为本机公开字体目录复制的 Version 2.1.5，三个字体 `OS/2.fsType=0`。已完整阅读本地 `fonts/SourceHanSans-LICENSE.txt` 和 `fonts/Liberation-LICENSE.txt` 的 OFL 1.1 文本，允许本次嵌入。OFL 保留主名称要求适用于下面的派生字体，未改原始字体名称。

业务 PDF 的 CFF Notice 年份为 2014–2021，但无可确认版本号。控制器已独立对比 PDF 与官方 OTF：regular 48 个映射字符、bold 3 字 advance 全相等；ascent/descent 相等；路径记录并非全部相同，存在轮廓起点、控制点及最大 1/1000 em 的边界差异。因此**不宣称官方 2.005 等于原 PDF 确切版本或逐点原字形**。

一次有限备用采用官方 `release/Variable/TTF/SourceHanSansSC-VF.ttf`，SHA-256：

`68f866374d8ff04d2103c5b2907f1cab2dbec91ac0fb6ad0b801c6db0c1faa80`

FontTools 将唯一 wght 轴分别固定为 400/700，完整保留 65,535 glyph 和 44,853 cmap 字符，不子集化，包含“编辑”。派生主名称为 **Sankey Sample CJK**，英文和中文本地化的相关 name ID 及 typographic 名称同步处理，版权与许可 name ID 0/13/14 保持；原 OFL 保留名 `Source` 未用于派生主名称。派生字体不是 PDF 的 CFF 原件，不宣称完全相同。

- `fonts/derived/SankeySampleCJK-Regular.ttf`：`73e526dd7c79231454c48602a616c771030ac07cbf6c24268b4dc1f2108b0a16`
- `fonts/derived/SankeySampleCJK-Bold.ttf`：`03a449249fcc6dda5c18218be473951da6e74e977ab704ac14cef6b5e9d5199b`

完整许可已经放在本地 `ttf-native/` 和两份 TTF Windows 材料目录。`fonts/derived/LICENSE.txt` 也保留 Source Han 原许可。PPTX 中 FontData 的原始版权/许可元数据保留；Office 自行导出的 PDF 临时名字变为数字，不能把数字 BaseFont 当作实际字体身份，需同时读取 PS 名称及字形。

## 实现依据与 TDD

公开依据：[W3C EOT 结构](https://www.w3.org/submissions/EOT/)、[MS-OE376 Font Part](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/1663dabc-5d98-463f-889e-bcd9b77c3d34)、[FontTools instancer](https://fonttools.readthedocs.io/en/latest/varLib/instancer.html)。实现采用 EOT 0x00020001、小端头、0x504C 魔数、无压缩/无 XOR、完整 FontData；PPTX 为 `application/x-fontdata` 和 font relationship。没有把裸 OTF/TTF 文件伪装成 fntdata。

`embed_fonts.py` 对许可位 restricted / preview-print / bitmap-only 拒绝输出。regular/bold 同 family 合并，启用 embedTrueTypeFonts、关闭 saveSubsetFonts。`derive_static_fonts.py` 只接受该官方单 wght 轴样例，产生两个完整静态实例；字体映射仅替换原页面 60 个 typeface token，其余字节不变。

## 字体实际使用证据

`font-evidence.json` 由 `inspect_font_evidence.py` 读取实际 Office PDF 字体流，核对 name 表、完整 glyph 集、解组件后的轮廓记录和 advance。

- Liberation TTF：PDF BaseFont 为 `+3` 或 `+1` 等，但嵌入字体 name ID 6 为 `LiberationSans`、Version 2.1.5、hhea 1854/-434、units 2048。`M/t/o/e/→` 五字的轮廓和 advance 全部匹配原 TTF，原样、保存重开及编辑后均成立。仅 TTF 对照中文仍为 MicrosoftYaHei / MicrosoftYaHei-Bold。
- CFF：PDF 没有实际 Source Han 中文字体，只有 Liberation；21 个中文文本片段被 Office 自行导出为 2×2 颜色图与 81×39 等 1-bit 软遮罩，PDF 文字不可提取。PNG 则明显衬线。PPTX 原生文字没有被本实现改成图片或轮廓；PDF 是 Office 的导出结果。内部回退原因没有确诊，不能从这一现象推导所有 Office/CFF 都不支持。
- 派生 TTF：PDF 的 `+1` 和 `+2,Bold` name ID 6 分别为 `SankeySampleCJK-Regular`、`SankeySampleCJK-Bold`，各有 65,535 glyph / 44,853 cmap。所有 56 个被检字符（源样例字符与新增“编辑”的并集）轮廓和 advance 均与派生 TTF 匹配；原样、roundtrip、edited 三个 PDF 均成立。编辑 PDF 可提取“编辑”。原样 TTF PDF 的图片 XObject 数为 0。

TTF 的完整字体随 PPTX 保留，Office 保存后三个 fntdata 均逐字节未变。因此“当前字形子集导致不能输入新字”已排除；但不能把这个事实扩展为跨输出路径外观全部正确。

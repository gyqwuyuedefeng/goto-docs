## 原因与目标

用户反馈 SVG 正确、其他格式中文乱码，而工具页 SVG 转换正常。此前已用同一实际 SVG 验证：工具页/R 环境能正常转换；限制为仅西文字体时可重现方框现象。本地 Java 主机旧 shell 调用还存在脚本执行失败却返回缺项 ZIP 的情况。

目标：消除桑基图对 Java 主机转换器/字体环境的依赖；保留用户当前 SVG、PDF 阴影兼容和 96 DPI，保证失败不会返回缺项成功 ZIP。

## 设计决策

- 仅 group15 非 SVG 调用公开接口 `gotoTools::fileConvert(input, output, dpi)`，沿用已有同步 Rserve 边界；未引入新任务协议、服务或配置。
- `PathResolver` 从 Java PUBLIC_ROOT 相对映射到 R_REMOTE PUBLIC_ROOT；路径通过 `session.set` 赋值，不拼接命令字符串，避免现有 `transformPath` 破坏路径引号转义。
- PDF 继续使用移除节点 rect 上 shadow-N 引用的临时副本、96 DPI；其他转换格式 300 DPI；SVG 原件保持不变。
- 检查连接、R 返回协议和 Java 侧非空产物；失败向外传播，清理当前随机输出目录及 PDF 临时输入，finally 关闭会话。
- 未直接检查生产 Java 主机字体配置，因此“生产缺少某个字体”仍不是已确认根因。该方案根据用户认可的环境统一方向修复，不修改生产字体设置。

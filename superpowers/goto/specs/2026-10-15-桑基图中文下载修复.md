# 桑基图中文下载修复设计

用户已确认本方案。目标是让桑基图非 SVG 下载使用工具页已验证可用的 R 转换环境，避免 Java 主机与 R 主机字体、转换器配置不一致。

## 证据与限制

同一份真实中文 SVG 在工具页和 R 容器转换正常；限制为仅西文字体后可重现方框现象。尚未直接检查生产 Java 主机的字体配置，故不能断言生产环境缺少某个字体。本机旧下载脚本还存在 CRLF/sh 执行失败并生成缺少 PDF/PNG 的 ZIP 的问题。

## 已确认行为

- 仅 group 15 的非 SVG 下载调用既有 Rserve 中的 `gotoTools::fileConvert(input, output, dpi)`；不新增异步消息或服务。
- 当前页面同步的 SVG 仍作为唯一输入，SVG 下载保持原字节和拖动后的布局。
- PDF 保留仅移除节点矩形 shadow-N 属性的临时输入，96 DPI；其他非 SVG 格式 300 DPI。
- Java/R 路径由 `PathResolver` 的 PUBLIC_ROOT 两侧映射，不硬编码机器路径。路径字符串安全引用后再进入 R 命令。
- 转换失败或没有非空输出时，本次桑基图下载明确失败，不返回缺少所选格式的成功 ZIP；临时 PDF 输入和 R 连接均须释放。
- 网络图 group 14 的 shell 转换和其他静态图的 GGSAVE 均不变。

## 验收与停止条件

回归测试覆盖 R 调用、路径映射、DPI、原始 SVG、PDF 临时文件、失败与连接释放，保留网络图回归。真实本地服务下载 ZIP 必须包含所选 SVG/PDF/PNG，中文显示正确，PDF 无异常文字缩放。完成编译测试、启动、关闭与测试数据清理后停止；不自动合并、推送或部署。

## 明确排除

不读取或修改四个机密 R 包源码，不修改模板/生产字体配置，不改网络图转换方式，不处理工具页本地下载链接等旁支问题。

# 通用任务 R 失败终态与完成事件修复 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:hybrid-subagent-driven-development` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 修复通用任务后台执行链路中 R 返回失败仍被标记为 `SUCCEEDED`、完成事件重复触发、正常完成清理误中断线程导致 Redis 通知/ACK 失败的问题。

**Architecture:** 以 `StageRunnable` 作为唯一完成事件出口，让 `CommonTaskRunnable` 把真实 `CheckResultMsg`/异常写入父类字段；完成处理器同时读取 `error` 和 `result` 判断终态；线程池区分“正常完成清理”和“外部取消”，正常完成不再调用 `future.cancel(true)`；通知发布为完成处理器提供可抛异常版本，保证通知失败时不继续 ACK。

**Tech Stack:** Java 17, Spring Boot, JPA/Hibernate, Redis Stream/Redisson, Rserve, JUnit 5, Mockito.

## Current Failure Chain

最新测试日志显示 R 已经正确返回失败：

```text
{"status":"fail","msg":"运行时依赖缺失，无法继续执行。缺失项：系统工具 - Pandoc、系统工具 - pdfLaTeX (texlive-xetex)","data":null}
```

但 Java 完成链路随后执行：

```text
UPDATE StreamJobExecution SET status='SUCCEEDED' ...
JobLeaseService - 任务标记成功：jobId=6
TaskEventPublisher - 通用任务通知发布失败：java.lang.InterruptedException
CommonTaskRedisCompletionHandler - 完成处理器执行异常：java.lang.InterruptedException
未找到完成上下文，可能已被处理或注册键不匹配
```

定位到的代码原因：

- `CommonTaskRunnable.execute()` 调用 `stage.execute()` 但不保存返回的 `CheckResultMsg(false)`。
- `CommonTaskRunnable` 自己声明了 `executionError`，遮蔽了父类 `StageRunnable.executionError`，父类完成事件读不到子类字段。
- `StageRunnable.doFinally()` 已触发完成事件，`CommonTaskRunnable.run()` 的 `finally` 又手动触发一次完成事件。
- `StageRunnable.doFinally()` 调 `ThreadPool.remove(data)`，`remove()` 对未 done 的当前 future 调 `future.cancel(true)`，正常完成线程被置中断，随后 Redisson 同步发送/ACK 抛 `InterruptedException`。
- `CommonTaskRedisCompletionHandler` 只看 `event.error`，不看 `event.result`。

# goto-web 基线单元测试修复设计

## 背景

`goto-web` 完整前端单元测试当前有 4 个失败套件、4 个失败用例。调查确认其中三个失败来自源码演进后仍锁定旧选择器、旧标签形式或引号格式的源码字符串断言；另一个失败来自已经提交测试、但从未提交实现和菜单接入的绘图组可见性过滤功能。

本次修复只恢复这些测试所保护的既定行为，不修改后端接口，也不回退当前绘图侧栏网格布局、权限规则或其他页面行为。

## 目标

- 完整单元测试恢复全绿。
- 保留 `PlotSidePanel` 当前自适应网格布局，并让回归测试验证当前完整宽度链。
- 图片转换页的铅笔图标测试兼容 Vue 模板的自闭合和成对标签写法。
- 管理入口权限测试不依赖 JavaScript 字符串使用单引号还是双引号。
- 分类图例的纵向列表布局只作用于 `.list-param`，不错误地覆盖整个 `.form-group`。
- 绘图菜单隐藏 `show === 0` 的分组，同时兼容缺少 `show` 字段的历史响应。

## 方案

### 稳定源码回归断言

`drawRegressionFixes.spec.js` 改为检查 `PlotSidePanel` 当前的 `.plot-upload-item`、直接子 `.container`、上传容器和 uploader 完整宽度链，不要求旧 `.file-settings` flex 实现。图片图标断言改为接受 `<i ... />` 或 `<i ...></i>`，继续验证图标和主题样式本身。

`navigation.spec.js` 使用允许单引号或双引号的正则验证两项角色权限，不改变生产权限表达式。

### 恢复分类图例布局作用域

将 `classifyLegendParam.vue` 中误写为 `.form-group` 的纵向 flex 规则恢复为 `.list-param`。现有测试已经准确描述目标行为并作为失败测试，无需降低断言强度。

### 补齐绘图组可见性过滤

新增 `plotMenu/plotGroupVisibility.js`，导出纯函数 `filterVisiblePlotGroups(groupList)`：

- 非数组输入返回空数组，避免菜单加载链路中断。
- 只过滤 `show === 0` 的条目。
- `show` 为 `1` 或缺失时保留，以兼容旧接口响应。
- 不修改输入数组。

`PlotMenu.vue` 在接口成功后、调用 `buildPlotMenuList` 前应用该过滤器。纯函数测试覆盖过滤和兼容行为；菜单接入测试验证组件实际导入并调用过滤器，防止只补模块而未接入运行链路。

## 数据流

`groupNameList` 响应先进入 `filterVisiblePlotGroups`，过滤结果保存到 `groupList`，再交给现有 `buildPlotMenuList` 异步加载图标并生成菜单项。后续激活菜单和向父组件发送 `menu-loaded` 的流程保持不变。

## 错误处理与兼容性

过滤器处理非数组输入，不抛出额外异常。图标加载失败仍由 `buildPlotMenuList` 的原有兜底逻辑处理。没有新增网络请求、后端字段或持久化格式。

## 测试

1. 以当前 4 个失败套件作为 RED 基线。
2. 先修正测试断言和新增菜单接入断言，确认新增接入断言按预期失败。
3. 最小实现分类图例选择器修复、过滤纯函数及 `PlotMenu` 接入。
4. 运行 4 个原失败套件和菜单构建相关测试。
5. 对改动的 JS/Vue 文件执行 ESLint，并运行完整前端单元测试。

## 非目标

- 不重构所有源码字符串型测试为组件挂载测试。
- 不改变 `PlotSidePanel` 的 accordion 或网格行为。
- 不调整管理入口权限集合。
- 不修改后端 `group_name_list` 返回结构。

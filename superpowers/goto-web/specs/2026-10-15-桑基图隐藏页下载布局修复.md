# 桑基图隐藏页下载布局修复

## 需求与已证实原因

用户在得到“保存最后一次可见布局，不导出隐藏 iframe 的零尺寸重排结果”的建议后，明确要求正式修复。
本地真实 16 节点、27 边用例中，切到边数据页将 iframe 变为 0×0，节点三列坐标从约 57/274/491 变为 0/55/110；后者全部 16 个节点坐标与用户 ZIP SVG 完全一致。上传 SVG 和下载 ZIP 中 SVG 字节一致，问题先于非 SVG 格式转换发生。

## 方案比较与决定

1. 采用：组件在结果可见时按需捕获当前 SVG，在离开结果页的 DOM 隐藏之前保存最后有效快照；隐藏或零尺寸时下载只取该快照。可保留真实拖动布局，不更改当前文件页签。
2. 未采用：下载时强制切回结果页再等待重排。隐藏后的重排可能已丢失拖动位置，不能保证导出原可见布局。
3. 未采用：只调整 width/viewBox/DPI。异常 SVG 的节点坐标已改变，放大画布无法恢复布局。

## 明确行为与边界

- 仅桑基图 group15 的 HTML iframe 导出增加有效布局保护，网络图、静态图及后端 R 转换不变。
- 结果可见且 iframe/图形有效时，下载读取当下 SVG，不能复用拖动前快照；切换边/节点数据页之前保留当前结果。
- 隐藏状态、零宽/高、空 SVG 不得覆盖已有有效快照；无有效快照则返回空，让现有下载入口明确报错，不上传空/窄文件，也不退回过期服务端 SVG。
- 开始新绘图、切换绘图/模板、HTML 或结果来源变化时清除旧快照；不得跨记录、跨结果复用。
- 不重构结果组件，不引入全局缓存、持久化缓存、MutationObserver 或新依赖。
- JPEG/TIFF 实际为 PNG、共享模板样例列不匹配属于独立事项，本次不修改。

## 验收与停止条件

先有能在旧实现失败的单元与浏览器用例；修复后覆盖可见下载、拖动后切边/节点页连续下载、无快照与快照失效、网络图回归。真实下载 SVG/PDF/PNG 中的 SVG 必须与隐藏前的有效快照字节一致，节点坐标/拖动位置及标题边界不被改变；PDF/PNG 中文与布局正常。前端受影响测试、生产构建通过，并运行全量测试确认无本次新增失败，临时登录页恢复、服务与测试记录清理后停止。不自动合并、推送或部署。

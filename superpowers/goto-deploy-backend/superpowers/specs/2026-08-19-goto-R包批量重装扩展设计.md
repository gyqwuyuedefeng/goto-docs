# GOTO R 包批量重装扩展设计

## 背景

现有 `goto-deploy-backend/.bash/reinstall_gotoBase_gotoTools.sh` 负责重装
`gotoBase` 和 `gotoTools`。新下载的 `gotoStat` 是正式 R 包，其
`DESCRIPTION` 明确依赖 `gotoBase` 与 `gotoTools`。当前批量入口名称只描述
两个包，且容器启动脚本尚未把 `gotoStat` 源码挂载到容器。

用户确认继续采用“单包脚本独立维护、一个入口统一编排”的结构。新增包时，
为该包补充安装与移除脚本，再把对应步骤加入入口；当前不建设自动发现或插件式
包管理框架。

## 目标

- 为 `gotoStat` 新增独立安装和幂等移除脚本。
- 保持 `gotoBase`、`gotoTools`、`gotoStat` 共六个单包脚本可单独维护和执行。
- 将批量入口改为通用名称 `reinstall_goto_r_packages.sh`，并只保留这一份批量入口。
- 批量入口在任何移除前完成六个脚本、容器、R 环境和三个源码包的预检。
- 按依赖关系反向移除、正向安装，并在新的 R 进程中验证三个包。
- 为 WSL R 容器增加 `gotoStat` 源码挂载。

## 非目标

- 不修改三个 R 包的业务代码、`DESCRIPTION` 或 `NAMESPACE`。
- 不安装或升级 `DESCRIPTION` 中声明的第三方依赖。
- 不执行 Roxygen 文档生成。
- 本次不重建或重启当前容器，不实际卸载或安装容器内的 R 包。
- 不实现旧版本快照和自动回滚。
- 不建设配置驱动、自动扫描目录或通用插件式安装框架。

## 依赖与执行顺序

依赖关系为：

```text
gotoStat -> gotoTools -> gotoBase
```

因此固定顺序为：

```text
移除：gotoStat -> gotoTools -> gotoBase
安装：gotoBase -> gotoTools -> gotoStat
验证：gotoBase -> gotoTools -> gotoStat
```

任一步真实失败时，批量入口立即停止并传递非零退出码，不继续执行后续步骤。

## 文件结构

实现仓库为 `/mnt/f/IdeaProjects/goto-software/goto-deploy-backend`。

| 文件 | 操作 | 职责 |
| --- | --- | --- |
| `.bash/install_gotoBase.sh` | 保留 | 安装 `gotoBase` |
| `.bash/remove_gotoBase.sh` | 保留 | 幂等移除 `gotoBase` |
| `.bash/install_gotoTools.sh` | 保留 | 安装 `gotoTools` |
| `.bash/remove_gotoTools.sh` | 保留 | 幂等移除 `gotoTools` |

| `.bash/remove_gotoStat.sh` | 新增 | 幂等移除 `gotoStat` |

| `.bash/reinstall_gotoBase_gotoTools.sh` | 删除 | 旧名称不再保留，确保只有一个批量入口 |

## 单包脚本契约

`install_gotoStat.sh` 使用 Rscript shebang，只从固定容器路径
`/root/software/gotoStat` 安装 `gotoStat`。安装前校验 `DESCRIPTION` 存在且
`Package` 字段为 `gotoStat`，然后调用：

```r
remotes::install_local(
  path = "/root/software/gotoStat",
  force = TRUE,
  upgrade = "never",
  dependencies = FALSE
)
```

脚本不负责移除旧包、不生成文档、不修改或安装依赖。批量入口保证它只在
`gotoBase` 和 `gotoTools` 安装成功后运行。

`remove_gotoStat.sh` 与现有移除脚本保持相同的幂等语义：遍历 `.libPaths()`，
包未安装时成功跳过；已安装时移除所有发现的副本，并验证没有残留。

## 批量入口接口

默认调用方式：

```bash
./reinstall_goto_r_packages.sh
```

允许通过唯一的位置参数覆盖容器名：

```bash
./reinstall_goto_r_packages.sh other_container
```

默认容器仍为 `goto_rbase_wsl`。入口通过自身目录定位六个单包脚本，不依赖
调用者当前目录，不使用 `eval`，也不拼接待解释的 Docker 命令字符串。

## 预检

首次移除前必须一次性确认：

1. 宿主机存在 `docker` 命令。
2. 六个单包脚本存在并可读。
3. 目标容器存在且正在运行。
4. 容器内存在 `Rscript` 和 `remotes`。
5. `/root/software/gotoBase/DESCRIPTION` 的包名为 `gotoBase`。
6. `/root/software/gotoTools/DESCRIPTION` 的包名为 `gotoTools`。
7. `/root/software/gotoStat/DESCRIPTION` 的包名为 `gotoStat`。

任何预检失败都必须发生在移除之前，并输出明确的中文错误信息。

## 容器挂载

`wsl_rbase_start.sh` 增加本地路径：

```text
/mnt/f/IdeaProjects/goto-software/gotoStat
```

以及容器挂载：

```text
/mnt/f/IdeaProjects/goto-software/gotoStat:/root/software/gotoStat
```

该修改只对以后由启动脚本重新创建的容器生效。本次不自动重建当前正在运行的
`goto_rbase_wsl`；当前容器仍缺少该挂载，因此本次不执行真实三包重装。

## 错误处理

- 批量入口继续使用 `set -Eeuo pipefail`。
- 每一步开始和成功时输出包名及动作。
- 单包脚本或最终验证返回非零时，入口立即停止并标明失败步骤。
- 包原本未安装是移除脚本的成功状态。
- 不自动回滚；当前没有可靠的旧包制品快照。
- 预检确保源码或挂载缺失不会在旧包已经移除后才被发现。

## 测试与验收

实施遵循测试先行：先扩展测试，使其因 `gotoStat` 脚本和通用入口缺失而按预期
失败，再编写最小实现使测试通过。

至少验证：

1. 六个单包脚本的 shebang、包名、固定路径、安装参数和幂等移除契约。
2. 通用入口默认容器、容器名覆盖、参数数量校验和预检失败行为。
3. 完整步骤严格为预检、移除 `gotoStat`、移除 `gotoTools`、移除 `gotoBase`、
   安装 `gotoBase`、安装 `gotoTools`、安装 `gotoStat`、最终验证。
4. 任一安装步骤失败后不再执行后续步骤。
5. 最终验证包含三个包的 `requireNamespace()` 与 `packageVersion()`。
6. `wsl_rbase_start.sh` 包含 `gotoStat` 本地路径检查和 Docker bind mount。
7. 批量入口和容器启动脚本通过 `bash -n`；六个 Rscript 能被 R 解析。
8. `git diff --check` 无格式错误。

验收完成不代表已在当前容器中安装三个包。真实安装需先明确授权重建容器或采用
其他受控方式让当前容器获得 `gotoStat` 挂载，再单独执行通用入口。

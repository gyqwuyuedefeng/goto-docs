# 原始 SVG 封面缓存设计

用户已确认只保留原始 SVG，不生成缩略图，并要求继续实施已讨论方案。

## 目标与范围

画图分类页刷新时复用未变化的原图，超过 20 张时继续加载，单张失败不阻塞其他封面。分类、模板修改后，下次刷新使用最新资料和权限。保持原始 SVG 字节及旧批量 POST 接口兼容；不读取或修改四个机密 R 包，不新增 CDN、Redis 图片缓存或持久化 Blob 协议。

## 接口与缓存

新增 `GET /api/plot/group_preview/{groupId}/{typeId}`，沿用 `plot:group_list` 权限。服务器只根据已验证的 ID 定位文件，不接受客户端路径；先核对登录、权限、显隐和所属关系，再检查条件请求。

成功返回原始 SVG，使用 `Cache-Control: private, no-cache`、内容摘要 ETag、`Vary: Authorization`。摘要由本次读取的原始字节计算，200 响应复用同一份字节。未变化返回 304；合法可见但无预览返回 204；不存在或隐藏对象返回 404；登录或权限失败为 401/403；IO 故障为 5xx。非成功图片响应使用 no-store。浏览器自动处理条件缓存，前端不自行维护 If-None-Match、ETag 或跨刷新的 Blob 存储。

SVG 传输启用 gzip，解压结果仍为原始文件；弱 ETag 可基于原始内容摘要以兼容编码变化，`Vary` 必须合并保留 Origin、Authorization、Accept-Encoding。只调整封面成功响应的缓存策略，不关闭全局安全缓存头。

## 前端

通过现有 Axios 登录头请求 SVG，适配现有图片 Blob 包装与 401/403 错误处理。使用临时 ObjectURL 展示，离开页面时释放并取消在途请求。保留 IntersectionObserver 的 240px 预加载范围；队列去重、最多 4 个在途请求，每项结束后持续排空。

单次超时 15000ms，仅网络错误、超时或暂时性 5xx 自动重试一次；404、无预览和鉴权失败不自动重试。失败卡片提供手工重试且阻止点击冒泡。鉴权失败停止队列并复用登录失效处理，取消请求不弹错误。每张成功立即显示，页面不再依赖批量 Base64。

## 后端资料与文件读取

复用当前 Redis 分类模板快照，只定位目标项，不重复筛选和深复制全部可见模板；从已找到分组取得目录，不再每图额外 readAllMap。现有缓存结构不能提供完整的按 ID 元数据索引，本期先沿用一次快照读取，真实验收记录其开销，不预建额外索引层。

分类/模板新增、编辑、删除，涉及显隐、目录或文件名时，在事务提交后刷新首页资料缓存；失败必须可诊断，不伪装刷新成功。快照先完整构造再原子替换，不使用 clear 后逐条填充让读取方看到空列表或半份 Map。只更新相关资料缓存，不全量重建字典或表单。

本期不加服务器 SVG 字节长期缓存：内容摘要每次重新计算以可靠识别同大小、同修改时间的替换。304 省去图片传输及 Base64 转换，但仍有文件读取和摘要计算成本。首次加载仍有 SVG 传输和渲染成本，不承诺固定速度提升。

## 用户确认追加：故障恢复自动保障

2026-10-03 用户明确选择“增加自动保障”，接受必要校验开销。审查确认：Redis 刷新与精准失效同时失败后，恢复连接的非空旧快照不能继续作为封面读取授权；仅记录人工重建不足以满足此需求。旧批量 POST 也必须同步防护，否则它会成为读取隐藏原图的绕过入口。

最小方案是实时数据库投影校验，不增加 Redis 故障标记、跨实例失效协议、outbox 或重连状态机。GET 和 POST 都保留一次既有关联 List 读取，仅用于现有首页收录资格和 ID 定位；当次显隐、真实所属关系、目录和文件名以当前数据库为准。Repository 增加按 typeId 范围的 group/type 非实体 join 投影，只读取命中记录的双方 show/folderName、实际 groupId、类型 paramSettings；GET 一项一次查询，POST 至多20项一次批量查询。只读 REQUIRES_NEW 避免复用调用方旧事务上下文，并用真实 JPA 验证投影转换，不返回受管实体。

小型投影只承载这次查询的必要属性，不是新实体/持久状态；复用既有递归文件名解析和安全原字节读取，不复制解析规则、不加载组参数或全量模板。实时 show 校验更简单，但不能识别文件名/目录/参数被清空，故选必要元数据投影。TTL 不能立即阻止隐藏图片；单实例故障标记不能保护其他实例；自动恢复协议则增加当前并不需要的状态协调。

任何数据库查询故障均失败关闭：GET 500 no-store，旧POST条目 failed，不回退旧图片；当前不存在、隐藏或不再收录为 GET 404/POST failed；当前可见文件不存在仍 GET 204/POST empty。保留管理员可看隐藏语义、原显隐取值解释、旧POST响应字段/顺序/cardKey/Base64前缀。当前权限/元数据验证完成后才允许200/304。

验收标准：缓存故意保留旧可见项时，真实数据库隐藏/删除/改所属后 GET 不得200/304且 POST 不得ready；改目录/文件名使用新路径，清空参数拒绝；数据库故障不沿用旧图；旧受管实体不影响实时投影；每批只查询一次，原字节、缓存语义、旧格式及管理员兼容仍通过。代价是 GET 每图新增一次主键范围数据库查询和该模板参数解析；分类卡片列表本身仍可能短暂陈旧，但两个预览入口不再据旧资料返回图片。

## 验收

覆盖 25 张以上持续加载、并发上限、去重、超时/重试、取消和资源释放；验证原始字节一致、200 后条件请求 304、原图变化重新 200、无预览和权限变化。使用真实本地 system/home 与前端动态端口，按项目规则控制登录页替换并恢复，浏览器缓存开启进行两次正常刷新；强制刷新或禁用缓存不作为缓存命中验收。

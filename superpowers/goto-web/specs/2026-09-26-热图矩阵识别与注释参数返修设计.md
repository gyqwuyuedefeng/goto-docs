# 热图矩阵识别与注释参数返修设计

## 当前事实与目标

热图组为 13；现存模板 1、286、167、168、171、247、169 共用数据集的 `x_column`、`y_column`、`value`、`value2` 标记。当前模板已将分组命名为“单元格设置（主值）”“单元格设置（次值）”，视觉属性使用 `heatmapLayout` 与 `cellLayout`；前端仍按 `heatmapStyle`、旧分组名和两列 `value` 判断。两侧注释条参数是 `moduleType=22`，其 `value` 为空而实际内容在 `list`，后端参数生成器错误地提前输出 `NULL`。注释条分类嵌套在 22 中，图例收集器只遍历顶层 7。

## 方案

使用当前已保存的数据集文件与标记调用 `gotoBase::check_symmetry(file, col_col, row_col, value_col)`。后端根据当前用户的绘图记录解析文件路径与三个单选列；无绘图 ID 的示例从模板已保存的文件与标记读取，避免前端提交任意文件路径；只返回 `isSymmetric` 和 `dataType`。前端仅在首次加载以及数据文件或标记保存后刷新检测结果，且不覆盖用户随后手工修改的数据类型。把对称结果作为不可见的 `isSymmetric` R 参数加入当前绘图参数树；示例结果只影响当前页面，不能通过空绘图 ID 的保存接口写回共享模板。检测不可用时不根据行列集合猜测对称性，完整矩阵保留可用，其他布局禁用；绘图提交等待检测成功。

布局限制由对称结果及 `value2` 是否有标记共同决定：非对称仅完整矩阵；对称无次值时全部可用；对称有次值时仅完整矩阵和上下三角分离可用。次值已标记且布局为完整矩阵时显示单元格布局。两组单元格 Tab 使用模板现名；旧“值标记两列”条件改为 `value` 和 `value2` 都已标记。`dataType=similarity` 显示距离转换方法，`dataType=raw` 显示距离算法，其他值隐藏二者。

后端 `ClassifyParamList` 与单个分类参数同样允许 `value=null`，再从 `list` 生成 R 值。前端图例收集热图两侧注释的嵌套分类，并在异步重建注释映射完成后刷新图例列表。

## 验证

先增加失败测试，覆盖接口列标记与权限、R 返回解析、四种布局组合、数据类型显隐、注释条 R 参数以及嵌套图例。随后运行受影响 Jest 和 Maven 测试、构建，按项目规定启动并关闭 Java 服务；真实 R 链路仅在本机 Rserve 与文件映射可用时执行。

## 2026-09-29 部署后矩阵检测失败提示优化

用户确认优化现有错误提示后自行重新部署。方案是在前端保存最近一次检测失败的安全原因，分析按钮按该原因显示错误，检测失败仍禁止绘图；正常非对称结果仍可绘图。区分缺少已保存记录、列/行/主值标记、404 接口缺失、401/403 认证权限、超时/网络、R 服务不可用、公开调用失败与返回格式异常。只显示已知业务错误或固定提示，不透出任意服务端异常、路径、表达式或包实现。重试成功清空旧原因，过期请求不覆盖最新原因。

沿用现有接口和检测算法，无需修改模板、字典、数据库或机密 R 包。request.js 只补充 error.response 的空值保护，确保无响应的网络错误不被二次 TypeError 覆盖，这是区分超时与断网的必要修复。拒绝仅换一条通用文案，因为不能帮助部署后定位；不添加检测降级，因为不能在没有有效结果时使用猜测的对称性。验收为相关 Jest 回归先失败后通过、前端生产构建成功、真实浏览器对实际组件的失败和恢复提示验证、合并后验证并推送已有基线。生产本次失败根因及完整 R 出图尚未解决。

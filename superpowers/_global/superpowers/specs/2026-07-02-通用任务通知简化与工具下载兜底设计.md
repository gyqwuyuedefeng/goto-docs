# 通用任务通知简化与工具下载兜底设计

## 背景

图片格式转换工具在转换成功后显示“转换成功”，但点击“下载结果”提示“没有可下载的文件”。前端控制台显示成功 WebSocket 消息的 `message.data` 是原始图片转换任务数据，包含 `inputFile`、`outputFile`、`fileName` 等路径字段，但不包含 `taskId`，因此 `convertResult.taskId` 保持为 `null`。

Excel 格式转换工具使用同一套通用任务通知链路和相同的前端提取逻辑，也存在同类风险：提交接口返回 `taskId`，但 `processing` 分支没有保存；成功通知只从 `message.data.taskId` 提取下载标识。

根因与近期通用任务通知链路改造有关。任务通知经过 Redis Stream 后，`system` 侧消费到的 `CommonTask.data` 可能是泛型 `Map`，导致 `CommonTask.simpleData()` 中的 `instanceof FileReshape`、`instanceof ImageConvertTask`、`instanceof MergeImageTask` 分支不命中，最终把原始任务数据透传给前端，而不是生成包含 `taskId` 的简化数据。

## 目标

1. 统一修复通用任务通知简化逻辑，让 Redis Stream 反序列化后的 `Map` 数据也能按 `taskType` 生成前端兼容数据。
2. 图片格式转换和 Excel 格式转换前端增加下载标识兜底，避免单条通知数据异常时无法下载。
3. 修复图片转换页 `el-progress` 的非法空字符串 `status` 警告。
4. 保持现有 WebSocket 路由协议不变：`commonNoticeUUID` 继续作为前端页面通知路由和工具下载任务 ID。

## 非目标

1. 不改变 `CommonTask.commonNoticeUUID` 与 `executionId` 的职责划分。
2. 不修改 Redis Stream、Job Ledger、ACK、租约或数据库结构。
3. 不重构下载框架或文件生成路径。
4. 不把工具下载任务 ID 改成 `executionId`。

## 方案对比

### 方案 A：只在前端兜底

前端在提交接口返回 `processing` 时保存 `taskId`，WebSocket 成功时如果没有 `taskId` 就使用已保存值或 `commonNoticeUUID`。

优点：改动小，能快速修复当前两个页面。

缺点：后端通知仍然不是约定的数据结构，其他通用任务页面仍可能收到原始任务数据。

### 方案 B：只在后端修复通知简化

后端在通知推送前把 `Map` 数据转成对应 DTO 或直接按 `taskType` 构造简化数据。

优点：修复根因，所有前端通用任务通知受益。

缺点：前端仍完全依赖通知携带 `taskId`，如果通知被旧服务或异常路径生成，下载按钮仍可能失败。

### 方案 C：后端统一修复 + 前端下载兜底

后端修复 `Map` 数据无法简化的问题；图片转换和 Excel 转换前端同时保存提交响应中的 `taskId`，并在成功通知缺少 `taskId` 时兜底。

优点：既修根因，也提高两个下载工具对异常通知的容错；符合当前用户确认的范围。

缺点：改动覆盖 `goto/common` 或 `goto/system` 加 `goto-web` 两侧，需要同时验证后端单测和前端行为。

推荐方案 C。

## 详细设计

### 后端通知简化

在 `CommonTask.simpleData(BasicMessage basicMessage)` 内统一处理 Redis Stream 反序列化后的 `Map` 数据。该方法本来就是通用任务通知的前端兼容数据出口，把兜底放在这里可以让所有调用方共享同一套简化规则，也避免 `system` 通知消费者复制任务类型判断。

当 `data` 是 DTO 实例时，保留现有 `instanceof` 分支。当 `data` 是 `Map` 时，按 `taskType` 读取需要的字段并构造统一的简化 `Map`。输出结构必须保持前端兼容：

- `TaskType.FILE_RESHAPE`：`taskId`、`fileName`、`type`、`status`。
- `TaskType.IMAGE_CONVERT`：`taskId`、`fileName`、`inputFormat`、`outputFormat`、`status`。
- `TaskType.MERGE_IMAGE`：`taskId`、`fileName`、`status`。

其中 `taskId` 必须来自 `commonNoticeUUID`，不能使用 `executionId`。

### 图片转换前端兜底

`goto-web/src/views/goto/toolsBox/type/imageConvert.vue` 调整：

1. 提交接口 `response.data.status === 'processing'` 时，如果 `response.data.taskId` 存在，立即写入 `convertResult.taskId`。
2. WebSocket 成功通知中优先使用 `message.data.taskId`；如果缺失，则使用已有 `convertResult.taskId`；再缺失时使用当前页面 `commonNoticeUUID`。
3. `fileName` 优先使用 `message.data.fileName`；如果没有，则保留当前输出文件名。
4. `el-progress` 不再传入非法空字符串状态。初始和普通进度状态使用 `null`，或在模板中只传合法状态。

### Excel 转换前端兜底

`goto-web/src/views/goto/toolsBox/type/excelFormatConvert.vue` 调整：

1. 提交接口 `response.data.status === 'processing'` 时，如果 `response.data.taskId` 存在，立即写入 `convertResult.taskId`。
2. WebSocket 成功通知中优先使用 `message.data.taskId`；如果缺失，则使用已有 `convertResult.taskId`；再缺失时使用当前页面 `commonNoticeUUID`。
3. `fileName` 优先使用 `message.data.fileName`；如果没有，继续依赖后端下载指定器按 Redis 元数据或默认规则解析。

## 数据流

1. 前端提交转换请求，并带上 `commonNoticeUUID`。
2. `system` 创建 `CommonTask`，`commonNoticeUUID` 作为下载任务 ID 和通知路由，`CommonTaskStreamPublisher` 生成独立 `executionId` 用于后台幂等。
3. `task` 执行业务并发布成功通知。
4. `system` 消费通知，按 `taskType` 把 `CommonTask.data` 简化成前端兼容数据，补齐 `taskId = commonNoticeUUID`。
5. 前端收到成功通知后保存 `taskId` 和 `fileName`。
6. 下载按钮调用通用下载接口，使用 `taskId` 查询对应工具任务 Redis 元数据并返回生成文件。

## 错误处理

- 如果后端通知简化失败，应记录 `taskType`、`commonNoticeUUID`、实际 data 类型，并尽量保留原始通知推送，避免阻断用户看到任务终态。
- 前端成功通知缺少 `taskId` 时使用兜底值，并记录控制台日志便于排查。
- 如果兜底后仍无 `taskId`，继续提示“没有可下载的文件”，但这种情况应只出现在提交响应和页面 UUID 都异常时。

## 测试策略

### 后端单元测试

新增或更新通用任务通知简化相关测试，覆盖：

1. `CommonTask.data` 是 `Map`，`taskType = FILE_RESHAPE` 时，简化数据包含 `taskId`、`fileName`、`type`、`status`。
2. `CommonTask.data` 是 `Map`，`taskType = IMAGE_CONVERT` 时，简化数据包含 `taskId`、`fileName`、`inputFormat`、`outputFormat`、`status`。
3. `CommonTask.data` 是 `Map`，`taskType = MERGE_IMAGE` 时，简化数据包含 `taskId`、`fileName`、`status`。
4. 已经是 DTO 实例的现有路径不回归。

### 前端验证

手动验证图片转换和 Excel 转换：

1. 提交后控制台 `convertResult.taskId` 不再是 `null`。
2. 成功通知携带简化 data 时可下载。
3. 模拟成功通知缺少 `data.taskId` 时，仍能用提交响应或 `commonNoticeUUID` 下载。
4. 图片转换页不再出现 `ElProgress status` 非法值警告。

## 风险与兼容性

- 最大风险是改变 `CommonTask.simpleData()` 后影响其他统计或数据处理通知。实现必须限定在明确的工具任务类型，不改变已有统计任务分支。
- `ImageConvertTask.fileName` 当前可能保存 R 输出路径而不是纯文件名。后端下载已可通过 Redis 元数据解析真实文件，本次只保证通知和前端下载 ID 正确，不扩大到路径语义重构。
- `executionId` 只用于后台幂等，不能进入工具下载 taskId，否则会找不到以 `commonNoticeUUID` 为 key 写入的结果元数据。

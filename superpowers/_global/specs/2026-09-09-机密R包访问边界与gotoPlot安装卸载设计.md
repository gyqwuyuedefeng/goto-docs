# 机密 R 包访问边界与 gotoPlot 安装卸载设计

## 已确认目标

用户要求将 gotoTools、gotoBase、gotoPlot、gotoStat 四个目录作为公司机密源码，Agent 只允许执行安装和卸载工作，不得读取内部代码；同时指出外部工具缺少 gotoPlot 安装和卸载入口。本次立即遵守该边界，仅检查部署仓 `.bash` 下的外部包装脚本和测试，不读取四个目录内部文件。

## 设计

- 在规范仓 `goto_software_spec.md` 添加常驻边界，覆盖源码目录、同源副本、容器映射以及索引、子代理、日志等间接读取渠道。通用索引补充项目规则路由，不把机密目录路径复制到其他项目。
- 允许已授权安装器在本机内部读取安装所需元数据和源码，但禁止把内容交给 Agent 或上传；允许输出包名、阶段、版本、退出码和不含源码的错误摘要。部署工具本身位于四个目录外，可以维护。
- 依照现有单包模式增加 `install_gotoPlot.sh`、`remove_gotoPlot.sh`。固定安装路径 `/root/software/gotoPlot`，关闭依赖安装和升级，卸载缺失包为成功空操作。
- 批量入口保留原三包安装顺序，再安装 gotoPlot；卸载顺序相反。所有四包和八个脚本均在卸载开始前预检。未读机密包 DESCRIPTION，不声明已经验证真实包依赖；实际安装器负责拒绝缺失依赖。
- WSL 启动配置补上 gotoPlot 挂载；目录不存在时在停止或删除旧容器之前退出，不创建机密源码目录。本次不启动脚本、不重建容器。

## 取舍与非目标

只增加两个单包脚本会使现有批量入口和容器挂载仍不支持 gotoPlot，因此同步补齐它们；不新增通用安装框架，不修改其他 R 包源码、不安装或卸载真实包、不改生产连接或执行部署。

## 验收

- 外部脚本测试采用模拟 Docker，确认四包预检、顺序、参数检查与任一步骤失败后停止。
- 通过容器中的 R 解析器仅解析外部八个包装脚本，不执行；测试不读取真实机密目录、不调用包内函数。
- 规范元数据与既有规则测试通过，检查保密边界优先于探索、索引和调试指令。
- 跨仓提交均包含本 ID；在 goto-docs 的完成总结根目录保留唯一总结，不推送远端的已有未推送提交。

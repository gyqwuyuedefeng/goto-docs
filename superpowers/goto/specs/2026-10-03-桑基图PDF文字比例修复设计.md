# 桑基图 PDF 内容一致性修复设计

## 目标与现状

用户要求导出的桑基图 PDF 与页面显示一致，尤其是文字和连线的相对比例；本轮只修桑基图 PDF，网络图和其他格式保持现状。现有流程由前端上传当前 SVG，`DrawPlotDownload` 调用 `fileConvert.sh` 转 PDF。该脚本默认以 300 DPI 调用 `rsvg-convert`。

已用同一份现有桑基图 SVG 复现：浏览器在 402×241 像素下显示正常，300 DPI 转换后的 PDF 按同样像素尺寸栅格化时文字严重重叠；改为 96 DPI 后，文字与连线的比例基本恢复。SVG 的坐标由约 401×241 的 `viewBox` 描述，文字使用 `font-size="8pt"`。300 DPI 将 PDF 页面缩至约 96×58 pt，但文字仍保持原物理字号，产生相对放大。

实际 PDF 内容复核又发现第二个独立问题：96 DPI 输出中的 30 个节点矩形全部消失，仅余连线和标签。同一 SVG 直接经当前 `rsvg-convert` 生成 PNG 时节点也消失，故问题发生在转换器解析 SVG 阶段，不是 PDF 查看器或页面栅格化。公开样本的每个节点 `<rect>` 都带 `filter="url(#shadow-N)"`，对应 `<feDropShadow>` 定义；在不改原件的临时输入中仅移除这些矩形的阴影引用，转换后的 PDF 节点恢复。用户已同意本轮继续修复节点，并接受 PDF 节点不带阴影。

## 设计

在 `goto/system` 的 `DrawPlotDownload` 中，仅当图组为桑基图（现有分支值 15）且下载格式为 PDF 时，向已有转换脚本传入 `-d 96`；此部分已经实现并通过自动测试。其他调用仍不传 DPI，沿用脚本默认 300。

同一分支在调用转换器前，于本次下载任务的临时工作目录制作 SVG 副本，仅移除节点 `<rect>` 上指向 `#shadow-N` 的 `filter` 属性；用该副本生成 PDF。必须限定为生成器已有的节点阴影语法，不删除其他元素或其他滤镜。转换完毕后，无论成功或失败，都删除该临时副本，且须在整理下载文件与创建 ZIP 之前删除，避免副本进入交付物。原始 SVG 的字节与存储路径保持不变；SVG 直接打包、PNG/JPEG、网络图和其他图组继续使用原输入。若读取或写入临时副本失败，沿用现有下载失败路径，不悄然回退到会丢节点的原 SVG。转换命令既有失败处理和 `fileConvert.sh` 默认值不扩改，不另建转换服务或配置项。

选择该方案是因为它分别修正已定位的 SVG→PDF 单位不匹配，以及当前转换器对节点阴影引用的处理问题；变更范围都可由下载器现有图组和格式判断限定。备选方案包括：在前端把 SVG 的 `pt` 字体转换为 `px` 或删除滤镜，会改变上传源文件及其他导出；修改 `fileConvert.sh` 的全局默认 DPI 或滤镜处理，会影响全部图形；替换共享转换器会扩大运行环境变更。均超出本轮范围。

## 验证与边界

原 DPI 命令部分已按先红后绿完成单元测试、受影响模块测试与一次完整 Maven 构建。节点部分继续先新增失败测试：桑基图 PDF 使用的临时 SVG 去掉目标节点阴影，原 SVG 不变；网络图 PDF 和桑基图非 PDF 不产生该处理；副本不进入 ZIP，失败时也会清理。再做最小实现，确认测试由红转绿。用同一现有 SVG 真实转换并按相同输出尺寸对照浏览器与 PDF：文字与连线比例正常，节点矩形可见且位置匹配；PDF 节点阴影可缺失。最后复跑受影响模块测试、必要构建、后端启动与关闭验证。不能以 PDF 文件生成成功、或仅测试转换命令，代替内容核对。

桑基图页面内滚动条另有来源：生成 HTML 的固定尺寸容器设置了 `overflow:auto`。简单隐藏会裁掉越界标签或拖动后的节点；用户允许暂缓，因此本轮不改滚动条，也不改变生成 HTML 或图形布局。

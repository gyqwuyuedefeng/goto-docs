# 桑基图 D3 动态渲染设计

## 背景与目标

当前网络图使用 D3.js v7 在 HTML 中创建原生 SVG，页面通过 iframe 展示该 HTML，下载时直接序列化用户操作后的 SVG DOM。这使页面与导出使用同一个渲染结果，并能保留节点拖拽后的布局。

当前桑基图只展示 R 绘图链路生成的静态 SVG，不支持节点拖拽、连线实时跟随、关联高亮和交互提示，也无法导出拖拽后的当前布局。

本次改造将桑基图调整为 D3.js + 原生 SVG 动态渲染，由同一个前端渲染器同时负责页面展示与 SVG 导出。验收目标是：

- 节点可以在图内拖拽，与该节点相连的边实时更新。
- 悬停节点或边时，高亮关联内容并显示数据提示。
- 沿用绘图结果区已有缩放能力。
- 下载 SVG 保留用户拖拽后的当前节点位置和连线几何形状。
- 现有桑基图参数、Tab 显隐和列标记联动继续有效。
- 动态渲染异常时仍可回退展示后端已生成的静态 SVG。

## 方案比较

### 方案一：D3.js + d3-sankey + 原生 SVG（采用）

- 使用项目已存在的 D3.js v7，增加官方 `d3-sankey` 布局模块。
- `d3-sankey` 负责初始层级、节点高度和边宽计算，原生 SVG 元素负责展示、拖拽和导出。
- 页面和导出共享同一 SVG DOM，架构特性与网络图一致。
- 不依赖外部 CDN，避免内网或断网环境下动态图失效。

### 方案二：ECharts SVG 渲染器

ECharts 已有桑基图和 SVG 渲染能力，实现量较小，但与网络图的 D3 原生 SVG 架构不同，并且对拖拽后几何位置、SVG 节点结构和导出细节的控制弱于 D3，不采用。

### 方案三：后端或 R 绘图链路同时生成 HTML

该方案表面上与网络图产物相同，但会扩大到后端、任务服务和 R 绘图链路，同时不利于使用页面已有参数和字段标记状态实时建模。本次没有修改后端协议的必要，不采用。

## 架构与组件边界

### 动态 SVG 渲染器接入点

`PlotResultCanvas.vue` 作为结果区唯一接入点，根据绘图分组选择结果渲染器：

- 网络图（分组 ID 14）保持当前 HTML iframe 方式。
- 桑基图（分组 ID 15）使用新的 D3 动态渲染组件。
- 其他图形保持静态图片展示。

接入层使用一个小型映射表将分组 ID 映射到动态组件，不引入独立插件框架。动态组件对外只需约定：

- `getSvgContent()`：返回当前布局的完整 SVG 字符串。
- `resize()`：结果容器尺寸变化时更新可视区域。

后续其他图形只有在确认需要动态 SVG 时才接入该映射和接口，本次不预建更多抽象。

### 桑基图数据适配器

纯 JavaScript 适配器负责把绘图页面状态转换为与 DOM 无关的桑基图模型，便于独立测试。其输入为 `plot.userDraw.fileSettings`、列标记状态和 `paramSettingsList`，输出为：

- 规范化的节点数组：唯一名称、层级、原始属性、样式与标签设置。
- 规范化的边数组：起点、终点、权重、原始属性与样式。
- 布局设置：画布尺寸、边距、节点宽度、节点间距、排序和对齐设置。
- 装饰设置：标题、副标题、字体、标签和图例。

数据适配器不读取固定 Excel 列名，而是通过 `file_settings` 中的标记定位当前列：

- 边文件的 `from`、`to`、`weight`、`attribute` 标记分别提供起点、终点、可选权重和可选边属性。
- 节点文件的 `name`、`order`、`attribute2` 标记分别提供节点名、层级和可选节点属性。
- 只纳入当前有效数据行；边中引用但节点文件未声明的名称会作为默认节点补入，防止整图因单行不完整而失败。
- `name` 是可选标记；未标记节点名时，全部节点都从边的起终点合并生成，节点文件属性不参与映射。
- 节点名为空、起点或终点为空、权重非有限正数的数据行按明确规则过滤或回退，不将 `NaN` 传入布局。

### D3 桑基图渲染器

渲染组件只负责把适配器模型转成 SVG：

1. 使用 `d3-sankey` 计算初始节点和边几何位置。
2. 用 `<rect>` 绘制节点，用 `sankeyLinkHorizontal()` 生成边路径，用 `<text>` 绘制标签和标题。
3. 节点通过 `d3.drag()` 在画布内拖拽；每个拖拽事件都更新节点的 `x0/x1/y0/y1`，调用 Sankey 布局的 `update` 刷新连接点，然后重绘相关边。
4. 节点拖拽限制在图形的布局区域内，不覆盖标题和图例保留区。
5. 悬停节点时保留其入边、出边及相邻节点的正常不透明度，弱化其他元素；悬停边时保留该边与两端节点。
6. 提示框作为交互层放在 SVG 外部，显示节点属性或边的起终点、权重和属性，不进入导出文件。

缩放继续由 `PlotResultCanvas.vue` 现有的结果容器缩放控件负责，不叠加第二套 D3 zoom 状态。这与当前网络图的页面操作保持一致。

## 参数、Tab 与字段标记映射

数据库中现有桑基图模板已包含本次渲染所需的参数和字段标记，本次不修改数据库模板，不新增参数名。

### Tab 显隐

- `管理参数`：继续隐藏。
- `预览与输出`、`节点设置`、`边设置`、`标签设置`、`图例设置`、`标题/副标题`、`主题样式`：继续显示。
- `nodeGroupOrder` 的显隐仍以具体模板的 `visible` 配置为准，不在渲染器中强制改写。

### 参数映射

- 画布：`width`、`height`、`plotMargin`。`width` 和 `height` 按模板声明的 mm 转换为 SVG pt 坐标（`pt = mm × 72 / 25.4`）；`dpi` 只作为后续位图转换输出参数。
- 节点布局：`nodeWidth`、`colMargin`、`vSpace`、`ifSorting`、`sortingMode`、`alignMode`、`nodeGroupOrder`。
- 节点样式：`nodeFillColor`、`nodeFillAlpha`、`nodeBorderColor`、`nodeBorderWidth`。
- 边数据与样式：`edgeWeight`、`colorFollowNode`、`edgeFillColor`、`edgeFillAlpha`、`edgeBorderColor`、`edgeBorderWidth`。
- 标签：`nodeLabel`、`nodeLabelAlign`、`axisPosX`、`axisTextX`。
- 标题：`title`、`subTitle`、`plotTitle`、`plotSubTitle`。
- 图例：`legendList`、`legendSettings`。
- 字体：`fontFamilyEN`、`fontFamilyCN`。

分类参数延续现有 constant、discrete 和 continuous 三种模式。数据适配器根据参数的 `by`、对应文件标记和行属性求值；找不到指定列、映射项或合法数值时使用该参数现有默认值。`colorFollowNode=true` 时边使用起点到终点的 SVG 线性渐变，`edgeFillColor` 的表单隐藏联动继续由 `sankeyModify.js` 处理。

布局参数的前端语义固定如下，避免与 `d3-sankey` 的默认排序产生隐式差异：

- `nodeGroupOrder` 决定 `order` 标记值对应的水平层级顺序；未列入的值按数据首次出现顺序追加。
- 当节点文件没有有效 `order` 标记时，层级索引由边的有向无环拓扑深度推导，源节点从第 0 层开始。
- `colMargin` 控制相邻节点层的水平间距，`vSpace` 作为同层节点的最小垂直间距，图形四周留白由 `plotMargin` 控制。
- `ifSorting=false` 时同层节点保留节点文件的输入顺序。`ifSorting=true` 且 `sortingMode=independent` 时，每层按节点流量降序独立排列，同值保留输入顺序；`sortingMode=sequential` 时，使用 Sankey 迭代放松按相邻节点重心调整顺序，以减少连线交叉。
- `alignMode=top|center|bottom` 分别将每个层级的实际占用区域靠上、居中或靠下放置，不将该垂直对齐参数错用为 `d3-sankey` 的水平 `nodeAlign`。

`sankeyModify.js` 继续负责表单阶段的参数联动，包括节点层级变化后重建 `nodeGroupOrder`、标签对齐列表以及边颜色参数显隐。其中兼容历史参数的 `hSpace` 分支不存在于当前四个桑基图模板，本次渲染器不将它当作当前参数。动态渲染器只消费最终状态，不复制表单规则。

## 页面展示与导出数据流

1. 用户按当前流程上传边文件和节点文件，完成列标记和参数设置。
2. 开始分析后，后端和 R 任务链路保持不变，仍生成原静态 SVG 作为结果完成信号与降级产物。
3. WebSocket 返回绘图成功后，`PlotResultCanvas.vue` 识别桑基图分组，把当前 `plot` 交给 D3 渲染器。
4. 渲染器从完整 Handsontable 数据、列标记和参数中构建模型，生成页面 SVG。
5. 拖拽只修改当前渲染组件内的布局状态，不回写 Excel、参数模板或数据库。重新分析或重新打开绘图时使用参数重算初始布局。
6. 用户下载时，`draw.vue` 通过结果区统一接口获取当前 SVG，沿用现有 `HTML_TO_SVG_FILE` 上传和下载链路。
7. 导出时对当前 SVG 做无损克隆，补齐 XML namespace、内联必要样式并清除悬停弱化等瞬时交互状态；节点和边的当前坐标不变。

因此屏幕和下载使用同一渲染器和同一布局状态。不承诺与历史 R SVG 像素级相同；新链路的一致性定义为“页面当前非瞬时交互状态与导出 SVG 一致”。

## 异常处理与降级

- 标记列缺失、有效节点不足、边数据为空、存在自环或桑基图不支持的循环时，适配器返回可诊断错误，不让 D3 使用不完整数据继续计算。
- 动态渲染失败时，结果区显示原静态 SVG，同时显示简短的动态渲染失败提示，不影响用户查看已有结果。
- 降级状态下下载使用原静态结果，不伪造“已导出拖拽布局”。
- 导出时若无法获取有效 SVG，保留现有错误提示并停止动态 SVG 上传，不上传空文件。
- 渲染组件销毁时移除 `ResizeObserver`、D3 事件和提示层，避免重复进入绘图页后发生内存泄漏。

## 测试与验收

### 单元测试

- 根据 `file_settings` 标记正确解析起点、终点、节点名、层级和多属性列。
- 空行、非数值权重、边引用的缺失节点、重复节点和循环数据按设计处理。
- constant、discrete、continuous 分类参数能够读取正确标记列并返回样式，缺少映射时回退默认值。
- 现有桑基图模板的 `nodeGroupOrder.visible` 差异不影响模型构建。
- 拖拽更新后导出 SVG 包含当前节点坐标和更新后的边路径。
- `PlotResultCanvas.vue` 只在桑基图数据可用时选择动态渲染器，失败时回退静态图片。
- `draw.vue` 对网络图 iframe 和桑基图组件都使用统一的当前 SVG 获取与上传逻辑。

### 本地与 Playwright 验收

1. 使用动态端口启动本地后端和前端，后端使用 `home` profile 与 `-Denv=local`。
2. 按项目规则临时备份并替换微信公众号登录页，使用本地验证码登录。
3. 选择实际桑基图模板和样例文件，校验列标记、Tab 显隐和参数联动。
4. 运行分析后校验 D3 SVG 正常显示，节点可拖拽，边实时跟随，悬停高亮和提示正常，缩放后仍可拖拽。
5. 记录一个节点拖拽前后的位置，下载 SVG，解析导出文件确认其包含拖拽后的坐标与路径。
6. 确认网络图原 iframe 展示和下载链路未回归。
7. 无论验收成功或失败，恢复登录页原始字节、校验 SHA-256 和 Git 差异，停止本次服务并确认端口释放。

## 范围边界

- 不修改桑基图数据库模板、数据字典、后端返回协议或 R 绘图实现。
- 不读取、分析或修改项目禁止访问的 R 包源码。
- 不将拖拽布局持久化到数据库；本次仅要求下载当前布局。
- 不同时重写网络图渲染器，只保证新的统一导出接入不影响旧链路。
- 不为未确认的其他图形创建额外组件、配置或通用布局引擎。

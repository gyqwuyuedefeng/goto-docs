- [ ] **Step 3: 实现表格和标记列规范化**

`sankeyModel.js` 先实现以下稳定边界：

```js
class SankeyModelError extends Error {
  constructor(message, code) {
    super(message)
    this.name = 'SankeyModelError'
    this.code = code
  }
}

function buildSankeyModel(plot) {
  const userDraw = plot && plot.userDraw
  if (!userDraw) throw new SankeyModelError('桑基图缺少绘图数据', 'MISSING_USER_DRAW')
  const edgeFile = requireFile(userDraw.fileSettings, 0, '边')
  const nodeFile = requireFile(userDraw.fileSettings, 1, '节点')
  const edgeRows = readSelectedRows(edgeFile)
  const nodeRows = readSelectedRows(nodeFile)
  const columns = resolveSankeyColumns(edgeFile, nodeFile)
  return assembleModel({ edgeRows, nodeRows, columns, paramSettingsList: userDraw.paramSettingsList })
}

export {
  SankeyModelError,
  buildSankeyModel,
  resolveClassifyValue
}
```

实现规则固定为：

- `handsontable.header` 同时接受数组和以数字为 key 的对象，`body` 行同时接受数组和数字 key 对象。
- 首列为 `GT_Selected` 时只保留 `1` 或 `'1'`；没有该列时保留所有非空行。
- 先由 `fileMarkContainerList[field].positionParam` 和 `headerInfo.status` 的位判定实际列，无容器时才以 `headerInfo.field/key` 兼容旧数据。
- `from`、`to` 缺失抛出带错误码的 `SankeyModelError`；`weight`、`name`、`order`、`attribute`、`attribute2` 可选，两类 `attribute` 标记支持多列。
- `name` 未标记时从所有边的起终点合并生成节点，不因节点文件可选标记缺失进入降级。
- 边权重无法转为有限正数时回退到 `edgeWeight` 的合法常量值，仍无合法值时使用 `1`。
- 边中出现而节点文件未声明的名称补为无属性节点；节点按名称去重，首行属性优先。
- 检测自环和有向循环，分别抛出 `SELF_LINK` 和 `CYCLIC_GRAPH`。

- [ ] **Step 5: 实现参数解析与布局语义**

`assembleModel` 实现下列确定性规则：

- `nodeGroupOrder` 选中项决定层级索引，缺失值按首次出现顺序追加。
- 节点数据没有有效 `order` 标记时，对已通过循环检测的边执行拓扑遍历，以从任一源节点到当前节点的最长路径长度作为 `levelIndex`。
- `width`、`height` 按毫米转为 SVG 点单位（`pt = mm × 72 / 25.4`），`plotMargin` 是上右下左图形留白；`colMargin` 是相邻节点层的水平间距，`vSpace` 是同层最小垂直间距。所有值先归一化为有限非负数。
- `ifSorting=false` 保留节点文件顺序；`independent` 按节点流量降序且保持稳定同值顺序；`sequential` 使布局器执行相邻层迭代放松。
- `alignMode` 只控制各层实际占用区域的 top/center/bottom 垂直偏移，不传给 D3 水平 `nodeAlign`。
- `nodeLabelAlign` 按层级索引选择 left/right/center；缺失项使用 left。
- 分类项 `type=1` 时先按 `by` 值匹配 `valueList.name/key`，无 `by` 时取首个合法值；`type=2` 时使数值域在两色或三色区间插值；任一级数据不完整都回退参数默认值。

- [ ] **Step 4: 实现渲染器基础结构与生命周期**

`D3SankeyResult.vue` 使用下列公开结构：

```vue
<template>
  <div ref="root" class="d3-sankey-result">
    <svg ref="svg" class="sankey-svg" role="img" aria-label="桑基图" />
    <div v-show="tooltip.visible" class="sankey-tooltip" :style="tooltip.style">
      {{ tooltip.text }}
    </div>
  </div>
</template>

<script>
import * as d3 from 'd3'
import { sankey, sankeyLinkHorizontal } from 'd3-sankey'
import { buildSankeyModel } from './sankeyModel'

export default {
  name: 'D3SankeyResult',
  props: { plot: { type: Object, required: true } },
  data() {
    return {
      graph: null,
      model: null,
      resizeObserver: null,
      tooltip: { visible: false, text: '', style: {} }
    }
  },
  watch: {
    plot: { deep: true, handler() { this.render() } }
  },
  mounted() {
    this.render()
    this.observeResize()
  },
  beforeDestroy() {
    this.destroyRenderer()
  }
}
</script>
```

`render()` 每次先清空旧 SVG 和渐变定义，再调用 `buildSankeyModel`。成功时发出 `render-ready`，失败时清空图并发出 `render-error` 且不向上抛出未捕获异常。`ResizeObserver` 只触发 `resize()`，销毁时 `disconnect()`。

- [ ] **Step 5: 实现 Sankey 布局和参数到 SVG 映射**

布局器的核心配置固定为：

```js
const layout = sankey()
  .nodeId(node => node.id)
  .nodeWidth(model.layout.nodeWidth)
  .nodePadding(model.layout.vSpace)
  .nodeAlign(node => node.levelIndex)
  .nodeSort(model.layout.ifSorting ? (a, b) => b.flow - a.flow : null)
  .extent([[model.margin.left, model.margin.top], [plotRight, plotBottom]])
  .iterations(model.layout.sortingMode === 'sequential' ? 32 : 0)

this.graph = layout({
  nodes: model.nodes.map(node => ({ ...node })),
  links: model.links.map(link => ({ ...link }))
})
```

布局后以 `colMargin` 作为相邻层的目标水平间距；当层数、节点宽度和间距超出可用宽度时，只等比压缩层间距到可用范围，不压缩节点宽度。`d3-sankey` 的 `nodeAlign` 回调层号受拓扑最大深度约束，若模板显式 `nodeGroupOrder` 超出该深度，须在布局后按 `levelIndex` 映射水平列，不能依赖回调保留所有列。然后按 `alignMode` 对每层 y 坐标做整体偏移。节点和边的 fill/stroke/opacity/width 使用模型已解析样式，标签按 `nodeLabelAlign[levelIndex]` 决定锚点和 x 偏移。`colorFollowNode=true` 时在 `<defs>` 中为每条边创建唯一 `linearGradient`。

节点选择集绑定：

nodeSelection.call(

`draw.vue` 中的核心流程调整为：

```js
async handleDownload() {
  const resultCanvas = this.$refs.resultCanvas
  if (!resultCanvas || !resultCanvas.hasCurrentSvgResult()) {
    this.doDownload()
    return
  }

  const svgContent = resultCanvas.getSvgContent()
  if (!svgContent) {
    this.downloading = false
    this.ToastificationNotice.notifyError(this, '获取当前SVG失败！')
    return
  }

  this.downloading = true
  try {
    const res = await crudFile.upload(this.createSvgFormData(svgContent))
    if (res.code === 200) this.doDownload()
    else this.downloading = false
  } catch (error) {
    this.downloading = false
  }
}
```

`createSvgFormData(svgContent)` 只使用本次调用显式传入的字符串创建 Blob，不再隐式依赖可能过期的 `resultCanvas.svgContent`。`uploadSvgImplicitly()` 同样在调用前重新取当前 SVG，无有效 SVG 时直接停止。

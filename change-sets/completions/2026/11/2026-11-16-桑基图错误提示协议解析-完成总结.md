# 桑基图错误提示协议解析完成总结

## 结果摘要

已修复前端错误提示直接展示整段 R 协议 JSON 的问题。标准 JSON、重复序列化字符串，以及 JSON 外直接附加单/双引号的形式，均可只展示有效的中文 msg。105 项单元测试、24 项 Playwright 场景和定向 ESLint 通过。后续按用户要求将已验收的集成提交 3d7e07690fc82978404f2642d291a5a258029fd5 合入本地 master，并推送至 origin/master；本地与远端提交一致。未进行部署操作。

## 原因与目标

用户反馈桑基图负权重校验错误直接显示 status/msg/data JSON，并要求检查历史修复、落实修复，以及使用 Playwright 故意返回错误核对提示。历史 goto-web 提交 394f1f3 只在绘图分析失败的 WebSocket 分支解析一层 JSON，其他组件和 HTTP 错误入口仍直接展示原文；该遗漏已由新增测试复现。线上原始消息究竟在哪一层增加引号尚未确认。

验收目标为四条入口只显示 msg、每次仅出现一个错误 Toast、失败状态不被改为成功，以及普通文本、无效协议、成功提示仍按原行为处理。后续用户追加本地重新启动 Playwright、验收通过关闭进程、合并本地并推送远端，沿用当前变更集完成。

## 设计决策

在 vueToastificationNotice 中集中解析错误消息，并在普通 HTTP/Blob HTTP 错误中复用；移除 draw.vue 的单独解析。最多解析四层，仅接纳 status 为 fail/error 且 msg 为非空字符串的协议；无法确认协议时保留原文。错误作为 title 或 message 传入均可处理。

未采用不加校验地删除所有引号、无限递归解析或直接修改后端协议的做法，以免破坏普通错误文字及既有调用语义。本次没有修改 Java、数据库模板、参数联动或任何机密 R 包。

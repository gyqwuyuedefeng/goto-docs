# Chrome 标签侧边栏管理器设计

## 背景

用户需要一个本地自用的 Chrome 插件，用来管理大量“不想关闭但需要分类保存”的网页。插件不需要上传 Chrome 商店，第一版通过 `chrome://extensions/` 的“加载已解压的扩展程序”方式安装和使用。

核心目标不是做一个小 popup 弹窗，而是做一个常驻的网页工作台：左侧由插件提供分组和网页导航，右侧仍由 Chrome 主标签页显示真实网页，例如淘宝、文档、后台系统等可正常交互的页面。

## 目标

- 使用 Chrome Side Panel 作为插件主界面。
- 左侧展示分组树，分组可展开，展开后显示该分组中的网页。
- 顶部提供常用工具按钮，包括保存、导入、导出和搜索。
- 点击左侧网页时，右侧 Chrome 主标签页打开真实网页。
- 打开网页采用“已有则切换，没有则新开”的策略。
- 支持保存当前页、当前窗口、当前 Chrome 原生标签组。
- 支持右键菜单把当前网页或右键链接添加到指定分组。
- 支持分组排序、同一分组内网页排序。
- 支持删除分组和删除单个网页。
- 支持 JSON 导出和导入，便于本地备份和迁移。

## 非目标

- 第一版不上传 Chrome Web Store。
- 第一版不把淘宝、京东等真实网页嵌入插件 iframe。
- 第一版不实现跨设备同步，避免受 `chrome.storage.sync` 容量限制。
- 第一版不实现批量删除、多选整理和跨分组拖拽移动网页。
- 第一版不抓取网页正文内容，只保存浏览器可获得的标题、URL 和来源信息。

## 推荐方案

采用 Manifest V3 + Chrome Side Panel。

插件界面常驻在浏览器侧边栏中，Chrome 主内容区仍显示真实网页。这样既符合“左侧分组、右侧网页本身”的使用预期，也避免多数网站通过 `X-Frame-Options` 或 `Content-Security-Policy frame-ancestors` 禁止被插件页面 iframe 嵌入的问题。

## 架构

### service_worker

负责插件生命周期、右键菜单注册、右键菜单点击处理、打开 side panel，以及与侧边栏页面之间传递待保存网页信息。

### sidepanel 页面

负责展示和操作主界面：

- 顶部工具栏。
- 左侧分组树。
- 分组展开/收起。
- 点击网页打开或切换 Chrome 标签页。
- 拖拽排序。
- 导入导出入口。
- 删除和重命名操作入口。

### storage 数据层

统一封装 `chrome.storage.local`，负责读取、写入、合并、覆盖、去重和排序保存。侧边栏和 `service_worker` 不直接散落调用存储 API，避免后续数据结构变更时影响范围过大。

### tabs 控制层

封装与 Chrome 标签页相关的行为：

- 查询当前激活标签。
- 判断同 URL 标签是否已打开。
- 激活已有标签。
- 新建标签并激活。
- 批量恢复分组。
- 创建同名 Chrome 标签组。

### import/export 模块

负责 JSON 导出、导入格式校验、合并导入和覆盖导入。导入失败时不得修改现有数据。

## 权限

初步需要以下权限：

```json
["tabs", "tabGroups", "storage", "sidePanel", "contextMenus"]
```

如果后续导入导出实现需要下载文件，还可以按实现方式评估是否增加 `downloads` 权限。第一版优先使用浏览器下载能力或页面内文件输入，避免不必要权限。

## 界面设计

侧边栏采用顶部工具栏 + 左侧树形导航的结构。

顶部工具栏：

```text
保存当前页 | 保存当前窗口 | 保存当前标签组 | 导入 | 导出 | 搜索
```

左侧分组树：

```text
▾ 购物
  淘宝首页
  京东商品页
  拼多多订单

▸ AI 工具
▸ 生产环境
```

点击分组只展开或收起，不自动打开网页。分组操作通过分组旁菜单或工具区触发，包括重命名、删除、导出、恢复到当前窗口、恢复到新窗口。

点击网页时，插件在 Chrome 主标签页区域打开真实网页。打开策略为 URL 精确匹配：当前窗口已有相同 URL 时激活已有标签，否则新建标签并切换过去。

## 右键菜单

右键菜单支持把当前网页或右键链接添加到指定分组。

页面空白处右键时：

```text
添加到标签管理器
  添加当前网页到
    购物
    AI 工具
    新建分组...
```

链接上右键时：

```text
添加到标签管理器
  添加当前网页到
    购物
    AI 工具
    新建分组...
  添加当前链接到
    购物
    AI 工具
    新建分组...
```

选择已有分组时直接保存。选择“新建分组...”时打开 side panel，并带入待保存网页，等待用户输入分组名后保存。

## 拖拽排序

第一版支持两类排序：

- 分组之间拖拽排序。
- 同一分组内网页拖拽排序。

排序结果写入 `chrome.storage.local` 中的 `sortOrder` 字段，并在刷新侧边栏后保持。跨分组拖拽移动网页暂不纳入第一版核心范围，可通过网页菜单的“移动到分组”作为后续增强。

## 删除

第一版提供删除分组和删除单个网页。

删除分组会删除该分组下所有保存网页，必须二次确认。确认文案需要明确说明影响范围，例如“将删除分组‘购物’及其下 5 个网页，此操作不会关闭已经打开的 Chrome 标签页”。

删除单个网页只删除本地保存记录，不关闭已经打开的 Chrome 标签页。网页删除入口放在网页行的更多菜单或右键菜单中。

## 数据结构

主数据保存在 `chrome.storage.local`。

```json
{
  "groups": [
    {
      "id": "group_001",
      "name": "购物",
      "sortOrder": 1,
      "expanded": true,
      "createdAt": "2026-06-20T10:00:00.000Z",
      "updatedAt": "2026-06-20T10:00:00.000Z",
      "items": [
        {
          "id": "item_001",
          "title": "淘宝首页",
          "url": "https://www.taobao.com/",
          "source": "page",
          "sortOrder": 1,
          "createdAt": "2026-06-20T10:00:00.000Z"
        }
      ]
    }
  ]
}
```

字段说明：

- `groups`：全部分组。
- `items`：分组内保存的网页。
- `sortOrder`：分组或网页的展示顺序。
- `expanded`：分组展开状态。
- `source`：保存来源，取值包括 `page`、`link`、`window`、`tabGroup`。
- `createdAt` / `updatedAt`：用于导入合并、排序和用户排查。

## 导入导出

导出时导出完整 JSON 数据。导入时提供两种模式：

- 合并导入：默认模式，保留现有数据，按分组和 URL 合并，重复 URL 跳过。
- 覆盖导入：用导入文件替换当前全部数据，执行前必须二次确认。

导入前必须校验 JSON 结构。结构错误、字段缺失或 URL 非法时，不修改现有数据，并向用户展示错误。

## 数据流

保存当前页：

1. 读取当前激活标签。
2. 过滤不可保存 URL。
3. 用户选择目标分组。
4. 检查同分组是否已有相同 URL。
5. 写入 `chrome.storage.local`。

保存当前窗口：

1. 查询当前窗口全部标签。
2. 过滤 `chrome://`、`edge://`、`about:`、扩展页等不可恢复页面。
3. 保存到新分组或追加到已有分组。
4. 重复 URL 默认跳过。

保存当前标签组：

1. 查询当前窗口内带 `groupId` 的标签。
2. 按 Chrome 原生标签组聚合。
3. 用原标签组标题创建插件分组。
4. 未命名标签组使用“未命名标签组”。

打开网页：

1. 根据 URL 查询当前窗口已有标签。
2. 如果存在，激活已有标签。
3. 如果不存在，新建标签并激活。

恢复分组：

1. 读取分组下所有网页。
2. 过滤不可恢复 URL。
3. 在当前窗口或新窗口批量打开。
4. 使用 `chrome.tabs.group` 和 `chrome.tabGroups.update` 创建同名 Chrome 标签组。

## 异常处理

- URL 不可保存：提示该页面不支持保存。
- 分组为空：恢复按钮禁用。
- 同分组 URL 重复：默认跳过，并提示已存在。
- 导入 JSON 格式错误：展示错误，不覆盖现有数据。
- 覆盖导入：必须二次确认。
- 删除分组：必须二次确认。
- 权限不足或 Chrome API 调用失败：展示失败提示，并保留现有数据不变。
- 批量恢复时部分 URL 不可打开：跳过失败项，并提示失败数量。

## 测试与验收

第一版验收标准：

- 能打开 Chrome Side Panel，并在侧边栏看到顶部工具栏和左侧分组树。
- 能创建、重命名、删除分组，删除分组有二次确认。
- 能保存当前页、当前窗口、当前 Chrome 标签组。
- 能通过右键菜单把当前网页或右键链接添加到指定分组。
- 能展开和收起分组。
- 点击网页时按“已有则切换，没有则新开”打开真实网页。
- 能恢复分组到当前窗口和新窗口，并创建同名 Chrome 标签组。
- 能拖拽调整分组顺序和同组内网页顺序，刷新后顺序保持。
- 能删除单个网页。
- 能导出 JSON。
- 能合并导入或覆盖导入 JSON。
- 能过滤不可保存或不可恢复的 URL，并给出提示。

测试方式：

- 手工加载扩展：打开 `chrome://extensions/`，开启开发者模式，加载未打包扩展。
- 使用固定测试网页验证保存、打开、恢复、删除、排序、导入导出。
- 对 `storage`、`tabs`、`import/export` 等纯逻辑模块做单元测试，使用 mock Chrome API。
- 对拖拽排序、右键菜单、side panel 行为做浏览器内手工验收。

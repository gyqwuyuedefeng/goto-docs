# 绘图结果恢复与工具箱公共产物处理

目标是修复公开绘图和工具箱回归发现的问题，共享实际相同的业务规则。以同一份正式样例复验。保持既有下载接口和状态枚举。

## 实施与验收

- 在 goto 的 AbstractToolResultTaskStage 统一产物验证、结果登记和成功通知的顺序。图片转换、拼图、长宽转换复用该入口，各自只提供必要的产物和元数据。沿用下载端既有 Redis 键和字段。缺失或无效产物以任务失败结束。
- 在图片转换通用流程中用受支持的编码器生成真实 TIFF 和 JPEG。PDF、SVG 复用处理。用真实转码的下载字节检测格式和可读性。
- 在 freedom-public 的 CommonWebSocket 同步管理同一用户和连接标识的替换与清理。并发广播可遍历活跃连接。用同标识重连及旧连接迟到关闭验证生命周期。
- 在 goto-web 绘图工作区的共用流程中，已受理的当前绘图按 ID 回查状态并恢复结果。已有 WebSocket 响应保留。切换记录或离开时停止回查，避免旧记录回写。报告 terminal 状态前需先确认本次请求已被受理。
- 通过应用公开参数合同及已有运行证据定位折线 276、SVG 拼图的输入问题。在有证据的共用输入点修复。机密包内计算错误按项目边界保留最小复现与可报告摘要。
- 使用 Java 测试覆盖产物不存在、产物编码、连接替换及迟到关闭。使用前端共享用例验证通知漏收、终态回查和记录切换。使用现有真实 Playwright 验收失败模板和三项工具；通过定向验证后按项目规则评估全量复验。

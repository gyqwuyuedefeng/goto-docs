# goto 交付流水线接入设计

本文件说明 goto 前后端和必要依赖如何接入模型无关交付流水线。通用执行与集成逻辑只维护一份，见 [共享设计](/mnt/f/IdeaProjects/hsmap/hsmap-docs/superpowers/_global/specs/2026-10-03-模型无关交付流水线设计.md)；本文件仅定义 goto 专属边界，不使 hsmap 规范或权限适用于 goto。

当前仅为设计文档，尚未新增验证入口、运行服务或执行真实业务验收。远端同步失败后，用户于 2026-10-03 明确允许仅本次文档以当前本地 main 离线归档；不推送，不声称包含最新远端内容，后续业务实现必须重新执行其适用的基线核验。

## 一 接入对象与角色

| 对象 | 角色与验证边界 |
|---|---|
| goto-web | 独立前端仓库，负责页面、接口与浏览器验收 |
| goto | Java reactor，common 是库，system 与 task 是被测应用 |
| rsession | Java 编译库，不是要启动的 R 服务 |
| freedom-public | 公共编译依赖，按受影响模块验证 |
| MySQL 与 Redis | 已有依赖资源，确认实际目标和本次数据范围，不默认重建或关闭 |
| goto_rbase_wsl 中的 Rserve | 本机既有计算依赖，需要验证可用性和路径映射，不因容器 running 就认为链路可用 |
| goto-deploy-backend 的外部工具与文件映射 | 仅按本次验收需要核查和处理，部署与容器重建不属于接入的默认权限 |

只使用明确的非机密目录白名单查找文件。四个机密 R 包是运行时黑盒依赖，不纳入源码或测试扫描；不得递归扫描 goto 根目录后再过滤。

## 二 按实际场景选择验证链路

| 场景 | 被测应用 | 必要依赖与结论范围 |
|---|---|---|
| 纯前端展示且接口明确 mock | goto-web | Node/npm；只能报告模拟场景结果 |
| 真实登录、查询、不触发计算的参数保存 | goto-web、goto/system | MySQL、Redis 和相关文件；不因此证明 R 计算通过 |
| 真实绘图、示例生成、统计分析、异步处理或完整导出 | goto-web、goto/system、goto/task | MySQL、Redis Stream、本机 Rserve、Java/R 可见的同一业务文件及完整结果回传 |

真实异步流程按现有架构执行：goto-web 发请求给 system，system 通过 Redis Stream 交给 task，task 调用 Rserve；结果经消息返回 system，再由 system 的 WebSocket 通知浏览器。无需新增 WebSocket 服务；RabbitMQ 遗留配置不构成启动它或切换消息通道的理由。

完整验收需要证明请求受理、预期 task 实际执行、R 计算成功、结果文件可见以及完成状态和通知返回。页面可打开、请求返回 200 或任务进入队列只是阶段证据。

## 三 编译与制品身份

按 `rsession → freedom-public → goto/common → goto/system、goto/task` 准备源码依赖，goto-web 可独立构建。已有且与验证版本一致的制品可复用，不默认重编全部仓库。

Java 使用 JDK 17，Maven 调用现有对应平台安全包装器；本期首先使用当前 WSL 入口。`-am` 不能替代跨仓依赖制品准备，必须确认消费 worktree 实际使用的 Maven 仓库能解析本次制品，并记录必要的来源版本。不得把其他 worktree 缓存可用当作本次缓存可用。

前端命令根据真实 package.json 和当前平台执行。Windows `set NODE_OPTIONS=...` 的脚本不能被认为自动在 WSL 生效；必要变量局部注入，不修改系统全局环境。

部分现有字典测试会读取 home 配置指向的数据库，不能按“前端测试”默认视为全部离线。缺数据库时报告缺口，不伪造字典凑通过。

## 四 启动与共享资源

system 使用 `-Denv=local -Dspring.profiles.active=home`；task 使用 `-Dspring.profiles.active=home`。JVM 参数放在 `-jar` 前，具体命令和配置以当前权威规范核对后落入项目配置。

前端、system 和 task 监听端口分别即时选择，服务保留在可控前台会话。前端 HTTP 与 WebSocket 都指向本次本地 system 的实际地址；浏览器验收使用本次前端地址，不复用旧应用或线上应用。

Rserve、Redis 和 MySQL 是既有依赖，而非本次新启动的应用。验收结束只关闭本次启动的前端、system 和 task；不得关闭或重建其他任务正在使用的依赖。

worktree 和动态端口不隔离 Redis Stream、消费组、业务记录或输出文件。无法证明消息、数据与文件隔离时，真实异步验收依次执行；已有可验证隔离时才允许并行。不能为追求并行自行发明任务协议、随意选择未知 Redis DB 或建设新的消息基础设施。

依次执行只避免本次验收任务之间竞争，不自动排除既有消费者或他人消息。启动 task 前还需确认已有可验证隔离，或明确、安全的验收窗口，避免既有消费者处理本次消息及本次 task 误消费他人消息。无法确认时阻塞真实异步验收，不擅自停止既有消费者、改消息协议或清理共享 Stream。仅证明本次消息最终由本次 task 处理，仍不足以排除对他人任务的影响。

现有 home、生产资源与 Rserve 的选择按本项目当前规范执行。生产测试写入授权在 goto 范围持续有效，不重复请求逐次授权；但仍核对实际连接目标、对象和输出位置，不清空共享库或删除他人文件，也不推导部署、发布或容器重建权限。

## 五 Java 与 R 文件视图

system 和 task 必须指向同一份业务文件。WSL Java 路径和容器 R 路径不只是字符串对应，相同相对路径必须映射到同一实际文件。

先核对容器挂载元数据、目录存在和 Java 侧配置。WSL 下通过当前进程参数覆盖必要的 Java 根路径，保留 R 的容器视图；不直接沿用 Windows 路径，也不假设某个临时目录已被挂载。

映射缺失而需要停止或重建共享容器时，报告具体条件并取得相应授权；不能以测试写入许可替代容器维护权限。路径错误或包缺失也不能通过换成生产 Rserve绕过本机验收对象。

## 六 登录与机密源码保护

微信公众号验证码登录继续使用规范指定的源文件、目标文件和运行条件。临时替换前确认真实 Git 根、两个文件已跟踪且目标无已暂存或未暂存改动；保存项目外字节备份和校验值。

无论成功、失败还是中止，先恢复目标原始字节并核对 SHA 与 Git 差异，再结束验收。固定测试验证码只用于规范允许的本地受控流程，不写入脚本、配置、文档或提交；本文件不复制其值。恢复失败保留备份并报告，不能声称验收完成。

临时替换作为受控验收覆盖单独记录，而不是候选版本本身：记录候选提交、原登录文件和替换源文件的校验值、构建或服务所用的覆盖快照、适用用例与恢复结果。验证结论仅覆盖能够证明未被替换影响的业务行为；测试登录成功不能作为原登录实现已通过的证明。恢复后确认候选内容一致，再执行原候选需要的检查；原登录或其他必要行为未验证时明确列出，不声称整套验收通过。

gotoBase、gotoTools、gotoPlot、gotoStat 及其所有同源副本、Git 历史和已安装可恢复实现均禁止 Agent 读取、搜索、索引或反射。仅可使用规范允许且用户授权的外部安装/卸载工具；安装器内部技术读取不能将源码或完整日志回传模型。

可报告信息限于包名、存在或安装状态、版本、阶段、退出码与无源码错误摘要。应用调用可验证黑盒结果，但不能进入包内排查或生成内部实现测试。必要源码排查交由用户在本地处理。

## 七 集成验收与结果

通用候选集成、互斥和条件更新采用共享设计。修改编译依赖时，在真实消费项目使用匹配制品验证；不能仅验证库自身就宣布消费链路通过。

跨前后端或 system/task 变化时，记录整组候选版本、实际运行配置、制品来源与依赖资源范围。共享资源验收按本节约束依次进行；各仓版本独立通过不能代替这一组版本的联合通过。

结果至少区分：基础检查、模拟页面、真实登录查询、真实异步计算、临时登录页恢复、服务关闭、本地合入与推送部署。未运行、失败、跳过以及共享资源冲突都明确列出，不把部分通过写成完整通过。

本期 goto 接入完成需满足共享设计中的 A1 至 A10，并补充证明：

1. 被测 task 确实消费本次消息，不是既有消费者代为处理；同时证明既有隔离或安全验收窗口，避免本次消费者影响他人消息。
2. Java 与 R 读写的是同一业务文件，结果可由本次应用链路读取。
3. 临时登录页在成功、失败或中止后均恢复，认证数据未固化。
4. 机密 R 包没有进入扫描范围、日志回传或内部测试。
5. 必要依赖缺失时如实阻塞，不改用已部署应用或另一计算目标凑通过。

当前未实施这些检查。后续计划在明确白名单和当前规范下补齐配置、入口与现有用例；不重建已有业务架构，不全面清理历史缺陷。

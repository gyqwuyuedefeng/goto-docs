# 图形上传双阶段遮罩设计

## 目标与范围

图形绘制页选择文件后，从 `/file/upload` 开始显示页面遮罩；该接口成功后，继续等待 `/api/plotType/obtain_file_setting_handsontable` 返回，再关闭遮罩。任一步失败也要关闭，保留错误提示。两个请求继续按现有顺序调用，表格仍可编辑。不改变统计上传、其他上传器、后端接口或文件大小限制。

## 当前调用链

`PlotSidePanel` 的 `Uploader` 负责第一步。成功回调通过 `reload-table` 通知 `draw.vue`，后者调用 `Handsontable.reloadFile()`，最终请求第二个接口。目前 `reloadFile` 不返回内部 Promise，页面只知道第二步已经发起，无法知道何时结束。

## 方案

推荐复用 `draw.vue` 已有的页面级 `v-loading`：以未完成上传数计算遮罩状态，`Uploader` 校验通过并开始上传时加一；第一步失败时减一；第一步成功时由 `handleReloadTable` 等待第二步的 Promise，在成功或失败的 `finally` 中减一。两个上传偶然重叠时，先完成的任务不能解开另一个任务的遮罩。上传结果处理在发起第二请求前抛异常时也减一并提示错误。`Handsontable.reloadFile()` 与 `obtainFile()` 返回现有请求 Promise。上传器在保持默认错误提示的同时增加失败通知，避免业务页面接管通用错误文案。

备选方案一是由侧栏直接创建全屏 Loading 实例，但它需要跨组件传递或手动管理实例，销毁路径更多。备选方案二是监听全局请求，但会误覆盖其他页面请求。现有页面遮罩与事件链改动最小。

## 验收

- 第一请求未返回时遮罩显示；第一请求返回成功、第二请求未返回时仍显示。
- 第二请求完成后关闭；第一请求失败、业务返回非 200 或第二请求失败时关闭。
- 上传结果处理异常时关闭；两次上传重叠时等待最后一个任务结束。
- 超过 20,000,000 字节的文件在前端拒绝，遮罩不开始。
- 原有上传参数、错误提示和表格编辑行为不变。

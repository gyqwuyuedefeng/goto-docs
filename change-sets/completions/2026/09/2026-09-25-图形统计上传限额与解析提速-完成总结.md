# 图形／统计上传限额与解析提速完成总结

## 结果摘要

图形／统计单文件上传的前端默认限制和后端六个业务处理入口统一为 **20,000,000 字节**：恰好达到边界允许，超过一个字节拒绝。后端表格插列改为按行下标直接替换，保留上传后整张表立即可编辑的行为。本地三个代码仓库已合入各自 `master`，完成构建、测试和后端启动关闭验收；尚未推送或部署。代表性大表的插列步骤明显加快，但未重新测量带登录的完整上传请求，因此不能宣称原约九分钟的端到端耗时已降至特定数值。

## 原因与目标

用户在本地上传约 11 MB 的图形／统计文件时，浏览器等待后端响应约 8.7 分钟；当时直接使用的前端上传器默认限制为 30,000,000 字节，图形／统计后端入口没有对应业务限额。目标是前后端一致限制到 20,000,000 字节，并修复大表处理中的慢算法，继续支持整表编辑，以相同数据对关键步骤做旧版和新版实测。

## 设计决策

前端修改直接上传组件的默认值，保留各调用方显式传入的限制；后端在图形／统计六类上传处理器的初始化初期调用共用的字节数校验，避免超限文件进入保存和解析。`HandsontableUtils.addColumn` 的旧实现每行调用 `body.indexOf(row)`，会对已解析整表重复搜索；改为整数下标遍历和替换，消除这一步的平方级扫描，并确保重复内容的行各自处理。不改变上传接口、文件格式或整表编辑流程，也不把基准测试中的单一步骤耗时当成整个 HTTP 请求耗时。

## 实际变更

- `freedom-public/common-utils`：修复 `addColumn` 行索引查找，并添加重复行正确性和十万行 CSV 时间回归测试。
- `goto/system`：添加共用 20,000,000 字节校验器，接入上传类型 1、2、3、5、6、9，添加边界与六个入口的测试。
- `goto-web`：将直接上传组件的默认单文件限制改为 20,000,000 字节，添加前端边界及显式覆盖测试。
- 原有其他上传器的显式限制、图形／统计整表立即编辑、其他业务上传规则未修改；未访问机密 R 包源码。

## 验证结果

- `freedom-public` 使用 WSL Maven 安全包装器执行全量 `clean install`：18 个模块 `BUILD SUCCESS`，测试失败数为 0。旧版十万行 CSV 插列测试约 11.55 秒并超过 5 秒门槛；新版约 0.36–0.42 秒，通过两项新增测试。
- `goto` 使用同一平台安全包装器执行全量 `clean install`：四个模块 `BUILD SUCCESS`；`common` 103 项、`system` 168 项、`task` 160 项测试均无失败，`task` 13 项按配置跳过。`system` 新增两项测试通过，覆盖 20,000,000/20,000,001 字节和六类处理器。`goto-manager.jar` 内嵌 `common-utils` 的 SHA-256 与新安装的修复版 JAR 一致。
- `goto-web` 在合入后的根工作区执行定向 Jest：3/3 通过；受影响文件 ESLint 通过；生产构建成功，保留四条既有构建警告。
- 将业务路径中的一份 9,524,950 字节、172,800 行 XLSX 复制到临时位置，对同一份数据仅计时 `addColumn`：旧版 118,029 毫秒，新版 10,904 毫秒，约 10.8 倍。另在该文件已包含标记列的状态下，单独测得读取表头信息约 6,750 毫秒、生成可编辑表数据约 4,480 毫秒、表格 JSON 序列化约 979 毫秒；这些数值不包含数据库、完整响应及浏览器渲染。原业务文件未修改，临时基准测试文件与副本已清理。
- 使用 `-Denv=local -Dspring.profiles.active=home` 及 WSL 路径覆盖，在本次取得的动态端口 40562 启动新 `goto-manager.jar`；日志出现 `Started AppRun`，未带参数访问 `/file/upload` 返回预期的 HTTP 400。通过 Ctrl-C 关闭并确认 40562 已释放。首次在端口 41588 的尝试因临时 `file.path` 参数类型错误而未完成启动，纠正启动参数后通过验收；41588 也已释放。
- 按用户授权，为解除旧 JAR 文件锁停止了原有 Windows Java PID 40120、16108；未自动重启原来的 8809、8808 服务。

## 偏差、风险与遗留

没有在受控新服务上完成真实登录的整条 11 MB 上传重测，无法证明浏览器等待的约九分钟已缩短到何值。当前实测只能证明主要慢点之一，即插列步骤，在代表性大表上从约 118 秒降为约 11 秒；其他处理、网络响应和前端渲染仍可能占时。启动验收只验证服务和路由可用，没有执行带认证的文件上传。第一次启动因本次临时路径参数配置错误失败，已用正确参数重试通过。原 8808/8809 服务已按授权停止，用户若继续在原端口本地测试，需要自行用新产物重启相应服务。代码仅合入本地主分支，未推送、未部署。

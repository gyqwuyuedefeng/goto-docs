# 桑基图PPTX原始尺寸与字体修复完成总结

## 结果摘要

本地修复与验收完成，尚未合并、推送或部署。用户样例的 46 个标签在 PowerPoint 中保持 PDF 的 10/9 pt，实际使用 Liberation Sans，不再替换为 Segoe Print；流带和节点仍可编辑。最终 PPTX 38,076 字节，未回到完整字体造成的大体积。

改动项目为 goto 后端、gotoTools 及 goto-docs；未修改前端、gotoBase、gotoStat、gotoPlot、Dockerfile 或 Action。

## 原因与目标

用户提供的 ZIP 中 PDF 为 562.285172 × 347.657478 pt，PPTX 只有约 179.875 × 111.25 pt；34 个正文标签 10→3.2 pt、12 个图例标签 9→2.9 pt。Java 桑基图 SVG 下载 PDF 传 96 DPI，PPTX 传 300 DPI，正好造成约 0.32 倍的物理尺寸变化。

该 PDF 超出有限原生解析器的渐变支持范围，走 LibreOffice 旧路径。旧路径没有嵌入字体，Windows 实际使用 Segoe Print，进一步改变字形和字宽。目标是保持 PDF 的尺寸、字号和布局，而非只把字体放大后挤占原来的小画布。

## 设计决策

- 桑基图 PDF/PPTX 使用相同 96 DPI，其他格式保留 300；不改变网络图等其他图形调用。
- 在旧路径完成现有字体恢复/映射后，按最终显式字体和实际用字匹配部署 TTF，复用已有许可、子集化和嵌入能力；不修改幻灯片 XML 中的坐标和字号。
- 保留原生 PDF 解析的拒绝边界，不扩展成通用 PDF 重建器，也不把整图转成图片。
- 修正预处理误把色标图片加宽 50% 的既有问题，仅文本框保留防换行宽度调整。

- 首次构建缺少隔离 Maven 缓存中的公共依赖；从已提交 freedom-public 快照准备依赖，Rsession 复用已核对源码一致的制品，没有扫描/复制共享 Maven 缓存。中央仓库直连超时使用临时 settings 接入已有本机代理后解决。首次临时 Redis 密码不匹配已修正，不属于产品改动。
- 旧路径的字体携带仅支持显式 Latin 字体族的常规/粗体静态 TTF；缺失、歧义、主题继承、斜体、缺字或许可受限时保留原引用并报告，不保证这些场景完全保真。现有用户字体映射不变。
- 字体子集保留当前文字的编辑；新增未包含字形仍可能需要完整字体或打开端字体支持。
- 本次分别验证 Java 调用契约与真实转换产物，未重新安装 R 包，未运行新版整套浏览器下载链路，不把旧安装包当新版验证。

# GotoSettings 管理页面视觉精修设计

## 目标与边界

精修 `plotGroup` 与 `plotType` 两个系统管理页面，使工具栏、表格、表单分区、状态提示和弹窗形成统一、克制的管理工作台视觉。用户端 `views/goto/plot` 只作为层次、留白和卡片质感参考，不复用其样式文件，也不把管理端样式写入用户端目录或全局主题。

本次只调整模板中的展示容器、语义文案和样式，不修改 `<script>`、接口、权限、CRUD 事件、表格字段、表单绑定或弹窗业务流程。

## 方案比较与选择

1. **管理端共享样式文件 + 页面 scoped 补充（采用）**：在 `views/gotoSettings/styles` 下维护共享视觉令牌和通用管理页结构，两个页面分别导入；一致性最好，且作用域与用户端天然隔离。
2. 两个页面各自复制完整样式：隔离直接，但颜色、间距和响应式规则容易漂移，维护成本高。
3. 修改全局 Element UI / 主题样式：代码最少，但会影响其他系统页和用户页，违反本次隔离边界。

## 视觉设计

- 使用项目既有 Cold Slate 语义变量：浅灰蓝画布、白色面板、靛蓝主操作、低饱和边框和阴影。
- 页面顶部增加轻量标题区，清晰区分“图形分组管理”和“图形类型管理”，并说明各自职责。
- CRUD 工具栏和数据表分别落在独立面板中；工具按钮统一高度、间距和圆角，危险/警告动作继续保留原 Element UI 语义色，但降低杂乱感。
- 表格表头、行悬浮、图片预览、空状态和分页使用同一套层次。
- 全屏编辑弹窗使用浅色画布和卡片化分区；普通确认弹窗与排序弹窗统一标题、正文和底部操作区。
- 在 1200px 以下允许工具栏换行；在 768px 以下减少页面留白、按钮自然换行，表格保持横向可用，不隐藏字段。

## 功能保护与测试

- 单元契约测试锁定两个页面 `<script>` 内容哈希，确保业务逻辑零变更。
- 源码结构测试确认两个页面使用管理端根类并导入独立 SCSS，同时确认用户页不导入管理端样式。
- 运行既有目标页测试、完整单元测试、lint/build。
- 使用 Playwright MCP 在真实页面检查桌面和窄屏布局、溢出、控制台异常、工具栏操作、筛选、弹窗打开/关闭及视觉截图。

## 验收标准

1. 两个管理页面视觉层次、颜色、间距一致，桌面和窄屏均无明显遮挡或错位。
2. 管理端样式只位于 `views/gotoSettings` 并由两个管理页导入，用户页不引用。
3. 两个页面原有 `<script>` 完全不变，现有 CRUD、筛选、同步、清理、排序和弹窗入口仍可操作。
4. 自动测试、构建与 Playwright MCP 回归均提供通过证据，测试产生的应用进程在结束时关闭。

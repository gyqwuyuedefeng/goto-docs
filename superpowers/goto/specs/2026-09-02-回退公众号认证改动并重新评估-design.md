# 回退公众号认证改动并重新评估设计

## 背景

`freedom-public` 提交 `81c7c26` 将微信公众号 OpenId Provider 从应用启动后的
`SecurityRunner` 注册改为认证管理器构建阶段注册，并为保留账号密码登录显式增加了
`DaoAuthenticationProvider` 与 `PasswordEncoder` 依赖。

`goto-task` 依赖并扫描 `common-security`，但它不提供登录能力，也没有
`PasswordEncoder`。新配置因此被 task 错误装配，导致生产环境 ApplicationContext
启动失败。task 未来也不需要登录能力。

## 目标

1. 完整回退提交 `81c7c26`，首先恢复 task 在修改前的启动行为。
2. 回退后重新复现并分析 system 微信登录 Provider 的注册时机问题。
3. 后续修复必须限定在拥有登录入口的 system，不再让 task 自动装配登录 Provider。

## 非目标

- 不给 task 增加 `PasswordEncoder`、登录接口或登录 Provider。
- 不修改 task 业务代码或安全配置。
- 不处理 Redis、Hibernate、BeanPostProcessor 等非致命警告。
- 本阶段不直接实施第二版 system 微信登录修复。
- 不引入配置中心、功能开关、新模块或通用认证自动配置框架。

## 方案比较

### 方案一：完整回退后重新评估（采用）

完整回退 `81c7c26`，恢复 `SecurityRunner`，删除本次新增的
`WeChatOpenIdAuthenticationConfiguration` 及其测试。该方案能够把 task 恢复到今天修改前的
已知行为，并为 system 登录问题建立新的、独立的失败复现。

代价是 system 原有的微信登录 Provider 注册时机风险会暂时恢复，因此回退完成后必须明确停止，
先取得新的复现证据，再设计 system 专属修复。

### 方案二：只删除 `PasswordEncoder` 依赖（不采用）

task 可能恢复启动，但 system 的账号密码 Provider 可能再次缺失，无法保证两类登录共存，属于症状修补。

### 方案三：在 task 排除配置或增加编码器（不采用）

这会让非登录服务承担登录配置的知识或能力，继续保留错误依赖方向，并给未来其他服务留下相同风险。

## 第一阶段：回退与恢复验证

### 变更范围

只在 `freedom-public` 仓库回退提交 `81c7c26` 涉及的三个文件：

- 恢复 `common-security/src/main/java/com/freedom/runner/SecurityRunner.java`。
- 删除 `common-security/src/main/java/com/freedom/config/WeChatOpenIdAuthenticationConfiguration.java`。
- 删除 `common-security/src/test/java/com/freedom/runner/SecurityRunnerTest.java`。

`goto` 仓库不修改生产代码。已有未跟踪崩溃日志和用户修改保持不动。

### 验证

1. 按项目 Maven 安全包装脚本运行 `common-security` 受影响范围测试与编译。
2. 重新安装受影响的共享依赖，并编译、测试 `goto-task`。
3. 使用隔离的动态端口和本地 profile 启动 task，确认不再出现缺少
   `PasswordEncoder` 的错误并等待 Spring Boot 完成启动。
4. 通过前台终端关闭本次 task 进程，并确认动态端口释放。

## 第二阶段：system 微信登录重新评估

回退完成后重新建立 system 登录失败的最小复现，追踪以下链路：

1. `AuthenticationConfiguration` 何时创建并缓存 `AuthenticationManager`。
2. `SecurityRunner` 何时向 `ProviderManager` 添加 OpenId Provider。
3. 登录控制器实际取得的是哪个认证管理器实例。
4. 账号密码 Provider 在显式注册 OpenId Provider 后是否仍然存在。

评估阶段只产出根因和候选方案。第二版修复必须满足：

- 注册发生在 system 认证管理器构建完成之前。
- 配置仅由 system 显式拥有或加载。
- system 的 OpenId 与账号密码登录均有失败先行的回归测试。
- task 在没有 `PasswordEncoder` 时仍不加载登录 Provider。

第二版方案经用户确认后再进入新的实现步骤，不与本次回退混合试错。

## 验收标准

- `81c7c26` 的三个文件变更被完整回退，没有夹带其他代码修改。
- `common-security` 受影响测试与 `goto-task` 编译测试通过。
- task 能在隔离端口完成启动，并能受控关闭且释放端口。
- task 源码没有新增 `PasswordEncoder` 或登录 Provider。
- 明确记录 system 登录问题仍待重新复现和设计，不声称其已修复。

## 停止条件

第一阶段验收完成后停止修改代码。随后只进行 system 登录时机的只读追踪和失败复现设计；
没有新的设计确认，不实施第二版 system 修复。

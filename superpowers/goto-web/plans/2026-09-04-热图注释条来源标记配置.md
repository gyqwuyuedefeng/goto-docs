# 热图注释条来源标记配置实施计划

> **面向执行 Agent：** 必须使用 `superpowers:executing-plans` 在当前会话内逐项执行本计划；受会话约束，不得委派子 Agent。每个任务遵循红—绿—重构，完成一项即运行该项验证并提交。

**目标：** 让热图的行、列注释条来源像 `moduleType=7` 的 BY 列名标记一样可配置；历史配置缺失时自动使用 `row_anno/y_column2` 与 `col_anno/x_column2`；PlotGroup 同步到历史 PlotType 后配置继续生效。

**架构：** 在后端 `ClassifyParamList`（`moduleType=22`）增加集合级 `byFileMarkColumnList` 并纳入参数同步。管理端复用 `MarkColumnSelector` 编辑该字段。热图运行时通过统一的“显式配置 → 三文件语义默认 → 旧标记回退”解析器定位来源，文件生命周期、动态分类重建和 tab 显隐都使用解析结果，不再依赖固定文件索引。

**技术栈：** Java 8、Spring Boot、Jackson/Gson、JUnit 5、Vue 2、Element UI、Jest、Lodash。

function resolveHeatmapAnnotationSourceMarks(commonParams, settingName) {
  const setting = localFindFromTopParamSettingsList(settingName, commonParams)
  if (!setting) return []

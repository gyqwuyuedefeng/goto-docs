# 统计分析运行平台重构设计

> 日期：2026-08-19
>
> 范围：`goto`、`goto-web`、`gotoStat` 以及统计分析运行文件目录
>
> 设计状态：已确认，允许直接生成实施计划并执行
>
> 现状基线：`goto-docs/superpowers/docs/2026-06-24-statistics-analysis-current-state.md`

## 1. 背景与目标

现有统计分析模块以“当前用户 + 方法”保存一份可变配置，输入和结果使用固定文件名覆盖。该模型无法表达每次运行的参数、输入版本、结果、失败原因和重新运行关系，并且前后端方法分支已经与当前 `gotoStat` 导出函数发生漂移。

本次不在旧模型上继续修补，而是重建一个最小、完整的统计分析运行闭环：

1. 方法以当前可执行的 `gotoStat` 导出函数为第一事实来源，文档 1～8 补充中文名称、参数和结果说明。
2. 用户上传一张原始表，在页面标记 ID、变量、分组等列角色；后端为每次运行生成方法需要的输入文件。
3. 每次点击运行都创建独立、不可变的历史，保存参数、输入文件版本、结果、失败原因和版本信息。
4. 重新运行创建全新的运行和目录，不覆盖原历史。
5. 结果优先按文件展示：Excel 在线表格预览，PDF/图片内嵌预览，单文件和结果包下载。
6. 历史默认保留 3 天；管理员可修改天数或设置永久保留。策略默认只影响之后进入终态的运行。
7. 前端采用当前绘图 `draw` 页的工作台视觉和主题体系，但不复用绘图领域对象、专用 WebSocket 或 ECharts 演示组件。

## 2. 已确认决策

### 2.1 重建边界

- 不迁移旧统计参数、旧输入、旧结果和旧运行状态。
- 不保留旧统计 HTTP 接口的兼容层，不做双写。
- 新链路通过验收后删除旧统计 Controller、Service、Domain、Repository、任务处理器、前端 11 个硬编码组件和旧路由分发。
- 旧数据库表不由应用启动过程自动删除；如部署方需要物理清理，使用单独、显式且可审核的维护 SQL。
- 继续复用登录权限、文件存储基础能力、通用任务/Redis Stream、WebSocket、Quartz、`ScriptExecutionFacade` 和 draw 主题原子能力。

### 2.2 事实来源

- `gotoStat/NAMESPACE` 中实际导出的可执行函数决定方法是否可用。
- 文档存在但 R 函数不存在的方法不在页面显示，不展示禁用占位卡片。
- R 函数存在而文档内容为空时，根据函数签名、校验和结果行为定义方法。
- 后端目录中的 R 函数名、文件名和服务器路径不能由前端指定。

### 2.3 方案选择

采用“代码方法目录 + 通用运行引擎 + 小型方法适配器”：

- 代码方法目录保存稳定、可版本控制的方法元数据。
- 通用运行引擎负责草稿、快照、任务、状态、历史、结果和清理。
- 方法适配器只负责该方法的列角色校验、输入生成、R 参数映射和结果识别。
- 普通参数由统一定义渲染；只有真实复杂交互才允许专用前端组件。

不采用数据库低代码方法平台，因为当前没有运行时编辑 R 方法定义的需求；不为每个方法复制一套 Controller、表和任务链路，因为这会恢复旧实现的分支膨胀。

## 3. 总体架构

```text
方法目录
   ↓
统计方法页 → 统计工作台 → 自动保存草稿
                         ↓ 点击运行
                   创建不可变运行快照
                         ↓
                 CommonTask<StatisticsRunTask>
                         ↓
               类型明确的统计任务处理器
                         ↓
                    方法适配器
                         ↓
              ScriptExecutionFacade → gotoStat
                         ↓
               状态 / 结果清单 / 错误
                         ↓
          WebSocket 通知 → 历史 / 预览 / 下载

管理员 → 保留策略 → 终态时固化 expiresAt
                    ↓
                Quartz 精确清理
```

### 3.1 后端职责

- `StatisticsMethodCatalog`：返回当前可用方法、输入角色、参数和结果定义。
- `StatisticsDraftService`：维护每用户每方法唯一的可变草稿和乐观锁版本。
- `StatisticsRunService`：创建运行、固化快照、投递任务、取消和重新运行。
- `StatisticsMethodAdapter`：校验方法规则、生成输入并创建类型安全的 `RFunctionRequest`。
- `StatisticsRunTaskHandler`：只接受 `StatisticsRunTask`，从数据库加载可信运行，不消费前端传入的领域对象。
- `StatisticsResultManifestService`：在所属运行目录内收集安全结果清单并提供预览定位。
- `StatisticsRetentionService`：维护全局策略、重新计算预览/应用和过期清理。

### 3.2 前端职责

- 方法目录页按后端目录渲染。
- 工作台负责上传原始表、列角色、参数、运行操作和结果预览。
- 历史抽屉负责分页、切换历史结果、重新运行和下载。
- WebSocket 只用于触发状态刷新；运行详情以 HTTP 查询结果为最终事实。

## 4. 数据模型

### 4.1 `statistics_draft`

每个 `user_id + method_key` 最多一条。

| 字段 | 含义 |
|---|---|
| `id` | 主键 |
| `user_id` | 草稿所有者 |
| `method_key` | 方法稳定键 |
| `catalog_version` | 草稿对应的方法契约版本 |
| `source_file_json` | 当前原始文件引用、名称、大小、类型、摘要和列信息 |
| `column_roles_json` | ID、变量、分组等列角色 |
| `parameters_json` | 当前参数 |
| `version` | 乐观锁版本 |
| `create_time`、`update_time` | 审计时间 |

草稿允许覆盖。上传新源文件、删除源文件、修改列角色或参数都会递增版本。

### 4.2 `statistics_run`

| 分类 | 字段 |
|---|---|
| 标识 | `id`、`run_id`、`user_id`、`method_key` |
| 幂等 | `submission_id`，与用户组成唯一键 |
| 关系 | `parent_run_id`，重新运行时指向来源运行 |
| 契约 | `catalog_version`、`adapter_version`、`goto_stat_version` |
| 快照 | `parameters_json`、`column_roles_json`、`source_manifest_json`、`input_manifest_json`、`invocation_json` |
| 存储 | `storage_relative_path`，由服务端生成，供任务与清理在无登录上下文时安全定位 |
| 执行 | `common_task_id`、`status`、`failure_json`、创建/开始/结束/取消时间 |
| 结果 | `result_manifest_json` |
| 保留 | `retention_mode`、`retention_days`、`expires_at` |
| 并发 | JPA `version`，用于状态条件更新 |

`invocation_json` 是方法适配器在 system 服务创建的可信调用快照，包含固定 R 方法、类型化参数和受管 R 路径；前端不能提交或覆盖。不可变字段包括用户、方法、父运行、参数、列角色、源文件、输入和调用快照。运行过程中只更新任务编号、状态、时间、错误、结果和终态保留快照。

### 4.3 `statistics_retention_policy`

全局单行配置：

| 字段 | 含义 |
|---|---|
| `mode` | `DAYS` 或 `FOREVER` |
| `retention_days` | `DAYS` 模式下的正整数，默认 3 |
| `updated_by`、`update_time` | 管理员审计信息 |
| `version` | 防止管理页覆盖并发修改 |

当前个人设置表只面向单个用户，不能表达全局统计历史策略，因此新增此单行实体是当前需求所必需的最小模型。

## 5. 状态与并发规则

```text
PREPARING
   ├─→ QUEUED ─→ RUNNING ─→ SUCCEEDED
   │      │          ├────→ FAILED
   │      │          └────→ CANCEL_REQUESTED ─→ CANCELLED
   │      └───────────────────────────────→ CANCELLED
   ├─→ FAILED
   └─→ CANCELLED
```

- 接受运行请求后立即插入 `PREPARING`，因此源文件复制或输入生成失败也有历史。
- 完成源文件和方法输入快照后才能进入 `QUEUED` 并投递通用任务。
- 任务处理器以条件更新完成 `QUEUED → RUNNING`，重复消息发现非 `QUEUED` 后幂等退出。
- `PREPARING` 或 `QUEUED` 取消可直接进入 `CANCELLED`；迟到的任务消息读取终态后退出。
- `RUNNING` 取消先进入 `CANCEL_REQUESTED` 并调用现有取消能力。取消与自然完成竞争时，数据库最先成功写入的终态生效。
- 所有终态为 `SUCCEEDED`、`FAILED`、`CANCELLED`。进入终态时读取当前保留策略并一次性固化 `expires_at`。
- 定时恢复将长时间停留在 `PREPARING` 且没有可执行任务的记录标记为 `FAILED`，失败阶段为 `SNAPSHOT`，避免进程异常留下永久悬挂历史。

失败阶段：`VALIDATION`、`SNAPSHOT`、`DISPATCH`、`EXECUTION`、`RESULT_COLLECTION`、`CLEANUP`。

## 6. 文件快照与目录

目录根从后端配置读取，前端不能传服务器路径。可变草稿源文件与不可变运行目录分离：

```text
{userNamespace}/statistics/
├── drafts/{methodKey}/
│   └── source/当前原始表
└── runs/{runId}/
    ├── source/
    │   └── 原始上传文件
    ├── input/
    │   ├── data.xlsx
    │   ├── metadata.xlsx
    │   └── 方法专属输入
    ├── output/
    │   └── gotoStat 生成的结果
    └── logs/
        └── execution.log
```

运行记录保存从受管存储根开始的 `storage_relative_path`，不保存或返回客户端可控制的绝对路径。例如：

```text
{userNamespace}/statistics/runs/{runId}
```

运行目录内部结构为：

```text
{runId}/
├── source/
│   └── 原始上传文件
├── input/
│   ├── data.xlsx
│   ├── metadata.xlsx
│   └── 方法专属输入
├── output/
│   └── gotoStat 生成的结果
└── logs/
    └── execution.log
```

规则：

- 每次运行完整复制自己的原始文件；不通过硬链接共享可删除文件。
- 源文件和输入清单保存文件 ID、相对路径、原名、媒体类型、大小、SHA-256、工作表和行列信息。
- 适配器只能写 `input`，R 执行只允许把结果写入 `output`。
- 结果清单保存文件 ID、相对路径、展示名、媒体类型、大小、SHA-256、预览能力和 Excel 工作表。
- 失败运行产生的部分结果可以进入清单，但标记 `partial=true`。
- 下载结果包时流式生成 ZIP，不长期保存重复压缩文件。
- 所有访问先按数据库清单查找文件 ID，再由后端组合并规范化路径；规范化结果必须仍位于当前运行目录。

## 7. 方法目录与适配器

### 7.1 通用列角色

- `ID`：样本或个体标识。
- `VARIABLE`：参与计算的数值变量。
- `GROUP`：分组或响应变量。
- `VARIABLE_SET_A`、`VARIABLE_SET_B`：两个相关性变量集合。
- `IGNORE`：明确不参与本次分析。

方法目录为每个角色定义最少/最多列数、允许的数据类型和帮助文本。适配器再次根据实际数据检查唯一性、水平数量、样本量、数值可转换性和方法组合。

### 7.2 第一阶段方法

| 分类 | `methodKey` | R 映射 |
|---|---|---|
| 描述统计 | `descriptive-statistics` | `GT_Descriptive_Stat` |
| 描述统计 | `normality-diagnostics` | `GT_Normality_Diagnostics` |
| 假设检验 | `one-sample-test` | `GT_OneSampleTest` |
| 假设检验 | `paired-sample-test` | `GT_TwoSamplesTest`，限定配对方法 |
| 假设检验 | `two-sample-test` | `GT_TwoSamplesTest`，限定独立样本方法 |
| 假设检验 | `multi-sample-test` | `GT_MultiSampleTest` |
| 多元统计 | `pca` | `GT_Ropls(method=pca)` |
| 多元统计 | `pcoa` | `GT_PCoA` |
| 多元统计 | `pls` | `GT_Ropls(method=pls)` |
| 多元统计 | `opls` | `GT_Ropls(method=opls)` |
| 多元统计 | `pls-da` | `GT_Ropls(method=plsda)` |
| 多元统计 | `opls-da` | `GT_Ropls(method=oplsda)` |
| 相关分析 | `correlation` | `GT_Corrlation`，适配器隐藏当前拼写 |
| 多样性 | `alpha-diversity` | `GT_AlphaDiversity` |
| 多样性 | `beta-distance` | `GT_Distance` |
| 模型评估 | `roc` | `GT_ROC` |

NMDS、t-SNE、UMAP、聚类和富集分析在当前 `gotoStat` 中没有可执行导出函数，第一阶段不显示。

### 7.3 参数协议

普通参数只支持当前需要的有限类型：单选、多选、整数、小数、布尔、短文本和分组水平选择。定义可以包含 `required`、默认值、选项、`min`、`max`、`step` 和帮助文本。

条件显示只支持等于、包含和非空三种简单判断，例如选择截尾均值后显示截尾比例。复杂业务规则留在适配器；不建设通用表达式引擎。

前端提交统一结构：

```json
{
  "methodKey": "roc",
  "draftVersion": 6,
  "submissionId": "客户端生成的UUID",
  "commonNoticeUUID": "当前页面通知UUID"
}
```

参数值和列角色从已保存且版本匹配的草稿读取，运行接口不接受任意 R 函数或服务器路径。

### 7.4 校验层级

1. 前端根据目录进行即时必填、类型和范围提示。
2. 后端通用层验证参数结构、目录版本和列角色基数。
3. 方法适配器读取实际表格，验证样本、分组和参数组合。
4. `gotoStat` 保留最终计算校验。

错误尽量定位到 `parameters.<key>` 或 `roles.<role>`。

## 8. HTTP 接口

统一前缀继续使用 `/api/statistics`，但资源接口全部重建，不保留旧动作式接口。

### 8.1 方法与草稿

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/methods` | 返回可用分类和方法摘要 |
| GET | `/methods/{methodKey}` | 返回输入、参数和结果契约 |
| GET | `/drafts/{methodKey}` | 获取当前用户草稿 |
| PUT | `/drafts/{methodKey}` | 按 `version` 保存参数和列角色 |
| POST | `/drafts/{methodKey}/source` | 上传/替换单张原始表并返回列和预览 |
| DELETE | `/drafts/{methodKey}/source` | 删除草稿源文件并递增版本 |

草稿写入版本冲突返回 HTTP 409 和最新版本。前端采用约 600ms 防抖；点击运行前必须立即冲刷待保存请求，并使用最新版本提交。

### 8.2 运行与历史

| 方法 | 路径 | 作用 |
|---|---|---|
| POST | `/runs` | 基于指定草稿版本创建运行，返回 202 |
| GET | `/runs` | 当前用户按方法、状态和时间分页查询历史 |
| GET | `/runs/{runId}` | 查询运行详情和结果清单 |
| POST | `/runs/{runId}/cancel` | 幂等取消当前用户的运行 |
| POST | `/runs/{runId}/rerun` | 使用历史源文件、角色和参数创建新运行 |
| GET | `/runs/{runId}/files/{fileId}/preview` | 鉴权后的 Excel/PDF/图片预览 |
| GET | `/runs/{runId}/files/{fileId}/download` | 下载单个清单文件 |
| GET | `/runs/{runId}/download` | 流式下载结果包 |

`submissionId` 在当前用户范围内唯一。重复 POST 返回已有运行，避免网络重试产生重复历史。

重新运行不会修改草稿：复制历史原始文件、列角色和参数，使用当前目录/适配器重新生成方法输入并执行，写入新的版本信息和 `parent_run_id`。第一阶段不归档旧版 R 包或容器，因此保证输入参数可追溯，但不承诺跨软件版本数值完全一致。

### 8.3 Excel 预览

- 预览接口按清单文件 ID 和工作表读取。
- 返回工作表名称、列头、总行数和分页数据。
- 单页默认 100 行，限制最大页大小；前端不一次加载完整大表。
- 单元格只作为文本/数值返回，不执行公式、不渲染 HTML。

PDF 和图片通过鉴权接口读取 Blob 后内嵌；未知文件类型只提供下载。

### 8.4 保留策略管理

需要独立管理员权限：

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/admin/retention` | 获取当前策略 |
| PUT | `/admin/retention` | 修改仅对未来终态生效的策略 |
| POST | `/admin/retention/recalculate-preview` | 计算已有终态历史的影响数量 |
| POST | `/admin/retention/recalculate` | 带确认数量应用重新计算 |

应用重新计算时再次计算影响数量；若与管理员确认的数量不同，返回 409，要求重新预览。运行中记录不参与重新计算，待进入终态时使用当时策略。

## 9. 运行流程

### 9.1 新运行

1. 前端冲刷草稿自动保存并提交 `draftVersion`、`submissionId` 和通知 UUID。
2. 后端验证方法可用、草稿归属和版本，立即创建 `PREPARING` 历史。
3. 在独立运行目录复制原始表、计算 SHA-256，并由适配器生成方法输入及可信 `invocation_json`。
4. 任一步失败则保存失败阶段和原因，进入 `FAILED`。
5. 快照完成后进入 `QUEUED`，发布只包含 `runId` 的 `CommonTask<StatisticsRunTask>`。
6. 类型明确的处理器重新从数据库读取可信运行，条件更新为 `RUNNING`。
7. task 服务只从可信 `invocation_json` 创建 `RFunctionRequest`，通过 `ScriptExecutionFacade` 调用已安装的 `gotoStat`。
8. 收集 `output` 结果和执行日志，更新终态与保留快照。
9. WebSocket 携带 `commonNoticeUUID`、`runId` 和状态；前端收到后重新获取运行详情。

### 9.2 取消

- 只能取消本人运行，管理员查看权限不隐含代替用户取消权限。
- 排队取消后迟到消息幂等退出。
- 运行中取消调用现有任务取消机制，但最终以数据库已写入终态为准。
- 重复取消返回当前状态，不抛内部异常。

### 9.3 结果与失败

- 成功运行展示完整结果清单。
- 失败运行展示用户可理解的阶段和原因，并允许查看已生成的部分结果。
- 原始堆栈、服务器绝对路径、R 启动命令和其他用户信息不返回普通用户。
- 完整执行诊断写入受控服务器日志；普通用户只接收脱敏后的失败原因，执行日志不进入普通结果包。

## 10. 前端设计

### 10.1 导航与目录页

- 恢复 GOTO 顶部“统计”入口，指向 `/goto/statistics`。
- 目录页从 `/methods` 渲染分类和方法卡片，不再维护前端 `type/subType` 常量镜像。
- 卡片使用主题语义变量，支持浅色和深色；空分类不显示。

### 10.2 工作台

路由：`/goto/statistics/workbench/:methodKey`。

```text
StatisticsWorkbench（draw-theme-scope）
├── StatisticsActionBar
│   ├── 方法标题
│   ├── 运行 / 取消
│   ├── 历史
│   └── 下载
├── StatisticsResultPanel（左）
│   ├── 空态 / 排队 / 执行 / 失败状态
│   ├── 结果文件列表
│   └── Excel / PDF / 图片预览
├── ResizeHandle
└── StatisticsConfigurationPanel（右）
    ├── 原始表上传和预览
    ├── 列角色标记
    ├── 方法参数
    └── 草稿保存状态
```

- 桌面端为可调整宽度的左右分栏。
- 窄屏切换为结果/配置页签，不保留旧页面固定 `min-width: 1024px`。
- 科学文档或图片预览区域允许保持白色画布；页面壳层、工具栏、表单、抽屉和表格必须使用现有主题 token。
- 第一阶段不引入 ECharts，也不定义结构化图表协议。

### 10.3 历史抽屉

历史显示方法、状态、创建时间、耗时、版本、过期时间和父运行关系。操作包括：

- 查看该次运行的参数、输入摘要、结果和失败原因。
- 使用该次运行重新运行。
- 下载单文件或结果包。

切换历史只改变左侧查看对象，不覆盖当前草稿。

### 10.4 草稿体验

- 参数和列角色约 600ms 防抖保存。
- 显示“保存中、已保存、保存失败、版本冲突”。
- 上传新源文件后清除不再存在的列角色，由用户重新确认。
- 点击运行时先完成待保存请求；保存失败或版本冲突时不创建运行。

## 11. 权限与安全

- 所有草稿、运行、文件和历史查询均在服务端使用当前登录用户限定归属；不信任请求体的 `userId`。
- 管理员保留策略使用独立权限，不复用普通统计运行权限。
- `methodKey` 必须存在于代码目录，R 函数名和固定参数只能来自适配器。
- 上传沿用系统文件大小配置，并校验扩展名、媒体类型和 Excel 可解析性。
- 结果路径必须通过运行目录规范化校验；拒绝 `..`、绝对路径、符号链接越界和不在清单内的文件。
- 文件响应设置安全的内容类型与文件名，Excel 单元格预览不执行公式或 HTML。
- 清理只接受数据库中解析出的明确 `userId/runId` 目录，不允许通配符或宽泛根目录递归删除。

## 12. 保留与清理

- 默认策略为 `DAYS/3`，可以改为其他正整数或 `FOREVER`。
- 策略更新不回写已有运行。
- 运行进入任一终态时固化策略；永久保留的 `expires_at` 为 NULL。
- Quartz 只查询终态且已过期的运行，逐条处理。
- 每条先删除精确运行目录，再删除数据库记录；目录删除失败时保留记录并记录 `CLEANUP` 诊断，后续重试。
- 清理任务具备互斥/幂等保护，多个实例不能同时删除同一运行。
- 管理页重新计算只更新终态记录的保留快照和 `expires_at`，不立即执行删除。

## 13. 旧实现下线

新链路完成端到端验收后：

1. 删除旧统计动作式 API、领域对象、Repository、初始化注册、固定目录工具、开始/取消处理器。
2. 删除旧前端统计常量、`operate/:type/:subType` 分发、11 个旧组件、公共旧 mixin 和无调用 API。
3. 删除旧统计上传/删除类型分派以及不再使用的统计组/统计类型管理源码。
4. 清理后执行全仓搜索，确保旧 R 函数 `GT_BasicStat`、`GT_DifferentialStat` 和旧动作接口没有运行时引用。
5. 不在代码部署中自动删除旧表或旧用户目录；另行提供人工维护清单。

不采用新旧并行，因为用户已明确不需要旧数据迁移或兼容，双链路只会增加状态和权限风险。

## 14. 测试策略

### 14.1 后端

- 方法目录：16 个方法键、R 函数映射、角色和参数约束。
- 草稿：首次创建、自动保存、乐观锁冲突、文件替换和越权。
- 运行：PREPARING 历史、不可变快照、SHA-256、提交幂等、投递失败。
- 状态：重复消息、取消竞态、非法回退、终态保留策略固化。
- 适配器：每个方法的有效请求和关键无效组合，断言最终 `RFunctionRequest`，不执行任意客户端函数。
- 结果：路径越界、清单收集、失败部分结果、Excel 分页预览和下载鉴权。
- 保留：默认 3 天、永久、未来生效、重新计算数量冲突、目录删除失败重试。
- Controller：HTTP 状态、权限、所有权和响应脱敏。
- Redis Stream 回归：处理器泛型必须为 `MessageHandler<StatisticsRunTask>`，反序列化后不出现原始 `Map` 分支。

### 14.2 前端

- 方法目录按 API 渲染且不显示未实现方法。
- 工作台上传、列角色、参数 schema、自动保存和 409 冲突。
- 点击运行前冲刷保存，运行/取消状态和 WebSocket 触发刷新。
- 历史切换不覆盖草稿，重新运行创建新 ID。
- Excel、PDF、图片、未知文件和失败部分结果的展示。
- draw 主题作用域、浅色/深色 token 和窄屏布局。

### 14.3 端到端

在可用测试账号和本地依赖环境下，使用 Playwright 验证：

1. 进入统计目录并打开一个方法。
2. 上传测试 Excel、标记角色、设置参数并确认自动保存。
3. 运行后观察排队/执行/终态并预览 Excel 结果。
4. 打开历史、重新运行并确认新旧 `runId`、目录和结果互不覆盖。
5. 触发一个可预期失败，确认历史保留失败阶段和原因。
6. 切换浅色/深色主题并检查工作台与抽屉。
7. 管理员修改保留策略、预览已有历史影响数量并显式确认重新计算。

## 15. 验收标准

1. 当前 `gotoStat` 对应的 16 个方法可以从统一目录进入；无 R 实现的方法不显示。
2. 每次运行都有独立记录、目录、参数、原始文件摘要、方法输入、结果或失败原因。
3. 重新运行产生新的 `runId` 和完整新快照，原运行任何文件和记录不变。
4. 草稿按用户和方法自动保存，并能可靠处理快速修改和版本冲突。
5. Excel 可分页预览，PDF/图片可内嵌，结果可以单文件及整包下载。
6. 运行、取消、重复消息和 WebSocket 通知没有原始 handler 反序列化或空结果异常。
7. 默认保留 3 天；管理员可设置天数/永久，已有历史只有在预览数量并确认后才重新计算。
8. 任何用户不能查询、预览、下载、重跑或取消其他用户的运行。
9. 统计工作台在浅色、深色和窄屏下符合 draw 主题体系，不依赖固定浅色页面。
10. 旧统计运行时代码和前端分发已下线，无双写和兼容分支；旧物理数据只通过显式维护操作处理。
11. 受影响 Java 模块完成编译测试、应用启动与关闭验证；前端完成单元构建和适用的 Playwright 验证。

## 16. 非目标与后续边界

第一阶段不包含：

- NMDS、t-SNE、UMAP、聚类和富集的占位或虚假实现。
- 数据库可编辑的通用 R 方法平台。
- ECharts 或结构化统计图表协议。
- R 包二进制、容器镜像或历史执行环境归档。
- 旧统计数据迁移、旧接口兼容和新旧双写。
- 用户自定义 R 代码、函数名或输出路径。

以后增加真实 R 方法时，仅在存在当前产品需求和可执行函数后新增目录定义、适配器及覆盖测试。

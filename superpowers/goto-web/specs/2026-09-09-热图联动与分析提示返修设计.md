# 热图联动与分析提示返修设计

## 目标

在不改变热图模板数据和其他图组行为的前提下，修复热图参数显隐、映射模式切换以及画图分析失败提示。

## 已确认的配置和根因

- MySQL 中热图图组为 `app_plot_group.id=13`，抽查模板为 `app_plot_type.id=167`。
- 第一个“单元格设置”的样式和大小参数分别是 `cellTypeA` 和 `cellSizeA`；`gs_cell_type` 字典中“默认”的值是 `default`。
- 对角线标签文字参数是 `diagonalText`。
- 数据集的可选“标签”列标记字段是 `label`，对应参数分组是“单元格标记设置”。
- 现有 `refreshHeatmapDependentSettings` 没有上述三项派生状态，所以首次加载、参数变更和保存列标记后不能保持一致。
- 映射弹窗把列类型兼容性用于禁用连续映射，导致 `limitType=false` 时仍不能自由切换；类型兼容性本应只决定是否提示警告。
- 画图页的 WebSocket 通知直接展示 `data.msg`，当它是串行化的 R 响应 JSON 时，页面会显示整段 JSON 而不是内部 `msg`。

## 设计

### 热图显隐联动

继续使用 `heatmapModify.js` 中的集中刷新流程，不创建新规则引擎：

- `cellTypeA === "default"` 时隐藏 `cellSizeA`，其他样式恢复显示；仅作用于第一个“单元格设置”，不联动 `cellTypeB/cellSizeB`。
- 矩阵非对称时隐藏 `diagonalText`，对称时恢复显示。
- 数据集中存在已标记的 `label` 列时显示“单元格标记设置”，没有时隐藏。
- 隐藏只改 `visible`，不清空已有参数值。首次加载、参数变更、文件上传/删除和列标记保存都复用同一刷新逻辑。

### 映射模式

保持 `limitType` 现有行为不变：为 `true` 时两个映射按钮继续禁用，映射类型保持调用方给定的初始值，连续模式下仍只展示数值列。当 `limitType=false` 时：

- 离散和连续两个映射按钮始终可用；未选择列、文本列或数值列都不会因为类型兼容性而禁用按钮。
- `numberColumn=true` 的列选择离散映射时，保留现有强制类型转换警告。
- `numberColumn=false` 且实际非空内容不能全部严格解析为有限数字的普通文本列选择连续映射时，新增不适配警告，但允许保持连续映射。
- `numberColumn=false` 但所有非空实际值都能严格解析为有限数字的特殊列选择连续映射时不警告，解决数值内容被识别为离散的问题。
- 数值兼容判断只用于警告展示，优先使用弹窗已携带的 `chooseColumnAllList`，不再参与按钮禁用，也不发起额外网络请求。

### 分析失败消息

仅在画图页的分析通知入口做容错：

- 消息是普通字符串时原样显示。
- 消息是 JSON 字符串，解析后为对象且含非空 `msg` 时，只显示该 `msg`。
- 解析失败或结构不匹配时回退原文，不吞掉有用错误信息。
- 不改全局 Axios/Toast 行为，不影响管理页和其他任务通知。

## 测试与验收

- Jest 回归覆盖 `cellTypeA` 往返切换、对称性往返切换和 `label` 列标记新增/取消。
- 映射弹窗测试覆盖未选列、原生数值列、内容为数字的离散列、普通文本列和 `limitType=true`；断言 `limitType=false` 时均可切换，只有不适配组合显示警告。
- 画图通知测试覆盖字符串 JSON、普通文本和非法 JSON。
- 运行相关 Jest 套件和前端构建。
- 使用动态端口启动本次 goto-web 与 `home` profile 的 system，必要时启动 task/Rserve 复现真实分析失败；Playwright 验证四项前端行为。
- Playwright 临时使用微信验证码登录页，验收后按 SHA-256 恢复 `src/views/login.vue`，并关闭本次启动的全部服务。

## 范围边界

- 仅修改 `goto-web`。
- 不改 `app_plot_group` / `app_plot_type` 模板，不改字典数据。
- 不修改 goto 后端、R 包或全局通知协议。
- 不扩展到其他图组的参数联动或映射规则。

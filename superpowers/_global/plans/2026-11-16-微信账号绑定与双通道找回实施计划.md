# 微信账号绑定与双通道找回实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. 当前采用单执行者顺序实施；用户选择委派执行时，改用 superpowers:subagent-driven-development，各执行者继承相同变更集 ID 和机密边界。

**Goal:** 为已有微信用户一次绑定用户名、强密码与唯一验证邮箱，在同一账号上提供密码备用登录、扫码或邮箱找回，以及小程序明确确认。

**Architecture:** 在现有用户实体和认证机制上补齐凭证状态与账号安全版本。公共认证库处理规则、身份及事务；goto/system 编排短期验证、邮件、二维码和通知；Vue 网页收集表单，小程序只负责确认。WebSocket 只传状态，授权始终由后端验证。

**Tech Stack:** Java 17、Spring Security、JPA、MySQL、现有 Redis/Redisson、BCrypt、现有邮件服务、WebSocket、Vue 2/Element UI/Vuex/Jest、微信原生小程序、Node test、Playwright。

## 全局约束

- 规格：[微信账号绑定与双通道找回设计](../specs/2026-11-16-微信账号绑定与双通道找回设计.md)，用户已确认；本计划不重新打开已确认的业务选择。

## 统一接口与状态契约

### 数据类型

新增 `AccountFlowTypes.java`（goto/system 的 com.freedom.account 包），类型命名和字段固定如下，业务接口不回传内部记录：

```java
public final class AccountFlowTypes {
    private AccountFlowTypes() {}
    public enum Purpose { LOGIN, BIND_CREDENTIALS, RESET_PASSWORD, CHANGE_EMAIL }
    public enum State { PENDING, CONFIRMED, CANCELLED, EXPIRED, CONSUMED }
    public enum EmailChannel { BOUND_EMAIL, NEW_EMAIL }
    public record StartRequest(Purpose purpose, String username, String email) {}
    public record FlowView(String flowId, Purpose purpose, State state,
                           long expiresAt, boolean identityVerified,
                           boolean emailVerified, String result) {}
    public record MobileInspectRequest(String scene, String code) {}
    public record MobileView(String scene, Purpose purpose, String accountLabel,
                             String emailLabel, long expiresAt, String mobileProof) {}
    public record MobileDecision(String scene, String mobileProof, boolean confirmed) {}
    public record EmailRequest(EmailChannel channel) {}
    public record EmailCheck(EmailChannel channel, String code) {}
    public record BindRequest(String username, String encryptedPassword, String email) {}
    public record PasswordRequest(String encryptedPassword) {}
    public record IdentityPasswordRequest(String encryptedPassword) {}
    public record PromptRequest(boolean disabled) {}
    public record BrowserView(String csrfToken, long expiresAt) {}
}
```

最终请求不接收可信 userId、openid、安全版本、是否已验证等客户端状态。`FlowView.result` 仅为 `NONE`、`SUCCEEDED`、`REVERIFY_REQUIRED`；CONSUMED 不等于数据库提交成功。用户名与邮箱以创建时绑定的目标为准，最终提交不允许悄悄更换。

CS 包新增 `AccountSecurityTypes.java`，定义 `SecurityState(boolean wechatBound, boolean passwordEnabled, boolean emailVerified, boolean promptDisabled, String maskedEmail, String loginSessionId)`、`CredentialContext(long userId, long expectedVersion)`、`BindCommand(String username, String rawPassword, String verifiedEmail)`、`MutationResult(long userId, long securityVersion)`。`rawPassword` 仅存在请求处理内存，不进入 Redis、审计或 toString。记录类不能直接打日志。

### HTTP 与通知

| HTTP | 参数与返回 | 访问规则 |
| --- | --- | --- |
| GET /api/account-security | SecurityState | 当前已登录用户，脱敏邮箱 |
| PUT /api/account-security/prompt | PromptRequest → 204 | 当前用户，不改变安全版本 |
| GET /auth/account-flows/browser | BrowserView，并设置/复用私有 Cookie | 同源或精确允许来源；只返回绑定 Cookie 的 CSRF 令牌，不返回 Cookie 秘密 |
| POST /auth/account-flows | StartRequest → FlowView | LOGIN/RESET 可匿名；BIND/CHANGE 必须登录；服务端绑定浏览器私有证明 |
| GET /auth/account-flows/{flowId} | FlowView | 浏览器归属证明；不存在/他人流程不泄露详情 |
| POST /auth/account-flows/{flowId}/cancel | 无体 → 204 | 浏览器归属，终态幂等 |
| POST /auth/account-flows/{flowId}/email/send | EmailRequest → 202 | 目的、渠道与归属检查；RESET 统一响应 |
| POST /auth/account-flows/{flowId}/email/verify | EmailCheck → FlowView | 验证码失败次数及原子校验 |
| POST /auth/account-flows/{flowId}/identity/password | IdentityPasswordRequest → FlowView | 仅已登录、历史缺验证邮箱的首次完善；不替代初次微信绑定身份 |
| POST /auth/account-flows/{flowId}/bind | BindRequest → MutationResult | 身份证明、新邮箱证明、一次性消费和事务 |
| POST /auth/account-flows/{flowId}/reset-password | PasswordRequest → MutationResult | 微信或原邮箱身份证明，RESET 专用 |
| POST /auth/account-flows/{flowId}/change-email | 无体 → MutationResult | 原身份加新邮箱证明，CHANGE 专用 |
| POST /auth/account-flows/{flowId}/login/exchange | 无体 → 原 authInfo 结构 | LOGIN 专用，浏览器兑换自己的 token |
| POST /auth/account-flows/{flowId}/socket-ticket | 无体 → ticket, expiresAt | 归属证明，30 秒一次性 ticket |
| POST /auth/account-flows/wechat/inspect | MobileInspectRequest → MobileView | 后端以 code 核验微信，再返回匹配身份可查看的说明 |
| POST /auth/account-flows/wechat/decision | MobileDecision → 204 | inspect 返回的一次性 mobileProof，确认或取消 |
| WSS /webSocket/account-flow | 首条消息提交 ticket；后续 {flowId,state} | 精确 Origin，ticket 原子消费前不订阅、不发状态 |

同站反向代理为生产首选。网页先调用 browser 接口，建立随机 32 字节 Cookie，服务端保存其 HMAC/摘要；Cookie 为 HttpOnly、Secure、SameSite=Lax、Path=/auth/account-flows。流程中的 22 字符公开随机标识与该私有凭证独立。browser 接口复用有效 Cookie 而非每次刷新重置，CSRF 令牌返回响应正文后仅放内存；浏览器变更请求携带该令牌。允许 Origin 列表精确到 scheme/host/port；同源 GET 缺少 Origin 时结合配置的实际站点与 Fetch Metadata/Referer 验证来源，不能因此允许任意跨站读取。小程序请求不依赖浏览器 Cookie，而使用微信 code/mobileProof，不为兼容无 Origin 的小程序而放开浏览器接口。prompt 接口使用原登录 Authorization 加精确来源校验，不借用不同 Path 下的流程 Cookie。

本地 home 验收的 HTTP 例外仅用于 loopback 同站代理，Cookie 可不置 Secure；生产默认必须 Secure，非 loopback 明文请求拒绝。不得为了本地便捷把生产 Cookie 策略整体改松。

错误代码固定：`INVALID_INPUT`、`CONFLICT`、`VERIFICATION_FAILED`、`FLOW_UNAVAILABLE`、`RATE_LIMITED`、`REVERIFY_REQUIRED`。流程不属于当前浏览器时用一致的 FLOW_UNAVAILABLE；HTTP 401 只表示真实登录失效，不用于普通验证码失败，避免触发现有全局退出拦截器。
